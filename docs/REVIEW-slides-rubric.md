# 章节幻灯片效果评审清单（rubric）与评分记录

> 用途：「商业可用」优化的验收口径（2026-09-29 规划，对标 Gamma / Kimi PPT 这类商业产品的观感）。
> 用法：用 `web/tools/review-decks.mjs <标签>` 生成逐页截图后，**逐页**对照本清单打分；
> 每维 1–5 分（1=不可接受，3=能用但有明显瑕疵，5=商业产品水准）。
> 评审素材在 `web/tools/shots/review/<标签>/<章节名>/`（p01.png… + deck.json）。

## 评分维度

| # | 维度 | 5 分的标准 | 1 分的典型 |
|---|---|---|---|
| D1 | 结构完整 | 封面（含课程眉题）→ 目录/脉络 → 分节 → 内容页 → 小结/结尾，节奏自然 | 缺封面/小结，页序混乱 |
| D2 | 信息密度 | 每页 ≤5 条要点、每条 ≤20 字、关键词/短语式（电报体）；一页只讲一件事 | 整句搬运正文、一页 6+ 条、每条两三行 |
| D3 | 无溢出裁切 | 任何一页的文字都在页框内，底部不被切 | 任一要点被裁掉一半 |
| D4 | 无重复 | 页标题、要点跨页不重复；同知识点只讲一次 | 同标题连出两页、要点换说法重复 |
| D5 | 版式多样与层次 | 版式随内容变化（要点/对比/步骤/代码/大数字），有视觉层次（眉题/强调色/留白），不是清一色 h2+ul | 全 deck 一种版式，标题与正文无层次 |
| D6 | 讲稿可用性 | notes 是口语化讲稿：有过渡语、能照读、信息量超过页面文字 | notes 只有「讲解本页」式套话或缺失 |
| D7 | 整体观感 | 放进商业产品里不违和：对齐、间距、字号阶梯、配色统一 | 一眼「默认模板直出」 |

## 评审规程

1. 每轮评测一个标签（= 模型 + prompt 版本），默认评测集 5 章（见 review-decks.mjs 的 EVAL_CHAPTERS）。
2. 逐章逐页看图打分：D1/D4/D5/D7 按**整 deck** 打分，D2/D3 按**最差一页**打分，D6 抽 3 页 notes。
3. 双模型对比时**打乱来源盲评**（不看标签先打分，再揭晓）。
4. 分数与典型瑕疵记在下表，作为下轮迭代的对照。

**小结（v1 → v2-r2）**：密度硬约束（≤20字/条、≤5条/页）全部达标；零溢出（自适应缩档兜底）；
零重复标题；notes 从 1–3 句提示升级为 100–300 字讲稿。剩余短板集中在**结构节奏**
（短章分节页过多、end 页偶缺）与**版式多样性**（v2 只有 bullets/two-col/code）—— 即 v3 的目标。

### 模型结论（2026-09-29 定版）

- **默认 `deepseek-flash`**：结构完整性与覆盖（页数/end 页）更好、延迟约 1/3、成本更低；
  v4-pro 仅在个别措辞上略细（如 steps 不带冗余序数词），不足以覆盖其速度与成本劣势。
- 已留**分级配置口**：`SLIDES_OUTLINE_MODEL` / `SLIDES_EXPAND_MODEL`（如大纲 pro + 扩写 flash），
  将来模型价格/质量变化时无需改代码即可切换。
- 遗留小项：steps 条目偶带"第一步"冗余序数词（可在后续 prompt 微调中消除，不影响可用性）；
  短章 end 页偶缺（大纲侧概率事件，重新生成可解）。
