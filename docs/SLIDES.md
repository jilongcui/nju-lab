# 章节在线幻灯片（Slides）功能指南

> 平台的章节幻灯片功能：教师按章节用 LLM 一键生成在线演示，可换主题/换版式、重生成单页、全屏放映；
> 学生在章节页随时切换「文档 ⇄ 幻灯片」。

> ⚠️ **2026-10-10 起是「语义模型（v2）」**：生成侧产出的是**教学意图 + 内容块**（不是 16 种版式枚举），
> 版式由渲染层映射 —— 因此有了关系图 / 管线 / 时间线 / 分层结构这类旧模型给不出的页面。
> 教师端编辑面同时收窄为「换主题 / 换版式 / 重生成当前页」，Markdown 视图降为只读预览。
> 历史 deck（v1）**不需要重生成**，前端会自动适配渲染。
> 设计、决策与实测记录见 `docs/DESIGN-2026-10-10-slides-semantic-html.md`（§9–§12）。
> 本文是**功能与原理的活文档**（随实现更新）。设计决策与踩坑见
> `docs/DESIGN-2026-09-29-chapter-slides.md`（含 §16 效果优化实录），
> 效果评分记录见 `docs/REVIEW-slides-rubric.md`，运行态见 `HANDOFF.md` §9。

## 0. 两代模型（v1 / v2）

| | v1（旧版式模型） | **v2（语义模型，默认）** |
|---|---|---|
| 生成产物 | `layout`（16 种枚举）+ `bullets/stats/compare…` | `intent`（17 种教学意图）+ `blocks`（13 种内容块） |
| 版式决定者 | 模型选版式 | **渲染层按 intent 映射** |
| 图示能力 | 5 种图片版式（单图/全幅/左图右文/右图左文/网格） | 关系图 / 管线 / 时间线 / 分层 / 数据表 / **数据图（柱·折线·环形）** / **LaTeX 公式** / **页级背景图** / **正文插图**（`image` 块，由渲染层画，模型只给数据与 fileId） |
| 交付 | 仅在线放映 | 在线放映 + **导出 PDF**（浏览器打印，每页一画布；pptx 明确不做） |
| 编辑 | MD / JSON 双视图改写 | 「换主题 / 换版式 / 重生成当前页」；MD 只读预览、JSON 可写 |
| 兼容 | — | 历史 v1 deck 由前端适配器渲染，**无需重生成** |

切换开关：生成侧 `SLIDES_SEMANTIC=0`（回退 v1）、渲染侧 `VITE_SLIDES_RENDERER=reveal`（回退旧渲染器）。

## 1. 它能做什么

- **一键生成**：以章节正文（Markdown）为素材，LLM 自动组织分节、挑选版式，产出 6–20 页演示稿；
- **单页重生成**：个别页不满意可只重写那一页（同步一次 LLM 调用，其余页与手工编辑不动）；
- **双视图编辑**：JSON 视图精修、Markdown 视图改写，改完即时预览、保存即生效（不花 token）；
- **图片能力**：教师个人图片库（上传/复用，跨课程）+ 图片选择器插入/换图；
  章节正文可从图片库选图/上传插入（支持多选）——**正文里的图就是幻灯片配图的唯一来源**。
  两代口径不同：**v1** 用 5 种图片版式（`image` / `image-full` / `image-left` / `image-right` / `image-grid`）；
  **v2** 用 `image` 块（`role: hero|inline|full|grid`，可单图或多图并列），图注与「放回上下文本节」由生成侧负责。
  ⚠️ v2 的插图链路 2026-10-10 上线时**实际不工作**（清单没进 prompt + fileId 形态不一致，8 张图 0 使用），
  2026-10-12 修好并实测（见设计文档 §14）；`fileId` 两代形态不同：v1 要 `file:<uuid>`、**v2 要裸 uuid**。
- **模板系统**：6 套内置模板（平台蓝/南大紫/**南大风**/学术白/深色高对比/极简黑白）+ 课程级自定义（可视化调参）；
- **在线放映**：全屏、键盘/鼠标翻页、页码进度、讲者备注（notes 是**可照读的讲稿** +
  `[ …… ]` 内联的备课提示，见 §5.3）、跨章节不退出切换；
- **光标同步 + 批注（白板，2026-10-17）**：讲者窗口的幻灯片上盖一层白板（**默认接管鼠标**）——
  鼠标到哪，投影上就有一个光点跟到哪；按住拖拽可以画线，工具条里可选 **4 种颜色 × 3 档粗细**
  （细/中/粗），也能切到「只指示」模式或一键清除。**翻页自动清空**（每页批注独立）。
  坐标一律用 **deck 画布坐标（1920×1080）**，两端各自按 letterbox 规则映射 ——
  所以讲者笔记本（16:10）与投影（16:9）上线条位置精确对齐，不会错位。
- **讲者视图（双窗口，2026-10-17）**：教师点「讲者视图」→ 本窗口**幻灯片照旧铺满**，
  右上角只多一行小控件（`⏱ 计时` / `观众窗口` 开关 / `退出`），右下角贴底一行「下一页：…」预告
  （讲稿浮层打开时自动上移让开它），**讲稿仍按 `S` 呼出**（底部浮层）；
  同时另开一个**观众窗口**（`?audience=1`）投到投影屏 —— 那里**只有幻灯片**：
  没有平台外壳、没有工具栏、没有讲稿。两窗口用 `BroadcastChannel` 实时同步翻页。
  ⚠️ 本站是 HTTP（无 443），`getScreenDetails()` / `documentPictureInPicture` 这类"自动把窗口投到第二屏"
  的 API 全部不可用 → 观众窗口需**手动拖到投影屏 + F11**（拖一次浏览器会记住位置）。
  ⚠️ 这条解决的是"投影看不到讲稿"；**deck 文档里仍然带着 notes 文本**，学生端页面按 F12 仍能看到
  （见 §5.2）。
- **跟随章节**：正文改了会提示「章节内容已变更」，教师决定重新生成或保留（绝不自动重新生成）。

## 2. 生成流程（核心原理）

素材不是专门为幻灯片写的内容，而是**章节本身的 Markdown 正文**（`Chapter.content`）。
生成分**两阶段**（一次吐 20 页完整 JSON 极易被 token 上限截断，拆开单次请求小、失败可局部降级）：

```
① 素材：章节正文（>30 万字截断，SLIDES_SOURCE_MAX_CHARS；2026-09-30 起随模型 500K token 上下文放开）
        │  教师手动点「生成」（绝不自动生成；sourceHash 命中缓存直接复用）
        ▼
② 阶段一：LLM 出大纲
   · 组织：通读正文 → 梳理 2–4 个分节 → 规划页序
     （封面 → agenda 目录 → 分节页 → 内容页 → 小结）
   · 选型：给每页定 layout（按内容类型，见 §3 选型规则）
   · 锚点：给每页写 keyPoint（“本页要让学员记住什么”，只给扩写看）
        ▼
③ 阶段二：LLM 分批扩写（4 页/批）
   大纲 + 原文回传，逐页补全：
   · bullets → 电报体成稿（≤20 字/条、3–5 条/页，禁止照抄整句）
   · stat/compare → 结构化字段（真实数字、两栏清单）
   · notes → 讲稿：**可照读的口播**（4–7 句、有过渡语、信息量比页面大），面向讲者的备课提示
     用半角方括号 `[ …… ]` 内联（见 §5.3）
   · cover 不写 bullets；section 给 2–3 条「本节导览」要点（纯关键词 ≤12 字、点名本节
     主题词，禁冒号补充结构，deck-teaser 弱化渲染；承接与过渡仍进 notes）
   约束：layout/title/keyPoint 不许改、页序不许变
        ▼
④ 程序化质检（不靠模型自觉）
   · 逐页形状校验（不合法只丢该页、大纲骨架兜底）
   · 分节导览条数硬闸 ≤SLIDES_SECTION_TEASER_MAX(3)（扩写管线内，整份/单页同口径）
   · postProcessSlides：标题≤30/要点≤60 截断、页内去重、
     标题高相似页合并（bigram Jaccard≥0.7）、
     分节页眉题强制顺序编号「第 N 节」（结构信息不靠模型编）
        ▼
⑤ 落库：SlideDeck.slides（JSON 唯一真源）+ markdown 投影 + 章节哈希
        ▼
⑥ 渲染：SlideJson → 自包含 reveal.js 文档（iframe srcdoc 隔离）
   · 按 layout 渲染版式；内容超重 → deck-fit-2/3 自动缩档（防底部裁切）
   · 模板只管样式：调参 → designToCss 编译 CSS —— 换模板不用重新生成
   · 就绪看门狗：iframe 5s 未回 ready 自动重挂载（换 key）×2，仍不行转明确错误
     —— 杜绝「转圈永不停」类竞态（2026-09-30 学生端二次进入偶发）
```

**健壮性**（都是实测踩过的坑）：deepseek-flash/v4-pro 是推理模型，`max_tokens` 与推理共用
（已带 `reasoning_effort=low`）；JSON 截断有抢救（回退最后完整对象补齐括号）；
大纲/扩写失败各自动重试一次；缺页用大纲骨架补齐，不整份失败。
模型会把 prompt 里的完整 schema 抄成空壳占位（`"compare": {"left": [], "right": []}` 挂在无关页、
`"image": null` 等，2026-09-30 实测一批 6 页被误杀）：校验层对**非 compare 页的空 compare 宽容丢弃**；
扩写页其他结构化字段缺失时**先降级为要点页**（保住模型写好的 bullets/notes），救不回才退大纲骨架。

## 3. 版式（16 种 layout + kicker 眉题）

| layout | 用途 | 内容形态 |
|---|---|---|
| `cover` | 封面（仅首页） | kicker 眉题 + 标题 + 副标题 |
| `agenda` | 目录/本章脉络（通常第 2 页） | 编号条目（bullets 承载） |
| `section` | 分节标题页 | kicker「第 N 节」（质检统一编号）+ 标题 + 2–3 条「本节导览」关键词（deck-teaser 弱化样式，与正文要点区分） |
| `bullets` | 要点页（最常用） | 3–5 条电报体要点，卡片化 |
| `steps` | 有序步骤/流程 | 序号圆点 + 连接线（bullets 承载） |
| `stat` | 大数字（1–4 个） | `{value, label, detail?}`，value 必须正文真实数字 |
| `compare` | 左右对比 | `{leftTitle, rightTitle, left[], right[]}` 双栏清单卡片 |
| `two-col` | 两栏自由文本 | left/right 两段 Markdown |
| `code` | 代码页 | `{lang, content}` ≤20 行 |
| `quote` | 引文/关键结论 | `{text, cite?}` |
| `image` | 单图页（暂限平台内文件） | `file:<fileId>` 引用 + 可选图注 |
| `image-full` | 全幅大图页 | 一张图撑满整页（contain 不裁切） |
| `image-left` | 左图右文页 | 图 + bullets 要点（图不可空，要点可空） |
| `image-right` | 右图左文页 | 同上，图在右侧 |
| `image-grid` | 多图网格页（1–4 张） | `images: [{url, caption?}]`，2 张两列 / 3 张三列 / 4 张 2×2 |
| `end` | 小结/结尾（仅末页） | 标题 + 要点 |

**生成侧的选型规则**（写在大纲 prompt 里，模型按此挑选）：一般要点 bullets；有先后顺序 steps；
正文有 1–4 个有说服力的数字 stat；成对对比 compare（优先于 two-col）；示例 code；点睛结论 quote。
**图片版式是条件放行**：正文含 `file:` 插图时（清单随 prompt 下发，fileId 与图注），模型可为讲图的页
选 image 系版式（一份 deck ≤3 页，url 只能照抄清单，服务端另有防幻觉闸，清单外引用直接丢该页走
大纲骨架兜底）；正文没有图时维持「不生成 image 页」。教师也可随时用「插入图片页 / 换图」手动插图。

## 4. JSON 与 Markdown 的关系（真源与投影）

可以直接改 Markdown，不会丢东西。**JSON 是唯一真源，Markdown 是 JSON 的可读投影**：

```
JSON（SlideDeck.slides，真源）
  │  toMarkdown()   确定性投影（每页带 <!-- .slide: layout=xxx --> 指令）
  ▼
Markdown（教师编辑视图）
  │  保存
  ▼
parseMarkdown()  严格解析（语法错误带行号报错，不静默丢）
  + mergeMarkdown()  按页位次合并：MD 表达不了的字段从旧 deck 捡回
  ▼
normalizeSlides() 统一校验 → 落库，即时生效（零 token）
```

**MD 视图能写**（刻意保持小的子集）：`# 标题`、`## 副标题`、`- 要点`、编号列表（agenda/steps）、
`- **数字** 标签：说明`（stat）、`**列标题**` + `<!-- .col -->`（compare/two-col）、围栏代码块、
`> 引用`、`![caption](file:...)`（image/image-full/image-left/image-right 单图行；
image-grid 把多张图写成多行、≤4 张）、`<!-- .notes: 讲者备注 -->`、`<!-- .slide: layout=xxx kicker="..." -->`、`---` 分页。

**MD 视图改不了**：页级高级设置（`attrs.background/transition/className`）——只在 JSON 视图改；
MD 保存时按位次合并保留，不会被悄悄覆盖。

三条硬保证：
1. JSON → MD **确定性**，切视图本身不改变任何内容（全版式往返实测逐字段相等）；
2. 解析失败**不静默**：返回 400 并带「第几行（第几页）：什么原因」；
3. 保存即生效、**不花 token**（渲染是数据驱动的；调 LLM 只在手动「重新生成」时发生）。

## 5. 模板系统

- **内置 6 套**：平台蓝（默认）/ 南大紫 / **南大风** / 学术白 / 深色高对比 / 极简黑白；
  基于 reveal 轻量主题派生（刻意避开内嵌 564KB 字体的 black 系）。
- **南大风**（2026-10 新增）在语义渲染器上除了配色 token，还带一层**主题装饰层**
  （`web/src/slides/semantic/decor/nju.ts`）：整页不是纯白的浅紫底 → 米色渐变、**眉首**紫金细带、
  **眉尾**一条素净的细线（2026-10 反馈：渐变带 + 金线投影出来发脏，已去掉）、页脚徽记、
  内容页右上角的同心弧，以及**封面／分节页右下角的钟楼辅助背景**。
  装饰只在该主题编译出的 CSS 里存在（换主题即消失，**DOM 一个字节都不变**），颜色仍走 token。
  钟楼的素材位是 `assets/nju-hero-photo.ts`：填了照片就用照片，留空则回落到自绘矢量剪影
  （`assets/nju-tower.svg`，无外部依赖与版权问题）。换图一条命令 ——
  `node web/tools/embed-tower-photo.mjs <照片路径> [--crop=l,t,w,h] [--fade=tint,hold]`：
  裁切拼图（`--crop=` 原图比例，或 `--crop-ratio=3:4` 居中裁）→ 压淡成水印 →
  沿椭圆把边缘**真正透明**掉 → 编码成 WebP data URI 内联；`--clear` 还原剪影。
  换图不用改主题、版式，也不用重新生成 deck。
  三条踩过的坑（都是**静默失败**，值得记住）：
  ① 该 SVG 的 XML 注释里**不能出现连续两个减号**，否则整张图解析失败、配好了却看不见；
  ② 别用"刷一层底色"来淡出照片 —— 底色是固定值而页面底是渐变，边缘会留一条色差线；
     必须用 alpha 渐隐，且渐隐形状要跟照片同比例的**椭圆**（矩形四角比边中点远 √2 倍，用圆做四角会留边）；
  ③ 遮罩层若与照片层都写 `background-size: Wpx auto`，渐变层的 auto 等于整个定位区高度 ——
     两层高度对不齐也会露边。压淡与渐隐因此烘焙进素材，CSS 只留一层背景。
- **可视化调参**（教师端「模板调参」抽屉，不开放自由 CSS）：主色/背景/文字/强调色、字体栈、
  圆角、疏密、**字号阶梯 fontScale**（小字 32px / 标准 38px / 大字 44px）、
  **要点卡片 cardStyle**（无 / 浅色底 / 描边）、页脚文案与 logo。
- **安全边界**：调参值全部窄字符集 + 枚举校验后才编译进 CSS（`designToCss`），
  杜绝注入；内置模板不可直接改，「保存模板」会先另存为课程模板。
- **换模板零成本**：模板只提供样式，不改变 SlideJson 语义 —— 同一份 deck 换模板不需要重新生成。

### 5.2 讲稿（notes）的可见性边界

| 场景 | 讲稿可见？ | 说明 |
|---|---|---|
| 放映（单窗口，按 `S`） | 同屏可见 | 单屏投影时观众也能看到 —— 所以是**手动开启**而非默认打开 |
| **讲者视图**（2026-10-17） | 只有讲者窗口可见 | 观众窗口不渲染面板，且 `?audience=1` 时连平台外壳都去掉 |
| 导出 PDF「附讲稿」 | 附加备注页 | 给讲者当讲义用 |
| **学生端页面** | ❌ 拿不到，**连 `S` 快捷键都没有** | 两层堵：① 服务端 `getDeck` 按观看者裁剪（`slides[].notes` 与 `markdown` 里的 `<!-- .notes: … -->` 都不下发）；② 学生端渲染时传 `allowNotes=false`，讲稿浮层的**容器都不渲染**（数据剥了但快捷键还在的话，学生按 `S` 会弹出一个「（本页没有讲稿）」的空浮层 —— 没有泄露，但"学生端有讲稿功能"本身就不该成立） |

> 学生端那行曾经是缺口（deck 文档里 `notes` 只是 `display:none`，按 F12 就能读到）；
> 现在**从数据层剥离 + 关掉入口**，而不是靠 CSS 隐藏。
> 判据见 `web/tools/verify-notes-privacy.mjs`（6/6）：学生 16 页有讲稿 0 页、markdown 无 `.notes`、
> 页数/标题没被剥坏、教师 16 页全有，以及学生端按 `S` 连浮层容器都查不到。

### 5.3 讲稿的两种成分：口播 + `[ …… ]` 备课提示（2026-10-17，prompt **v12**）

**问题**：v11 的讲稿把两种东西混在一段里 —— 能照着念的**口播**，和「先给学员一个隐喻」
「提醒学员留意」「思考题第一题就是从这儿出的」这类**面向讲者的备课提示**。教师反馈"那更像是老师的
思考，而不是能念的稿子"。实测 13 份 deck、227 页讲稿里 **44 页（≈19%）** 出现第三人称「学员/学生」，
另有 17 页出现「稍停一下 / 点一句 / 念法」这类导演式措辞。

**v12 的口径**（`SEMANTIC_EXPAND_SYSTEM` 铁律 4/6；v1 prompt 同步）：

- 讲稿**主体是能照着念的第一人称口播**：4–7 句、有过渡语、信息量大于页面；
- **念不出来的话一律用半角方括号 `[ …… ]` 内联标注**：动作与节奏、易错点提醒、
  与思考题/实验的呼应 —— 都是备课提示；
- 判据很硬：**把 `[ …… ]` 整段删掉后，剩下的口播仍要通顺可读**；
  口播正文里不许出现第三人称「学员/学生」，那类话只能进 `[ ]`；每页 `[ ]` 至多 2 处、每处 ≤30 字。

**渲染**：`[ …… ]` 由 `web/src/slides/notesCue.ts` 包成 `.notes-cue`（**斜体 + 压淡**，不写颜色 ——
深浅两套主题都要成立），讲稿浮层（按 `S`）与导出 PDF 的备注页共用同一份渲染 ——
讲者一眼分得清**哪句出声、哪句只是提示**。两条渲染路径（v2 语义 / v1 reveal）同口径；
`notes` 仍只做文本，`[<b>x</b>]` 这种写着玩的东西进不了标签（断言覆盖）。

**配套**：生成侧校验「讲稿去掉 `[ ]` 后的正文里出现『学员/学生』」→ 该页进 warnings（不丢内容，
提示教师改）；断言见 `assert-semantic.mjs`（浮层 + 备注页各一条）与 `assert-render.mjs`（v1 路径）。
**旧 deck 不用重生成** —— `[ ]` 是约定不是结构，没写 `[ ]` 的照旧显示；想只改一页用「重生成当前页」，
想整份调口吻用右栏「生成」tab 的提示词（例：*讲稿全部改成可照读的口播，面向讲者的提示放进方括号*）。

### 5.1 页头/页脚的两个版式开关（2026-10，**按主题启用**）

这两条是"结构"级观感差异（kicker 的 DOM 位置、页脚文案口径），纯 CSS 表达不了，
所以做成了主题上的声明式开关 —— `DeckTheme.layoutFlags`，**默认全关**：

| 开关 | 打开后 | 默认（老模板） |
|---|---|---|
| `pinKicker` | kicker 抽成页面级 `.slide-kicker`，绝对定位钉在内容区左上角（top 30px / left 96px），与主标题分离 | kicker 仍排在标题上方，随内容垂直居中（与改版前完全一致） |
| `chapterOnlyFooter` | 页脚左侧只写章节名（`footerText \|\| chapter \|\| course`） | 页脚仍是「课程 · 章节」 |

> 为什么默认全关：渲染是数据驱动的，改渲染层会**连带平台上已经生成的 deck 一起变样**。
> 教师没动过任何东西、样子却变了，不该是换主题之外的副作用 —— 所以新版式只给显式声明的主题
>（目前只有「南大风」）。实测：库里 14 份历史 deck 用老模板渲染，页数/内容/观感均与改版前一致。
> 封面例外：封面的 kicker（`ly-cover-kicker`）属于封面构图，两种模式下都随大标题居中。
> 断言见 `web/tools/assert-semantic.mjs`（默认主题 kicker 在 `.ly-head` 内、南大风是页面级）。

## 6. 模型、成本与护栏

- **默认 `deepseek-flash`**（盲评定版：结构完整性/覆盖更好、延迟约为 v4-pro 的 1/3、成本更低；
  评分记录见 `docs/REVIEW-slides-rubric.md`）。
- 配置：`SLIDES_GENERATOR=llm|mock`、`SLIDES_MODEL`、`SLIDES_OUTLINE_MODEL` / `SLIDES_EXPAND_MODEL`
  （分级策略，如大纲 pro + 扩写 flash）、`SLIDES_LLM_REASONING_EFFORT=low`、
  `SLIDES_TITLE_MAX_CHARS=30`、`SLIDES_BULLET_MAX_CHARS=60` 等，全量见 `server/.env.example`。
- **成本量级**：单章 ≈ 20–30k tokens / 40–90 秒（flash）。护栏：每课程每小时 20 次
  （`SLIDES_GENERATE_PER_HOUR`）+ 同内容缓存（`sourceHash = sha256(正文+模型+prompt版本)`，
  命中直接复用）+ `SLIDES_MAX_TOKENS` 单次上限。
  **2026-09-30 放开 token 限制**：模型上下文支持 500K tokens，`SLIDES_MAX_TOKENS` 默认
  4000→32768（旧预算会把大纲/扩写 JSON 截断，表现为「内容没生成完就结束了」）、
  `SLIDES_SOURCE_MAX_CHARS` 默认 12000→300000、`SLIDES_LLM_TIMEOUT_MS` 默认 90s→300s；
  截断抢救与失败重试保留作兜底。
- **改 prompt 必须把 `SLIDES_PROMPT_VERSION` +1**（当前 **v12**：讲稿分两层 —— 可照读的口播 +
  `[ …… ]` 内联备课提示；沿革见 `slides.config.ts` 的版本注记），否则命中旧缓存看不到新效果。

## 7. 典型工作流

1. 教师写好章节正文 → 章节编辑页点「幻灯片」→「生成」（可顺便选模板）；
2. 等 1 分钟左右（异步生成，页面轮询状态）→ 得 6–20 页初稿；
3. 微调：MD 视图改要点/加备注，JSON 视图精修；个别页不满意点「重生成当前页」单页重写
   （同步一次 LLM 调用，计入每小时频次；该页手工修改会被覆盖）；「插入图片页」5 种版式任选
   （图片库上传/复用），
   单图页可一键「换图」，MD 视图还能「插图到光标」（给并排页补图、手动凑多图网格）；「模板调参」改观感；
4. 放映授课：全屏翻页（←/→、空格、点左右区域、Esc 退出），教师看讲稿（notes）；
5. 章节正文大改后：页面提示「章节内容已变更」→ 选「重新生成」或「保留现有 deck」。

学生侧：章节页顶部「文档 ⇄ 幻灯片」切换，只读（章节须已发布）。

## 9. 已知限制与后续项

- 个别运行缺 end 页（大纲概率事件，重新生成可解）；steps 条目偶带“第一步”冗余字样；
- 长章节分块生成未做（单次送入上限 30 万字；当前真实章节最长 3.6k 字打不到）；
- image-grid 页内逐张换图没有图形化入口（在 JSON/MD 文本里改 `file:` 引用即可）；
- LLM 配图只引用**正文里出现过的**插图（防编造，清单外的 fileId 一律丢弃）；正文无图时不生成图片页；
- **插图依赖正文素材**：目前课程里只有第 2 章（5 张）与第 3 章（3 张）正文有图，其余章节正文本身无图 ——
  想让更多章节图文并茂，需先在章节编辑页右栏「图片」tab 上传插图并插入正文，再重生成该章；
- 数据类内容不依赖素材：正文有数值序列时模型会用 `chart` 块自绘图表；
- v2/v3 候选：Mermaid/公式渲染、pptx/pdf 导出、自由 CSS 模板档（见设计文档 §13.4「仍未做」；
  插图链路本身见 §14）。
