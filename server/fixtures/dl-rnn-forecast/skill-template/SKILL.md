# 传感器时序估计 Skill（你的方案）

> **本实验是应用任务，不是"按口径写代码"**：给你一个真实需求（提前一分钟估出设备温度），
> **窗口长度、网络结构、特征组合、优化器都由你自己决定**。没有唯一答案 ——
> 达标看的是"**MAE 达到比值线** + 你能不能**说清窗口与时序纪律**"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | 业务背景 + 三条要求 + 达标线 + 数据字典 + **口径**（滑窗/切分/基线）+ 交付格式 |
| `judge.md` | 判据：哪些项会被核对（含"时序纪律"与"可疑地过于好"） |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案） |
| `cases/case01`、`cases/case02` | 两批时序（常规工况 / 工况变了），自测用 |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 要减掉的是"下一分钟往哪走"的误差 | 心里有数 |
| ② **看一眼数据 + 画图** | 趋势/周期/台阶/噪声，下一分钟会不会突变 | `figures/` 里第 1 张图 |
| ③ 定基线 | 现有做法（当前读数当下一秒）在同一测试段上的 MAE | 报告的 `baseline` |
| ④ **滑窗 + 训练 + 画图** | 切样本 → 标准化 → 训练，**逐轮记录 loss/val_loss**，画训练曲线 | 报告的 `window` / `training`、第 2 张图 |
| ⑤ **评估 + 画图** | 测试段 MAE/RMSE + 预测 vs 实际（误差在哪一段） | 报告的 `metrics`、第 3 张图 |
| ⑥ **写结论** | 为什么取这个窗口、周期与工况怎么处理、还有什么不足 | 报告的 `figures` / `notes` |

材料配合：`task.md`（需求 + 口径）→ 读 `reference/`（一份**走完这六步**的示范）→ 回 `scripts/train.py` 走自己的六步 → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **窗口多长**：3 分钟能看到什么？45 分钟？为什么不是越长越好？
2. **预测绝对值还是增量**：两种都行，但猜猜哪种更好学、为什么。
3. **用哪些特征**：`current` / `vibration` / `ambient` / 周期编码各自有多少用？（② 的图会给你线索）
4. **怎么切分与标准化**：为什么必须按时间切、只能用训练段统计量做标准化？
5. **训练怎么控**：学习率、epoch 上限、早停 patience、取哪一轮的权重。

`training{history,epochs_run,best_epoch,early_stopped}` / `figures[≥3 张]` / `notes`。

## 自测

两个 case 都要跑，并对照 `task.md` 的达标线自己核一遍（case01 比值 ≤ 0.55、case02 ≤ 0.60）：

```sh
for c in cases/*/; do
  python3 scripts/train.py "$c" /tmp/out_$(basename "$c").json
done
```

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段，再回来改自己的实现。
