评分细则（应用任务：达标判定）

⚠️ 窗口长度/网络结构/特征/轮数由学生自选，**输出数值不要求等于参考水平**（`expected.json` 是"参考水平"，不是标准答案）。

**硬性条件与全部数值门槛由平台断言判定**（`manifest.json` 的 `assertions`）：报告字段完整、
图表说明齐全、`mae` 为正数、**窗口 ≥3 分钟**、滑窗样本数自洽、测试集占比、逐轮训练历史、训练轮数自洽、
是否早停、**基线可信**（与参考值的容差）、**达标线**（MAE 相对基线的比值，门槛值见各 case 的
`expected.json.accept`）、以及"不能低到不可能"的下界。未过断言者不交给你判，**你不必重算任何数值**。

只判下列语义项（任一不成立 → 不通过）：

1. 三张图里必须有一张讲**逐轮训练过程**（从哪一轮开始变差、怎么处理），一张讲**误差出现在哪一段时刻**。
   结论套话、互相复述、或与 `training` / `metrics` 矛盾 → 不通过。
   （小批量训练时逐轮损失并不单调，**轮间的小幅波动本身不算矛盾**；只看「验证损失触底之后是否还有新的收益」
     这类结论是否与 `training` 自洽。）
2. `notes` 必须说清**为什么取这个 `window`**（更短/更长会怎样）以及**周期与工况怎么处理**。
   只写"用了 LSTM，效果不错" → 不通过。
3. **时序纪律**：测试段必须是时间序列**最后一段**（训练段不晚于测试段）。若显示用了随机打乱切分 → 数据泄漏 → 不通过。
4. `mae` 低于参考水平的 0.3 倍且 `notes` 无解释 → 判为可疑（疑打乱切分、用测试段调参、把 `temp_next` 当特征）→ 不通过。
5. `baseline` 必须是"把当前读数当下一秒"且在同一测试段上算；拿训练过的模型当基线、或用整段（含测试段）算 → 不通过。

口径：键序 / 缩进 / 空白 / 小数位差异不扣分；`score` = 达成程度（任一项不成立时 ≤0.5）；
rationale 用中文、一句话（≤60 字），不通过时指出具体哪一项。
