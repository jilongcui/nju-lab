# 深度学习实验三：传感器时序下一值估计（序列建模 · 滑窗 + LSTM）

## 业务背景

你是某车间设备监控系统的算法同学。系统按分钟采集一组传感器读数，运维同学需要在**过热之前**
提前一分钟估出设备温度（`temp_next`），据此决定是否调低负载。

**现有做法**：监控看板上直接显示**当前这一分钟的读数** —— 要看"下一分钟"怎么办？
经验做法就是把它当成下一分钟的估计（"温度不会突变"）。它不需要模型，也不需要历史 ——
所以你的任务不是"跑个 LSTM"，而是**比这个做法明显更准**，并说清你是怎么用历史的。

## 你的任务

用工作目录里的 `data.csv` 训练一个**序列模型**（LSTM / GRU / 一维卷积…由你选），
对**任意一分钟**给出下一分钟的估计，产出 `output.json` 与你的图，达到三条要求：

1. **比现有做法明显更好**：在测试段上，平均绝对误差（MAE）要达到达标线：

   | case | 数据 | 达标线 |
   |---|---|---|
   | `cases/case01` | 1500 分钟，常规工况 | MAE ≤ **0.55 ×** 现有做法的 MAE |
   | `cases/case02` | 1200 分钟，**工况变了**（工作循环变快、中段负载整体抬升、读数噪声更大） | MAE ≤ **0.60 ×** 现有做法 |

2. **必须真的用上一段历史**：至少看 `window ≥ 3` 分钟的窗口（具体多长由你定），
   并把**逐轮训练历史**（每轮的训练损失与验证损失）写进报告，用**训练曲线**说明
   什么时候开始过拟合、为什么取最优轮次。
3. **按时间切分、用图讲清楚**：**不许打乱时间顺序**（测试段取时间序列**最后**一段，占比 20%~40%）；
   看数据时画图、训练过程画图、预测结果画图，**每张图写一句结论**（写进 `figures` 字段）。

> 网络结构、窗口长度、特征组合、优化器、epoch 数、早停策略都由**你自己决定**
> （选一个你能讲清楚的即可，不必做多个方案的对比）。达标与否看上面三条是否真的做到（判据见 `judge.md`）。

## 实验流程（六步，每一步都要走完）

这是一个**完整的小任务**。按下面六步走，②④⑤都要产图（共至少 3 张）：

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 要减掉哪种误差、什么算成功（比"当前值当下一秒"好多少） | 心里有数 |
| ② **看一眼数据 + 画图** | 温度怎么走（趋势 / 周期 / 台阶）、目标怎么分布、噪声有多大；**画一张总览图** | `figures/` 里第 1 张图 |
| ③ **定基线** | 不做模型能做到多少（当前读数当下一秒），在**同一测试段**上算 MAE | 报告的 `baseline` |
| ④ **滑窗 + 训练 + 画图** | 切成 (窗口 → 下一分钟) 样本 → 标准化 → 训练序列模型，**逐轮记录训练/验证损失**，画训练曲线 | 报告的 `window` / `training`、第 2 张图 |
| ⑤ **评估 + 画图** | 测试段 MAE / RMSE，并**画出预测 vs 实际**（误差出现在哪一段） | 报告的 `metrics`、第 3 张图 |
| ⑥ **写结论** | 每张图一句结论 + 整体判断（`notes`：为什么这么定窗口、怎么处理周期/工况、还有什么不足） | 报告的 `figures` / `notes` |

> 图用 `matplotlib` 画（镜像已预装），存到工作目录的 `figures/` 下，例如
> `plt.savefig("figures/forecast.png", dpi=110)`。**图是给你自己看的** ——
> 但请把"从图里看到了什么"写进 `takeaway`，否则没人知道你看了。
>
> ⚠️ 图里的**标题与坐标轴标签建议用英文**（如 `Prediction on the test segment`）：运行环境里没有中文字体，
> 中文会渲染成方框。中文解释写在 `takeaway` 和 `notes` 里（那些是给人读的）。

## 数据字典（`data.csv`）

每分钟一行；目标是**紧接这一分钟的下一分钟**的温度。

| 列 | 含义 |
|---|---|
| `minute_of_day` | 这一分钟是一天里的第几分钟（0~1439） |
| `ambient` | 环境温度 ℃ |
| `current` | 设备电流读数 A（负载的代理量） |
| `vibration` | 振动强度（任意单位） |
| `temp` | **这一分钟**的设备温度读数 ℃ |
| `temp_next` | **目标**：**下一分钟**的设备温度 ℃ |

> 数据是固定种子合成的**教学数据**（不是真实设备日志），规律符合常识：
> 负载按**工作循环**上下走（`current` 看得出来），温度跟着它起落，但**慢半拍**（热惯性），
> 同时仪表读数带一点噪声。注意：**工作循环不是"整点"**，`minute_of_day` 里藏着它的影子，
> 但光看一个时刻的数值给不出"下一分钟往哪走"。

## 口径（必须这样算，判据会核对）

1. **滑窗**：用连续 `window` 分钟的特征预测**紧接其后**那一分钟的温度。
   这样样本数 ≈ 行数 − `window` + 1（开头被窗口"吃掉"的行没法用）。`window ≥ 3`。
2. **按时间切分**：测试段取时间序列**最后** 20%~40%（不许随机打乱 —— 打乱会让"未来"漏进训练）。
   训练段内部如果要划验证集，也从**它的末尾**划。
3. **基线**：现有做法 = 把当前这一分钟的读数当下一秒。在**同一测试段**上算它的 MAE。
4. **`n_train` / `n_test`** 都指**滑窗样本数**（不是原始行数）。

## 交付格式

**`output.json`**（写在工作目录下）：

```json
{
  "model": "你最终使用的模型名称（例如 LSTM(32) + delta head）",
  "window": 8,
  "n_train": 934,
  "n_test": 375,
  "metrics": { "mae": 0.11, "rmse": 0.13 },
  "baseline": { "name": "persistence", "mae": 0.62 },
  "training": {
    "epochs_planned": 60,
    "epochs_run": 60,
    "best_epoch": 59,
    "early_stopped": false,
    "history": [
      { "epoch": 1, "loss": 1.31, "val_loss": 1.18 },
      { "epoch": 2, "loss": 0.72, "val_loss": 0.61 }
    ]
  },
  "figures": [
    { "path": "figures/data_overview.png", "takeaway": "温度按约 45 分钟的工作循环上下走，幅度约 10℃；读数噪声很小（约 0.1℃），所以下一分钟的走向主要由循环位置决定。" },
    { "path": "figures/training_curve.png", "takeaway": "训练与验证损失一起下降，第 59 轮最低后验证损失不再改善，说明再练只会拟合噪声。" },
    { "path": "figures/forecast.png", "takeaway": "预测曲线与实测几乎重合；残差集中在循环拐点（正负切换处），说明模型对方向反转的反应略慢。" }
  ],
  "notes": "先看图：温度被约 45 分钟的工作循环带动、噪声很小，而当前值给不出方向，所以必须看窗口。窗口取 8 分钟能覆盖上升/下降段，再长帮助不大；标准化后用 LSTM（32 隐单元）预测增量（窗口最后读数 + 网络输出的变化量），测试段 MAE 0.11，比现有做法（0.62）低约 82%。不足：循环拐点处误差偏大。"
}
```

- `metrics` 至少要有 `mae`（`rmse` 可选，推荐给）。
- `baseline.mae` 必须是**你自己算出来的**现有做法 MAE（当前读数当下一秒，测试段上算）。
- `training` 必须有 `history`（**每轮一条**，含 `loss` 与 `val_loss`）、`epochs_run`、
  `best_epoch`、`early_stopped`。轮数很多（`epochs_run` > 60）时可按等间隔抽样到约 60 条 —— 完整曲线以训练曲线图为准，别把报告撑得过大。
- `figures` 至少三张：看数据（②）、训练曲线（④）、预测 vs 实际（⑤），每张都要有 `path` 与一句 `takeaway`。
- 数值不需要和任何"标准答案"一致 —— 达标看的是"是否真的比现有做法好到达标线"。

## 怎么算完成

1. 写一个能跑的方案（推荐做成 Skill 里的一段脚本），能对任意一份同结构 `data.csv`
   产出 `output.json` 与三张图。
2. 在 `cases/case01` 与 `cases/case02`（不同工作循环/不同工况）上都达标 —— 判据对两个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
