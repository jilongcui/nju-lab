# 题目包：传感器时序下一值估计（序列建模 · 滑窗 + LSTM）

> 这是本实验的**题目包** —— 一个真实需求（提前一分钟估出设备温度）、达标线、两批时序数据，
> 外加**一份示范实现**（`reference/`）供你对照学习。

## 这个实验要学什么

1. **时间顺序不能乱**：时序任务里"随机打乱切分"= 让未来信息漏进训练，成绩会虚假地好。
   正确做法是**按时间切**（测试段取最后一段），本实验的判据会因此核对你的切分。
2. **滑窗是把时序变成监督学习的标准动作**："用连续 `window` 分钟 → 预测下一分钟"，
   窗口长度本身就是一个要论证的决策（太短看不到趋势、太长会把旧工况带进来）。
3. **从窗口里读方向**：这一批数据里"下一分钟往哪走"取决于循环处于上升段还是下降段 ——
   单个当前值给不出方向，只有历史能。
4. **预测增量比预测绝对值容易**：先估"下一分钟比现在高/低多少"，再加回当前读数 ——
   网络不用把 40 多度的基线也学一遍（参考实现就是这么做的，你可以试试别的路子）。
5. **训练过程要看得住**：逐轮记 `loss` / `val_loss`，用训练曲线判断从哪一轮开始过拟合、取哪一轮权重。

## 两批数据

| case | 规模 | 特点 | 参考水平（现有做法 → 参考实现） |
|---|---|---|---|
| case01 | 1500 分钟 | 常规工况，工作循环 45 分钟 | MAE 0.617 → **0.109**（比值 0.18） |
| case02 | 1200 分钟 | **工况变了**：循环 37 分钟、中段负载抬升 6℃、噪声更大 | MAE 0.749 → **0.299**（比值 0.40） |

> `expected.json` 里的数值**不是标准答案**，而是"参考水平"：判据用它核对你的
> `baseline.mae` 是否可信、并识别"可疑地过于好"的结果。你可以做得比参考实现更好，
> 只要说清是怎么做到的。

## 自测方法

CLI 约定：`train.py <case_dir> <output.json>`（`<case_dir>` 里要有 `data.csv`）。

```sh
# 两个 case 都跑一遍，看比值 = metrics.mae / baseline.mae（case01 要求 ≤ 0.55、case02 ≤ 0.60）
for c in cases/*/; do python3 <你的skill>/scripts/train.py "$c" /tmp/out_$(basename "$c").json; done
```

脚本末尾会打印本轮 MAE、基线 MAE、比值、窗口长度与训练轮数。判据的其余各项
（`training.history`、图的条数、样本数自洽、`notes` 长度）请对照 `judge.md` 自己核一遍。

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段。
