# 检验报告解读 Skill（参考实现 · 学习示范）

> 📖 这份实现**随题目包一起下发**（`problem/reference/`），是给你的**示范** —— 不是标准答案。
> 判据只看"判定口径一致 + 危急值抓得全 + 不确定的项如实报 + 不越界下诊断 + 说得清"，
> 所以函数怎么切、图怎么画、文案怎么写都随你；换一种写法只要口径一致就能通过。

## 能力边界

- 能处理：`lab_report.csv` + `reference_ranges.csv`（+ 可选 `patient.json`）这套固定结构的输入
- 能处理：带全角字符、前后空白、空值、重复项目行的报告单（按题干口径清洗并计数）
- 能处理：只给单侧区间（`ref_low` 或 `ref_high` 为空）、不给危急阈值的项目
- 能处理：**参考区间表里没有的项目** —— 判 `unknown` 并列出，不猜
- 不处理：**趋势判断**（需要同一患者多次历史结果）、项目之间的组合意义（如阴离子间隙）
- 不处理：单位换算（报告单单位与区间表不一致时不做换算，会按区间表的口径判）
- 不处理：影像 / 病理 / 心电报告，以及任何需要**诊断**或**用药建议**的诉求

## 方法（六步 —— 与 `task.md` 的流程一致）

1. **看清需求** —— 报告单只有"项目/值/单位"，判定依据在区间表里；`description` 要写清触发与不适用
2. **读材料** —— `load_report` / `load_ranges` / `load_patient`
3. **清洗归一** —— `clean_rows`：全角转半角 → 去空白 → 丢空值/非法值 → 同名项目只留首次（顺序不能反）
4. **逐项比对** —— `classify`：`flag` 用严格不等（等于上限算正常）、危急值用闭区间（等于阈值就报警）
5. **报警 + 画图** —— `build_alerts`（每条 `reason` 写出依据阈值）+ `plot_deviations`（偏离参考区间）
6. **写结论** —— `compose_summary`（含就医提示、不下诊断）+ `compose_notes`（口径与局限）

产出结构（`output.json`）见 `task.md`；判据见 `judge.md`。

## 为什么把算数交给脚本（本章的教学点）

- 模型对"6.2 是不是超过 6.2"这类**边界问题**极不稳定：它会给出"略高""基本正常"这类含糊结论；
  这条口径又恰恰是安全相关（危急值漏报的代价最大）→ 所以 `classify` 只做机械比较，模型只负责**表达**；
- `skill_card.description` 是**触发路由**：写不清"什么时候不该用我"，Skill 就会在影像报告、
  用药咨询这类场景被错误触发 —— 这正是正文里"description 不是宣传语"的意思；
- 正文里的 `hooks` 拦截（检测到危急值就强制提示）在实验里落成
  **`critical_alerts` + `summary` 里的就医提示**：平台没有 hooks 运行时，但"拦截"可以被检验。

## 实测档案

- 自测时间：2026-10-10（参考实现复验 2/2 通过）
- 用例通过率：2/2
- 关键数字：
  - case01：报告单 15 行 → 13 项（12 可判定 + 1 表外 `BIL-T`），丢弃 1 非法 + 1 重复；
    危急值 3 个（`K` 6.2、`PLT` 28、`WBC` 1.2）
  - case02：报告单 19 行 → 16 项（15 可判定 + 1 表外 `FERR`），丢弃 1 非法 + 2 重复；
    危急值 3 个（`CA` 1.55、`CREA` 560、`GLU` 26.0）
- 踩坑记录（pitfalls）：
  - **两条边界口径方向相反**：`flag` 严格不等（等于参考上限算正常），危急值闭区间（等于危急阈值就报警）
    —— 一开始两条都写成同一方向，`LDL` 3.4 与 `K` 6.2 全判错了
  - 全角数字必须按 NFKC 转半角再 `float()`：`６．４` 直接解析会失败，整行被当成非法值丢掉
  - 去重口径是"保留**首次**出现"：`case02` 里 `K` 先出现 3.5、后面又出现 7.1（危急值），
    若按"取更严重的"就会多报一个危急值
  - `item` 排序用 `sorted()`（ASCII 序）：`HBA1C` / `HGB` 这类全大写项目名不会有歧义，
    但如果混入小写就会排到后面 —— 列表顺序也是断言要比对的一部分
