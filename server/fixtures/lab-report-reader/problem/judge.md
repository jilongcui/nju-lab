评分细则（**应用任务：检验报告解读 Skill**）

⚠️ 清洗口径与判定口径已在 `task.md` 里钉死，所以逐项 `flag`、危急值名单、丢弃计数、`unknown` 名单
都是**确定的**。这些已由平台用**确定性断言**判定（见 `manifest.json` 的 `assertions`）：
字段完整、逐项判定（含边界值与排序）、`flag` 合法性、危急值名单与条数、丢弃计数、
`unknown` 名单与区间为 `null`、技能卡字段齐全、`reason` 长度、图、`summary`/`notes` 长度。
断言未通过的结果**不会交给你判**，你不必重算这些数字。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`skill_card.description` 是不是一条合格的"触发路由"**（对照本章正文：description 不是宣传语，
   而是模型决定"用不用这个技能"的依据）。应当同时说清：解决什么任务、什么指令会触发、
   **什么场景不适用**。以下情况**不通过**：只有一句"这是一个检验报告工具"这类自我描述；
   只写能力不写边界；把 `not_applicable` 写成"我没有限制"这种空话。
2. **有没有越界**：`summary` / `notes` / `items` 里出现诊断性断言（"这是糖尿病""确诊……"）、
   用药或治疗建议（"建议服用……""必须打胰岛素"）→ 不通过。正确的写法是描述
   "数值与参考区间的关系"，并给出**就医提示**（"尽快联系临床医生核对"）。
3. **`critical_alerts[].reason` 是否说清了依据**：应当写出触发的是哪一侧阈值、阈值是多少（含单位），
   并且与该项目的 `items` 记录自洽。只写"结果异常，请复查""需要重视"这类没有依据的话 → 不通过。
4. **`summary` 是否与报告自洽**：正常/偏高/偏低各几项、哪几项达到危急阈值，必须与 `items`、
   `critical_alerts` 对得上（**允许四舍五入**，例如"偏低 3 项"而实际是 3 项即可）；
   有没有交代"有项目因为缺参考区间无法判定"（`unknown`），有没有说明**不构成诊断**。
   数字与 `items` 矛盾、或对危急值只字不提 → 不通过。
5. **`notes` 是否讲清了做法的关键与局限**：至少要提到 ① `flag` 用严格不等（等于参考上限/下限算正常）
   而危急值用闭区间（等于危急阈值就报警）这处**容易判错的地方**；② 清洗顺序（先丢空值/非法值，
   再去重）；③ 至少一条**真实的**局限（例如只能看单次结果、判断不了趋势；参考区间没按性别/年龄细分；
   不识别项目之间的组合意义）。只复述题目、只堆字段名、把 `notes` 写成操作流水 → 不通过。

判定口径：
- 键序、缩进、空白、小数位差异不扣分。数值是否符合口径**由断言负责**，你不必复核；
  你只管「报告内部是否自洽」与「有没有越界」。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
