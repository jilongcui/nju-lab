# 应用任务：做一个"检验报告解读"Skill

## 业务背景

社区医院检验科每天要给患者出一批报告单。医生看报告要一项项对着参考区间算，慢且容易漏掉**危急值**
（例如血钾 6.2 mmol/L）——漏掉的代价很大。

科室想把这个流程**固化成一个 Skill**：患者/护士把报告单交给它，它把每一项判成
**正常 / 偏高 / 偏低 / 无法判定**，把达到危急阈值的项目单独拎出来提醒，最后给一段**说得清依据**的解读。

这条流程有两类知识：**能写死的**（数值 vs 参考区间的比较、阈值判断）和**要判断的**
（报告该怎么解读、哪些话不能说）。这正是这一章要讲的工程原则：

- **确定性任务下沉给脚本** —— 算数、比大小交给代码，不让大模型"心算"，否则它会把 6.2 说成正常；
- **description 是触发路由** —— 你的 Skill 必须写清"什么指令会触发我、什么情况我不该接"；
- **风险操作要有拦截**（正文里的 `hooks`）—— 危急值必须被拦住并突出提示；全程**不许下诊断**。

> 说明：本课程的运行环境里没有 hooks 运行时（那是平台能力，不是 Skill 能自带的东西）。
> 所以本实验把"拦截"落成**交付物里必须出现的两样东西**：每一处危急值都要进 `critical_alerts`
> 并写明依据阈值，`summary` 里要给出"尽快就医/联系临床医生"的提示 —— 这就是可被检验的"拦截"。

## 你的任务

用工作目录里的 `lab_report.csv`（报告单）、`reference_ranges.csv`（参考区间表）、`patient.json`
（虚拟患者信息）做一个**可复现的解读方案**，产出 `output.json` 与一张图。具体要求：

1. **先看清口径**（下面「清洗口径」与「判定口径」是钉死的业务规则，逐字执行）；
2. **把不确定性如实报出来** —— 参考区间表里**没有**的项目判 `unknown`，不许猜成正常或异常；
3. **把判定下沉到脚本** —— 清洗与比较都写成代码；`output.json` 里的数字应当来自脚本，不是你的推理；
4. **把 Skill 的"脸面"写进报告** —— `skill_card` 里的 `description` 就是模型的触发路由
   （写清：解决什么任务、什么指令触发、**什么场景不适用**）；
5. **安全边界** —— 危急值逐条进 `critical_alerts`（`reason` 要写出依据的阈值与单位），
   `summary` 给出就医提示，**任何地方都不要下诊断结论**（不要写"这是糖尿病""确诊……"）；
6. **用图说清结论** —— 每一项相对参考区间的偏离画成一张图，写一句结论。

> 代码怎么组织、函数怎么切、图怎么画都随你（`csv` / `json` 标准库 + `matplotlib` 就够了，
> 不需要装任何东西）。判据看的是：**口径一致 + 危急值抓得全 + 不确定的项如实报 + 不越界 + 说得清**。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 谁用、什么算解决、哪些话不能说（安全边界） | 心里有数（写进 `skill_card`） |
| ② **读材料** | 报告单只有"项目/值/单位"，判定依据在**参考区间表**里；先看清两份文件怎么对应 | 报告的 `items`（先有个印象） |
| ③ **清洗归一** | 全角转半角、去首尾空白、丢弃空值/非法值、同一项目只留首次出现 | 报告的 `dropped` |
| ④ **逐项比对** | 用区间表逐项判 `normal / high / low / unknown`，并判危急值 | 报告的 `items` / `unknown_items` |
| ⑤ **报警 + 画图** | 危急值逐条给出依据；把偏离参考区间的程度画成一张图 | 报告的 `critical_alerts` / `figures` |
| ⑥ **写结论** | `summary` 讲清结论与建议、`notes` 讲清口径与局限 | 报告的 `summary` / `notes` |

> 图用 `matplotlib`（已预装）画，存到工作目录的 `figures/` 下，例如
> `plt.savefig("figures/lab_report_flags.png", dpi=110)`。
> ⚠️ **图上的标题与坐标轴标签必须用英文**：运行环境里没有中文字体，中文会渲染成方框。
> 中文解释写在 `figures[].takeaway`、`summary` 与 `notes` 里。

## 清洗口径（**逐字执行**，顺序不能反）

对 `lab_report.csv` 逐行处理，**按文件里的出现顺序**：

1. **全角转半角 + 去首尾空白**：`item` / `value` / `unit` 三个字段都做。
   全角字符按 Unicode 兼容分解（NFKC）转半角：`６．４` → `6.4`。例：` 6.2 ` → `6.2`、` HBA1C ` → `HBA1C`。
2. **必填字段不能为空**：`item`、`value`、`unit` 任一为空 → 整行丢弃。
3. **`value` 必须能解析成数字**（可有小数点与正负号）→ 否则整行丢弃。
4. **同一 `item` 只保留首次出现**：重复的整行丢弃（**哪怕后面那条更严重也不例外**）。
5. 丢弃计数分两类写进报告：`dropped.invalid`（第 2/3 步丢的）与 `dropped.duplicates`（第 4 步丢的）。

> 顺序要求：**先做 2/3 再判 4**。如果先去重，一条空值的坏行可能把后面的好行挡掉。

## 判定口径（**钉死**，两处的不等号方向不同，看清楚）

区间表 `reference_ranges.csv` 按 `item` 匹配（`ref_low` / `ref_high` / `critical_low` / `critical_high`
**可以是空字符串 = 这一侧不判**）。

**① `flag`（用严格不等）**：

| 条件 | `flag` |
|---|---|
| `ref_high` 非空且 `value > ref_high` | `high` |
| `ref_low` 非空且 `value < ref_low` | `low` |
| 其余（含**恰好等于**参考上限/下限） | `normal` |
| `item` 不在区间表里 | `unknown`（`ref_low`/`ref_high` 写 `null`，`critical` 为 `false`） |

**② `critical`（用闭区间，安全侧优先）**：

| 条件 | `critical` |
|---|---|
| `critical_high` 非空且 `value >= critical_high` | `true` |
| `critical_low` 非空且 `value <= critical_low` | `true` |
| 其余 | `false` |

> 两处口径的差别是刻意的：**恰好等于参考上限算正常**（区间是"参考范围"），
> **恰好等于危急阈值就要报警**（宁可多提醒，不可漏）。这正是"算数必须交给脚本"的原因 ——
> 靠感觉判，边界值一定会错。

## 数据字典

`lab_report.csv`：

| 列 | 含义 |
|---|---|
| `item` | 检验项目（`ALT` / `AST` / `CRP` / `CREA` / `GLU` / `HBA1C` / `HGB` / `K` / `LDL` / `PLT` / `TSH` / `WBC` / …） |
| `value` | 结果值（可能有全角字符、前后空白、空值） |
| `unit` | 单位 |

`reference_ranges.csv`：

| 列 | 含义 |
|---|---|
| `item` | 检验项目（与报告单对应） |
| `unit` | 该项目在**本表方法学**下的单位 |
| `ref_low` / `ref_high` | 参考区间下限 / 上限（空 = 不判这一侧） |
| `critical_low` / `critical_high` | 危急值下限 / 上限（空 = 该项目不判这一侧） |

`patient.json`：虚拟患者信息（`report_id` / `name` / `sex` / `age` / `collected_at` / `complaint`），
可用于 `summary` 的开头。数据是**虚构教学数据**，没有真实患者。

## 交付格式

**`output.json`**（写在工作目录下；**键名与层级按下面的样例写**）：

```json
{
  "skill_card": {
    "name": "lab-report-reader",
    "description": "检验报告解读 Skill：读取报告单与参考区间表，逐项做「数值 vs 参考区间」的比对，判正常/偏高/偏低/无法判定，挑出达到危急阈值的项目并给出依据；当用户贴出报告单、问「这些指标正常吗 / 有没有危急值」时触发。只做区间比对与科普层面提示，不下诊断结论，不适用于影像与病理报告。",
    "triggers": ["用户贴出或上传检验报告单", "用户问「有没有危急值」", "用户要求生成结构化解读"],
    "not_applicable": ["影像 / 病理 / 心电报告（没有「数值 vs 参考区间」结构）", "需要下诊断或给治疗建议的场景"],
    "safety_rules": ["命中危急阈值必须进 critical_alerts 并提示尽快就医", "禁止诊断性断言与用药建议"]
  },
  "items": [
    { "item": "ALT", "value": 38.0, "unit": "U/L", "ref_low": 7, "ref_high": 40, "flag": "normal", "critical": false }
  ],
  "critical_alerts": [
    { "item": "K", "value": 6.2, "unit": "mmol/L", "reason": "value 6.2 mmol/L 达到危急上限 6.2 mmol/L" }
  ],
  "unknown_items": ["BIL-T"],
  "dropped": { "invalid": 1, "duplicates": 1 },
  "summary": "……（≥60 字：正常/异常各几项、哪几项达到危急阈值、建议尽快就医；并说明不构成诊断）",
  "figures": [
    { "path": "figures/lab_report_flags.png", "takeaway": "……（一句话结论，数字要与 items 自洽）" }
  ],
  "notes": "……（≥60 字：口径与做法、边界怎么处理的、局限在哪里）"
}
```

- `items` **按 `item` 的 ASCII 升序**（Python 默认 `sorted()` 的顺序），每项字段名与样例一致；
- `flag` 只能取 `normal` / `high` / `low` / `unknown`；
- `critical_alerts` 按 `item` 升序，`reason` 要写清"依据哪条阈值"（含数字与单位）；
- `unknown_items` 列出所有判 `unknown` 的 `item`（**没有就给空数组**）；
- 图至少 1 张：`path` + 一句 `takeaway`（结论要"看图说话"，并与你报的数字自洽）；
- 报告里的数值**不需要**和任何人一致 —— 只要口径对，它们**本来就该相同**；口径错了就会不一样。

## 怎么算完成

1. 写一个能跑的方案（本实验就是一个 Skill：`SKILL.md` + `scripts/`），能对任意一份同结构的
   报告单 + 区间表产出 `output.json` 与一张图；
2. 在 `cases/case01` 与 `cases/case02`（两批不同数据）上都能跑通 —— 判据对两个 case 各判一次；
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
