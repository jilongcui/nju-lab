# 用药安全预警 Skill（你的方案）

> **本实验是应用任务**：给你一个真实需求（审查医嘱里的禁忌与相互作用，并说清"为什么"），
> **图怎么存、代码怎么组织由你自己决定**；预警口径与本体校验是口径（必须照做），
> 达标看的是"图与预警口径一致 + 更新（含被拒绝的）真的落到图上 + 说清可解释性与局限"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：业务背景、六步流程、建图/预警/更新口径、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（函数划分与你的骨架一致） |
| `cases/case01`、`cases/case02` | 两批数据，自测用（各带 `expected.json` 可对照） |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 要答的是关系问题；医生要的是"为什么有风险"而不只是"有风险" | 心里有数 |
| ② **回头看本体** | 实体类型 + 每种关系的端点类型（`from`/`to`）—— 图更新的校验依据 | 报告的 `graph` |
| ③ **建图** | 三元组 → 有向图（边带关系名） | 报告的 `graph` |
| ④ **多跳预警** | 两跳碰头（患者—疾病—药物）、两味药之间找边，**每条留路径** | 报告的 `alerts_before` |
| ⑤ **图更新** | 补录 / 撤销 / 更正，每条先过本体校验，不合格的拒绝 | 报告的 `crud` |
| ⑥ **再看一次 + 写结论** | 更新后重跑预警、对比图、说清可解释性与局限 | `alerts_after` / `figures` / `notes` |

材料配合：`task.md`（需求 + 口径）→ 读 `reference/`（一份**走完这六步**的示范）→
回 `scripts/kg.py` 填掉自己的 TODO → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **为什么用图而不是表**：同一件事用 SQL 要几次 JOIN？增加一跳会怎样？"路径"为什么重要？
2. **本体是干什么的**：为什么更新要按 `relation_schema` 校验端点类型？
   被拒绝的那条更新**错在哪**？（提示：往"药物→疾病"的关系上塞了患者节点）
3. **方向性**：禁忌证是有向的（药物→疾病），相互作用是**相互**的 —— 这个差别怎么体现在查询里？
4. **更新的可见性**：撤销一条医嘱后，哪些预警应当消失？为什么"更新后必须重跑查询"？

## 自测

```sh
for c in cases/*/; do
  python3 scripts/kg.py "$c" "/tmp/$(basename "$c").json"
done
```

> 卡住了怎么办：先看 `reference/scripts/kg.py` 里对应的那一段，再回来改自己的实现。
