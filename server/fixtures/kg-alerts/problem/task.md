# 应用任务：用药安全审查（用知识图谱做多跳预警）

## 业务背景

医院的合理用药审查需要回答一类**关系型**问题：

- 患者 P001 患有严重肾功能不全，而医嘱里开了二甲双胍 —— **这个药对这个病是禁忌的**；
- 患者 P005 长期服用华法林，这次又开了阿司匹林 —— **两味药之间有相互作用**。

用关系数据库也能做，但要层层 JOIN，而且**每增加一跳就要重写查询**；更重要的是，
医生要的不只是"有风险"这个结论，而是"**为什么有风险**" —— 一条能展示出来的推理路径。

工作目录里有一份**三元组表**（`triples.csv`，药物知识 + 患者数据）、一份**本体**（`ontology.json`，
定义实体类型与每种关系的端点类型）、一份**图更新单**（`updates.json`）。

## 你的任务

用 `networkx`（已预装，也可以自己写邻接结构）把三元组建成**知识图谱**，产出报告 `output.json` 与一张图：

1. **建图**：三元组 → 有向图；统计实体类型与关系类型（类型按 `ontology.json` 的映射取）；
2. **多跳预警**：找出**禁忌证预警**与**相互作用预警**，每条预警都要带**完整的推理路径**；
3. **图更新**：按 `updates.json` 补录 / 撤销 / 更正，**每条更新先过本体校验**，
   不合格的要**拒绝**并计数；
4. **更新后再看一遍**：撤销医嘱应当让对应预警消失，补录带冲突的患者会带来新预警；
5. **用图说清变化**：把"更新前后两类预警的数量"画成一张对比图，写一句结论。

> 图怎么存、怎么组织代码由你决定；达标看的是"图与预警口径一致 + 更新（含被拒绝的）真的落到图上 +
> 能不能说清可解释性与局限"。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 要答的是"关系"问题；为什么"有路径"比"有结论"更重要 | 心里有数 |
| ② **回头看本体** | 实体类型 + 每种关系的端点类型（`from`/`to`）—— 它是图更新的校验依据 | 报告的 `graph` |
| ③ **建图** | 三元组 → 有向图（边带关系名） | 报告的 `graph` |
| ④ **多跳预警** | 两跳把"患者—疾病—药物"碰头、在"患者在用的两味药"之间找边，**留路径** | 报告的 `alerts_before` |
| ⑤ **图更新** | 补录 / 撤销 / 更正，每条先过本体校验，不合格的拒绝并计数 | 报告的 `crud` |
| ⑥ **再看一次 + 写结论** | 更新后重跑预警、画对比图、说清可解释性与不足 | `alerts_after` / `figures` / `notes` |

> 图用 `matplotlib`（已预装）画，存到工作目录的 `figures/` 下，例如
> `plt.savefig("figures/alert_counts.png", dpi=110)`。
> ⚠️ **图上的标题与坐标轴标签必须用英文**：运行环境里没有中文字体，中文会渲染成方框。
> 中文解释写在 `figures[].takeaway` 与 `notes` 里。

## 建图口径

- `triples.csv` 每行是一条三元组 `head,relation,tail` → 一条**有向边**（`head → tail`，边上带关系名）；
- 实体类型取自 `ontology.json` 的 `entity_types`（实体名 → 类型），不在表里的记为 `Unknown`；
- `graph` 里的 `entity_types` / `relation_counts` 都按**键名升序**输出（结果要可复现）。

## 预警口径（两类，都要带路径）

**在用药** = 关系 `服用` 或 `医嘱使用`（两种都算）。

| 预警 | 判定 | 路径（三元组数组，顺序照抄） |
|---|---|---|
| **禁忌证** `contraindication` | 患者 `-患有→` 疾病 `c`，且他的某味药 `d` 有 `d -禁忌证→ c` | `[[患者,"患有",c], [d,"禁忌证",c], [患者,"服用",d]]` |
| **相互作用** `interaction` | 患者同在用的两味药 `a`、`b` 之间有 `-相互作用→` 边（**两个方向都算**，因为相互作用是相互的） | `[[患者,"服用",a], [a,"相互作用",b], [患者,"服用",b]]`（若图里方向是 `b→a`，就把这两条对调成图里的实际方向） |

排序口径（结果必须可复现）：

- 禁忌证预警按 `(patient, drug)` 升序；
- 相互作用预警按 `(patient, drug, drug2)` 升序，其中 `drug` 与 `drug2` 按**字符串升序**取（即 `drug < drug2`）。

## 图更新口径（`updates.json`，**每条都要先过本体校验**）

本体校验：`relation_schema[relation]` 给出 `from` / `to` 两个类型；只有
`entity_types[head] == from` 且 `entity_types[tail] == to` 才算合法（未知实体或未知关系都算不合法）。

| 字段 | 语义 | 你要做的 |
|---|---|---|
| `add_triples` | 补录（新患者 + 患病 + 用药） | 过校验 → 加节点/边（**新节点也要计入 `added_nodes`**） |
| `remove_triples` | 撤销（如撤回一条医嘱） | 边存在则删除，计入 `removed_edges` |
| `replace_triples` | 更正错误关系（`old` → `new`） | 删旧边、加新边，计入 `updated_edges` |
| `invalid_triples` | **故意写错的更新** | 本体校验不通过 → **拒绝**，计入 `rejected_updates`，**不要**加进图 |

`crud` 里还要有更新后的 `final_n_nodes` / `final_n_edges`。

## 数据字典

| 文件 | 列 | 含义 |
|---|---|---|
| `triples.csv` | `head` / `relation` / `tail` | 三元组（`(头实体, 关系, 尾实体)`） |
| `ontology.json` | `entity_types` | 实体名 → 类型（`Drug` / `Disease` / `Symptom` / `Patient`） |
| | `relation_schema` | 关系名 → `{from, to}`（端点类型） |
| `updates.json` | — | 图更新单（见上表） |

关系一览：`禁忌证`（药→病）、`相互作用`（药→药）、`不良反应`（药→症状）、
`患有`（患者→病）、`服用` / `医嘱使用`（患者→药）、`过敏`（患者→药）。

> 数据是虚构的**教学用**知识整理（药物—疾病—症状关系按常识编排，患者数据由固定种子生成），
> 不是临床依据，不能用于任何真实用药决策。

## 交付格式

**`output.json`**（写在工作目录下；**键名与层级按下面的样例写**）：

```json
{
  "graph": {
    "n_nodes": 36, "n_edges": 60,
    "entity_types": { "Disease": 10, "Drug": 12, "Patient": 8, "Symptom": 6 },
    "relation_counts": { "不良反应": 7, "相互作用": 6, "患有": 30, "禁忌证": 6, "服用": 20 }
  },
  "crud": {
    "added_edges": 3, "added_nodes": 1, "removed_edges": 1, "updated_edges": 1,
    "rejected_updates": 1, "final_n_nodes": 37, "final_n_edges": 61
  },
  "alerts_before": {
    "contraindication": [
      { "patient": "P001", "drug": "二甲双胍", "reason": "contraindication", "with": "严重肾功能不全",
        "path": [["P001", "患有", "严重肾功能不全"], ["二甲双胍", "禁忌证", "严重肾功能不全"], ["P001", "服用", "二甲双胍"]] }
    ],
    "interaction": [
      { "patient": "P005", "drug": "华法林", "drug2": "阿司匹林", "reason": "interaction",
        "path": [["P005", "服用", "华法林"], ["华法林", "相互作用", "阿司匹林"], ["P005", "服用", "阿司匹林"]] }
    ]
  },
  "alerts_after": { "contraindication": [], "interaction": [] },
  "figures": [
    { "path": "figures/alert_counts.png", "takeaway": "更新前禁忌证预警 5 条、相互作用 5 条；撤销一条医嘱、补录一位患者后变成 4 条与 6 条。" }
  ],
  "notes": "图里有 36 个实体、60 条关系……两类预警都是两跳查询，每条预警都能给出完整的三元组路径……"
}
```

- `alerts_before` 是**更新前**的图上的预警，`alerts_after` 是**更新后**的；
- 每条预警必须带 `path`（三元组数组）；
- 图至少 1 张：`path` + 一句 `takeaway`（要"看图说话"，并与你自己报的数字自洽）。

## 怎么算完成

1. 写一个能跑的方案（推荐做成 Skill 里的一段脚本），能对任意一份同结构的三元组 + 本体 + 更新单
   产出 `output.json` 与一张图。
2. 在 `cases/case01` 与 `cases/case02`（两批不同规模的数据）上都能跑通 —— 判据对两个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。
