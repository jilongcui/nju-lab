# 用药安全预警 Skill（参考实现 · 学习示范）

> 📖 这份实现**随题目包一起下发**（`problem/reference/`），是给你的**示范** —— 不是标准答案。
> 判据只看"图与预警口径一致 + 更新（含被拒绝的）真的落到图上 + 说清可解释性与局限"，所以
> 用 `networkx` 还是自写邻接表、代码怎么分层都随你。

## 能力边界

- 能处理：`triples.csv` / `ontology.json` / `updates.json` 这套固定结构的输入
- 能处理：三元组建图、两跳预警（禁忌证 / 相互作用）并给出**完整推理路径**
- 能处理：按本体（关系端点类型）校验的增删改（补录 / 撤销 / 更正 / 拒绝非法更新）
- 能处理：更新前后各跑一次预警，用数字说明变化
- 不处理：`过敏` 关系的预警规则、剂量 / 用药时间窗 / 循证等级（真实临床审查还要这些）
- 不处理：通用图查询语言（这里是直接用 Python 遍历；真实系统会用 Cypher / SPARQL）
- 不处理：本体推理（不做事例推理、不补全隐含关系）—— 只做显式边的多跳查询

## 方法（六步 —— 与 `task.md` 的流程一致）

1. **看清需求** —— 要答的是关系问题，且要能说清"为什么有风险"
2. **回头看本体** —— `ontology.json`：实体类型 + 每种关系的端点类型（校验依据）
3. **建图** —— `build_graph`：三元组 → 有向图；`graph_stats` 出统计
4. **多跳预警** —— `find_contraindication_alerts`（在同一个疾病上碰头）/ `find_interaction_alerts`
5. **图更新** —— `apply_updates`：每条先过 `is_valid_triple`，不合格的拒绝并计数
6. **再看一次 + 结论** —— `all_alerts` 重跑 + 对比图 + `notes`（可解释性、本体的作用、局限）

产出结构（`output.json`）见 `task.md`；判据见 `judge.md`。

## 实测档案

- 自测时间：
- 用例通过率：/2
- 关键数字：
  - case01（8 位患者 / 36 节点 / 60 条边）：禁忌证预警 **5 → 4**（撤销一条医嘱），相互作用 **5 → 6**（补录一位带冲突用药的患者）
  - case02（12 位患者 / 38 节点 / 78 条边）：禁忌证预警 **13 → 12**，相互作用 **9 → 9**（补录带来一条、更正消掉一条）
  - 两个 case 都有 1 条更新被**本体校验拒绝**（往"药物→疾病"的关系上塞了患者节点）
- 踩坑记录（pitfalls）：
  - "在用药"要同时认 `服用` 与 `医嘱使用` 两种关系名，只认一种会漏预警
  - 相互作用是**相互**的：只查一个方向会漏掉一半；路径要按**图里实际存在的方向**写
  - 本体校验必须比**端点类型**（`from`/`to`），只检查"关系名存在"会放非法更新进来
  - 更新之后必须**重跑**预警查询：拿着更新前的对象算，`alerts_after` 会与 `alerts_before` 一模一样
