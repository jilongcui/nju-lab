评分细则（**应用任务：建图 + 多跳预警 + 图更新**）

⚠️ 本体校验、预警判定、路径三元组顺序、排序口径都已在 `task.md` 里钉死，所以结果是**确定的**。
这些数值（图统计、更新条数与被拒绝数、更新前后两类预警及其路径）已由平台用**确定性断言**判定
（见 `manifest.json` 的 `assertions`）。断言未通过的结果**不会交给你判**，你不必重算这些数字。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否讲清了"为什么要用图"**：要说出多跳/关系的意义 —— 禁忌证预警是
   「患者—患有—疾病」与「药物—禁忌证—疾病」在**同一个疾病上碰头**；相互作用预警是在
   "患者在用的两味药"之间找边；并且**每条结论都能给出可展示的推理路径**（医生要的是"为什么"）。
   不通过的情形：只复述题目、只说"知识图谱很好用"、把预警规则说错
   （例如声称要遍历整张图或做了"推理机"）。
2. **`notes` 是否讲清了本体校验的作用**：被拒绝的那条更新**错在哪**（往"药物→疾病"的关系上塞了患者节点），
   以及本体在这里扮演什么角色（相当于关系数据库的 Schema）。
   把"被拒绝"说成"程序报错/数据缺失"、或完全没提这件事 → 不通过。
3. **是否说清更新后的变化与局限**：撤销医嘱让哪类预警减少了、补录的患者带来了什么；
   并给出至少一条真实局限（本体覆盖有限、未纳入过敏/剂量/时间窗、图谱给的是可能性不是结论）。
   只说"更新成功"、或声称图谱能替代临床判断 → 不通过。
4. **`figures[].takeaway` 是否"看图说话"且与 `alerts_*` 自洽**：图里的两组数字必须与报告里的
   预警条数一致；只写"我画了对比图"、数字对不上 → 不通过。

判定口径：
- 键序、缩进、空白、额外字段不扣分；路径的三元组顺序与口径一致才判过（**由断言负责，你不必复核**）。
- 结论里的**整数**要与报告里的预警条数一致；精确数值与路径由断言核对，你不要以此判不通过。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
