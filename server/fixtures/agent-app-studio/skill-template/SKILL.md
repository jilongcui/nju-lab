# 可分享的智能体应用（你的方案 · 第 20 章 · 收官）

> 第 19 章你写的是 harness 的六件；这一章要把它们**装进一个应用**：附件能上传、报告能复核、
> 前端能改、发出去能给别人用。**本实验不给参考实现** —— 给的是需求、数据、模板与交付契约。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：六步流程、附件解析 / 报告 / 记忆 / 前端分享的口径、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `cases/case01`、`cases/case02` | 两套输入（请求 + 三类附件 + 模板 + 知识库）+ `expected.json` |

**实验流程（六步，与 `task.md` 一致）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 谁会用、给什么、要拿到什么 | 心里有数（写进 `notes`） |
| ② 摸清材料 | 三种附件各是怎么存的、报告模板给了什么 | 心里有数 |
| ③ **搭 core + 改前端** | 解析 → 报告 → 记忆 → 安全；前端换主题加区块 | `harness/api.py` / `web/` |
| ④ **逐轮核对** | trace / 指标表 / flag / 四节 / 出处 | `output.json` |
| ⑤ 边界与分享自测 | 截断轮、忘掉偏好后的行集、拒答、`web_sha256` | `report` / `safety` / `app` |
| ⑥ 写结论 | 为什么自己解附件、记忆改变了什么、局限 | `notes` |

## 能力边界

> 这一节是技能说明书的一部分（什么时候该用、不该用我）；**平台不检查这一节**。

- 能处理：本实验约定形态的附件（未压缩文本流的 PDF、标准 DOCX、PNG）与
  `report_format.json` 那套报告模板
- **不处理**：真实世界里带压缩流 / CJK 字体的 PDF、扫描件 OCR、图片内容识别、
  复杂表格版面分析
- **不承担**：诊断结论。超出参考区间的行只升级、诊断式提问只拒答
- 已知失效情形：PDF 里文本用 `TJ` 数组或压缩流时抽不到；DOCX 的表格（`w:tbl`）不在本实验口径里；
  偏好记忆只有"只列异常"这一条，换别的偏好要自己加

## 要做的决策（本实验的重点）

1. **附件为什么必须解析成结构化行**：把 PDF 的文本原样塞进报告，和"每行都能对上 item/value/flag"，
   哪一种能被医生复核？差别在哪？
2. **偏好记忆改变了什么**：`报告只列异常指标` 生效时，`listed` 与 `total` 的关系是什么？
   忘掉之后又变回什么？这算不算"记忆真的有用"？
3. **前端要改到什么程度**：模板能用，但它是老师的。你的应用要改主题（背景/配色）、
   加一个对科室有用的区块（例如"异常项置顶"或"导出 JSON"）。
4. **分享与可见性**：先给谁看？`teacher` 还是 `course`？被下架意味着什么？

## 交付

`output.json`（字段见 `task.md` 的「交付格式」）+ 一张图 + **改过的 `web/`** + 填好的 `app.json`。
