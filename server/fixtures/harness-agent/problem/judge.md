评分细则（**给随访助手写一个 harness —— 循环 / 记忆分层 / 工具 / 知识库**）

⚠️ 本章是**迁移检验**型任务：学生只拿到需求与交付契约，**没有参考实现**。
可机器判定的部分（`trace` 逐步、工具调用的校验结论与错误码与 mock 摘要、记忆三层与更新/遗忘、
检索 top3 与对照轮次、越界升级与拒答、`metrics`）已在 `task.md` 里钉死，
由平台用**确定性断言**判定（见 `manifest.json` 的 `assertions`）。断言未通过的结果**不会交给你判**，
你不必重算这些值。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否说清每个部件"为什么这么做"**：循环 —— 为什么每步都要记 `observation`
   （不记的话出错时定位不到是哪一步偏了）、为什么 `max_steps` 是硬边界；
   记忆 —— 为什么分三层、`superseded` / `forgotten` 两种状态不用会出什么事；
   工具 —— 为什么先校验再执行、为什么失败也要如实记 `rejected`；
   检索 —— 为什么不能直接拿余弦/最长文档当第一名。
   只写"我都实现了""六件事齐了"这类空话，或只是复述题干 → 不通过。
2. **有没有把"检索第一名"当"结论"**：`bm25_top3[0]` 只是**可能相关**的段落，
   `citations` 只说明出处。如果 `notes` 或 `answer` 里出现"所以这个病人是感染/贫血"这类
   **越界的诊断式断言**，即使字段都填对了 → 不通过。
3. **安全边界是否被真正理解**：要能说清"越界读数为什么只升级不解释"（可能测错、需要人工复核、
   助手不承担判断责任）与"为什么拒答诊断式提问"（诊断必须由医师结合完整病史与检查作出）。
   把这两处说成"模板要求/格式要求"、或照抄固定话术而没有理由 → 不通过。
4. **有没有正视局限**：至少给出**两条**真实局限，例如：`plan_stub.json` 是**模型桩**
   （不是真 LLM，换成真实模型后步数会长很多）；工具是**本地 mock**，不是真正的 MCP 服务；
   检索只做**字面 2-gram 匹配**，换个说法就排不到前面；记忆是**本地条目表**，
   没有语义去重、也没有跨会话持久化；`max_steps` 到点就停，所以长任务会被硬切。
   只复述题干、只堆字段名、把 `notes` 写成运行日志 → 不通过。

判定口径：
- 键序、缩进、空白、措辞差异不扣分。数值与名单**由断言负责**，你不必复核；
  你只管「理由是否说清」与「有没有越界」。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
