# 随访助手 harness（你的方案 · 第 19 章）

> **本实验不给参考实现**（前几章的包里多有 `reference/`，这一章没有）。
> 给你的是**需求 + 数据 + 交付契约**，要你把学过的本事**自己组装**起来：
> 循环与状态（本章）、记忆四操作（第 16 章）、MCP 报文与参数校验（第 17 章）、
> 检索与对照（第 5 章）、安全边界落成字段（第 18 章）。
>
> 六件事**必须真的发生**（不是加分项）：① 循环 + 每步观测 ② 记忆三层 + 更新/遗忘
> ③ 工具四级校验 + 业务校验 ④ BM25 与对照 top3 ⑤ 越界升级 + 拒答 ⑥ 答案带出处。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：六步流程、六个部件的口径、数据字典、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `cases/case01`、`cases/case02` | 两套输入（七份材料）+ `expected.json`（自测用） |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 六个部件各解决什么问题、难在哪 | 心里有数（写进 `notes`） |
| ② 摸清材料 | 七份材料怎么对上（对话 / 记录 / 名册 / 调用 / 决策 / 限额 / 知识库） | 心里有数 |
| ③ **搭六个部件** | 检索、记忆、工具校验、循环、安全、答案拼装 —— 一段一个函数 | 代码 |
| ④ **逐轮核对** | 每轮 trace 步数 / 记忆应用 / 工具结论 / 出处 | `output.json` |
| ⑤ 边界自测 | 被截断的那一轮、被遗忘的条目、对正常读数要求升级、要求下诊断的提问 | `harness` / `memory` / `safety` |
| ⑥ 写结论 | 每个部件为什么这么做、BM25 与对照差在哪、至少两条局限 | `notes` |

## 能力边界

> 这一节是技能说明书的一部分（什么时候该用、什么时候不该用我）；**平台不检查这一节**。
> —— 这一节与 `description` 里的"不适用场景"是同一件事的两种写法。

- 能处理：`dialogue.jsonl` + `records.csv` + `tools.json` + `tool_calls.jsonl` +
  `plan_stub.json` + `limits.json` + `kb/*.md` 这套结构的输入
- **不处理**：真实 MCP 服务（这里是本地 mock 工具）、真实大模型（`plan_stub.json` 是模型桩）、
  语义检索与向量化（这里只做字符 2-gram）、跨会话持久化（记忆只活在这一次运行里）
- **不承担**：诊断结论。越界读数只升级、诊断式提问只拒答 —— 判断必须由临床医生作出
- 已知失效情形：换一套指标名/阈值就会失效（阈值来自 `limits.json`）；
  决策序列里出现未声明工具名会直接记 `unknown_tool`；`max_steps` 一到就硬停，长任务会被截断

## 要做的决策（本实验的重点）

1. **observation 记什么**：只记"成功/失败"够不够？为什么非法调用也要把 `rejected_reason` 记进 trace？
2. **三层记忆各自的代价**：working 省 token 但会忘、short 省地方但丢细节、long 要维护状态。
   你打算把"什么时候写、什么时候用、什么时候忘"定在哪？
3. **错误码为什么要分**：`-32601` 与 `-32602` 对调用方意味着什么？全都报一个码会怎样？
4. **对照的意义**：余弦排出来的第一名为什么是长综述？这说明"看起来更相关"可能只是"更长"。
5. **升级与拒答的边界**：什么情况下必须把判断交回给人？助手凭什么不做结论？
