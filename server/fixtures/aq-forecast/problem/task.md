# 应用任务：估算下一小时的 PM2.5

## 业务背景

你是某市环境监测中心的数据分析同学。值班人员需要一个"**提前一小时**"的 PM2.5 估算，
用来提前给敏感人群（老人、儿童、呼吸道疾病患者）发提示。

**现有做法**：直接把本站**上一小时的实测值**当作下一小时的估算（业界叫"持久性"基线，
persistence baseline）。它简单、不需要模型 —— 所以你的任务不是"跑个模型"，而是
**比这个现有做法明显更好地解决问题**。

## 你的任务

用工作目录里的 `data.csv` 构建一个估算方案，产出 `output.json`，达到三条要求：

1. **比现有做法明显更好**：在测试集上，平均绝对误差（MAE）**至少比持久性基线低 20%**。
2. **可复现**：切分与训练用固定随机种子；产出里写清 `n_train` / `n_test`
   （测试集占比 **20%~40%**，怎么切由你决定）。
3. **说清你的选择**：用了哪些特征、为什么选这个模型 —— 这决定了别人能不能信任、复用你的方案。

> 模型、超参、特征组合都由**你自己决定**。不存在"唯一正确答案"，
> 达标与否看上面三条是否真的做到（判据见 `judge.md`）。

## 数据字典（`data.csv`）

每行是一个"时刻"的观测；目标是**该时刻的下一小时**浓度。

| 列 | 含义 |
|---|---|
| `temp` | 气温 ℃ |
| `humidity` | 相对湿度 % |
| `wind_speed` | 风速 m/s |
| `pm25_lag1` | 本监测点**上一小时**的 PM2.5（µg/m³） |
| `pm25_neighbor` | 周边站点**当前**的 PM2.5 均值（µg/m³） |
| `hour` | 当前小时（0-23） |
| `pm25_next` | **目标**：下一小时的 PM2.5（µg/m³） |

> 数据是固定种子合成的教学数据，但规律"讲道理"：本点上小时浓度是主因，
> 周边站点反映区域输送，风速反映扩散条件，湿度偏高时二次生成会更活跃。

## 交付格式（`output.json`，写在工作目录下）

```json
{
  "model": "你选择的模型名称（例如 Ridge / RandomForest / 梯度提升…）",
  "n_train": 450,
  "n_test": 150,
  "metrics": { "mae": 3.9, "r2": 0.86 },
  "baseline": { "name": "persistence", "mae": 6.1 },
  "notes": "用了 pm25_lag1 + pm25_neighbor + wind_speed：邻居站反映区域输送、风速反映扩散条件，所以明显优于只看上一小时。"
}
```

- `metrics` 至少要有 `mae`（`r2` 可选，推荐给）。
- `baseline.mae` 必须是你**自己算出来的**持久性基线 MAE：把 `pm25_lag1` 直接当作预测值，
  在**同一个测试集**上算 MAE。（判据会核对它是否可信。）
- 不需要和任何"标准答案"的数值一致 —— 达标看的是"是否真的比基线好 20%"。

## 怎么算完成

1. 写一个能跑的方案（推荐做成 Skill 里的一段脚本），能对任意一份同结构 `data.csv` 产出 `output.json`。
2. 在 `cases/case01` 与 `cases/case02`（两批不同季节的数据）上都达标 —— 判据对两个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
