# 应用任务：估算下一小时的 PM2.5

## 业务背景

你是某市环境监测中心的数据分析同学。值班人员需要一个"**提前一小时**"的 PM2.5 估算，
用来提前给敏感人群（老人、儿童、呼吸道疾病患者）发提示。

**现有做法**：直接把本站**上一小时的实测值**当作下一小时的估算（业界叫"持久性"基线，
persistence baseline）。它简单、不需要模型 —— 所以你的任务不是"跑个模型"，而是
**比这个现有做法明显更好地解决问题**。

## 你的任务

用工作目录里的 `data.csv` 构建一个估算方案，产出 `output.json` 与你的图，达到三条要求：

1. **比现有做法明显更好**：在测试集上，平均绝对误差（MAE）**至少比持久性基线低 20%**。
2. **可复现**：切分与训练用固定随机种子；产出里写清 `n_train` / `n_test`
   （测试集占比 **20%~40%**，怎么切由你决定）。
3. **用图把分析讲清楚**：看数据时画图、评估结果时画图，并**给每张图写一句结论**
   （写进 `output.json` 的 `figures` 字段）。看图说话，比堆数字更能说明你理解这份数据。

> 模型、特征、超参都由**你自己决定**（选一个你能讲清楚的即可，不必做多个方案的对比）。
> 达标与否看上面三条是否真的做到（判据见 `judge.md`）。

## 实验流程（六步，每一步都要走完）

这是一个**完整的小分析任务**。按下面六步走，②和⑤都要产图：

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 解决什么问题、什么算成功（比现有做法好 20%） | 心里有数 |
| ② **看一眼数据 + 画图** | 多少行、每列什么含义、范围与分布；**画一张总览图**（目标怎么分布？哪列和它最相关？有没有异常） | `figures/` 里第 1 张图 |
| ③ **定基线** | 不做模型能做到多少（沿用上一小时） | 报告的 `baseline` |
| ④ **训练模型** | 选一个模型、固定种子切分后训练 | 报告的 `model` / `metrics` |
| ⑤ **评估 + 画图** | 算 MAE / R²，并**画一张评估图**（预测 vs 实际、或误差怎么分布） | `figures/` 里第 2 张图 |
| ⑥ **写结论** | 每张图一句结论（`figures[].takeaway`）+ 整体判断（`notes`：好在哪里、哪类样本误差大） | 报告的 `figures` / `notes` |

> ② 和 ⑤ 的图都用 `matplotlib` 画（镜像已预装），存到工作目录的 `figures/` 下，
> 例如 `plt.savefig("figures/data_overview.png", dpi=110)`。**图是给你自己看的** ——
> 但请把"从图里看到了什么"写进 `takeaway`，否则没人知道你看了。
>
> ⚠️ 图里的**标题与坐标轴标签建议用英文**（如 `Distribution of pm25_next`）：运行环境里没有中文字体，
> 中文会渲染成方框。中文解释写在 `takeaway` 和 `notes` 里（那些是给人读的）。

## 数据字典（`data.csv`）

每行是一个"时刻"的观测；目标是**该时刻的下一小时**浓度。

| 列 | 含义 |
|---|---|
| `temp` | 气温 ℃ |
| `humidity` | 相对湿度 % |
| `wind_speed` | 风速 m/s |
| `pm25_lag1` | 本监测点**上一小时**的 PM2.5（µg/m³） |
| `pm25_neighbor` | 周边站点**当前**的 PM2.5 均值（µg/m³） |
| `hour` | 当前小时（0-23） |
| `pm25_next` | **目标**：下一小时的 PM2.5（µg/m³） |

> 数据是固定种子合成的教学数据，但规律符合常识：**上一小时的浓度**是最主要的参考
> （空气不会突然变化），**附近监测站的读数**也有参考价值；此外**风大时污染物容易被吹散**
> （浓度更低），**湿度高时浓度往往略高**。

## 交付格式

**`output.json`**（写在工作目录下）：

```json
{
  "model": "你最终选择的模型名称（例如 Ridge / RandomForest / 梯度提升…）",
  "n_train": 450,
  "n_test": 150,
  "metrics": { "mae": 3.9, "r2": 0.86 },
  "baseline": { "name": "persistence", "mae": 6.1 },
  "figures": [
    { "path": "figures/data_overview.png", "takeaway": "上一小时浓度与下一小时高度正相关；目标分布右偏，少数高污染时刻拉长了尾巴。" },
    { "path": "figures/evaluation.png", "takeaway": "预测点大致贴合 y=x；浓度越高越容易低估，说明模型对极端值偏保守。" }
  ],
  "notes": "先画了分布与散点图，确认 pm25_lag1 是主因、各列量纲差别不小；用全特征 Ridge(alpha=1.0)，测试集 MAE 3.9，比持久性基线（6.1）低约 36%。不足：高浓度时刻误差更大。"
}
```

- `metrics` 至少要有 `mae`（`r2` 可选，推荐给）。
- `baseline.mae` 必须是你**自己算出来的**持久性基线 MAE：把 `pm25_lag1` 直接当作预测值，
  在**同一个测试集**上算 MAE。（判据会核对它是否可信。）
- `figures` 至少两张：一张"看数据"（②）、一张"评估结果"（⑤），每张都要有 `path` 与一句 `takeaway`。
- 不需要和任何"标准答案"的数值一致 —— 达标看的是"是否真的比基线好 20%"。

## 怎么算完成

1. 写一个能跑的方案（推荐做成 Skill 里的一段脚本），能对任意一份同结构 `data.csv`
   产出 `output.json` 与两张图。
2. 在 `cases/case01` 与 `cases/case02`（两批不同季节的数据）上都达标 —— 判据对两个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
