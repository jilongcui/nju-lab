# 题目包：估算下一小时的 PM2.5（回归应用）

> 这是本实验的**题目包** —— 一个真实需求（提前一小时估算 PM2.5）、判据、两批数据，
> 外加**一份示范实现**（`reference/`）供你对照学习。

## 这个实验要学什么

1. **从需求出发做选择**：先看清业务目标（"比现有做法明显更好"），再决定用什么模型、哪些特征 ——
   而不是拿到一个模型名字往数据上套。
2. **基线（baseline）意识**："我的模型好不好"必须有参照物。本实验的参照物是
   **持久性基线**（直接把上一小时的值当预测），这是这个行业里真实存在的做法。
3. **比较**：只报一个模型"结果还不错"说服不了人 —— 至少要试两个方案并给出各自成绩。
4. **指标要能对业务说话**：为什么用 MAE（平均差多少 µg/m³）而不是 R²（方差解释比例）。
5. **可复现**：固定随机种子、写清切分，别人才能复核你的结论。

## 实验流程（六步）

`task.md` 里写了完整流程（① 看清需求 → ② 看一眼数据 → ③ 定基线 → ④ 建模并比较 → ⑤ 评估 →
⑥ 写结论），`reference/scripts/train.py` 是一份**把这六步都走完**的示范 —— 照着走一遍，
再换成你自己的做法。

## 包内有什么、怎么用

| 路径 | 是什么 | 建议怎么用 |
|---|---|---|
| `task.md` | 需求 + 三条要求 + 数据字典 + 交付格式 | **动手前先读** |
| `judge.md` | 判据：达标线、会被核对的项（含防伪核对） | 交之前读一遍 |
| `reference/` | **示范实现**（Ridge + 全特征 + 基线对比） | 先读 `scripts/train.py`，再写自己的 |
| `cases/case01`、`case02` | 两批数据（不同季节）+ 参考水平 `expected.json` | 自测用 |

## 两批数据

| case | 规模 | 特点 | 参考水平（持久性基线 → 参考实现） |
|---|---|---|---|
| case01 | 600 行 | 常规季节 | MAE 6.07 → 3.56 |
| case02 | 420 行 | 冬季重污染（浓度整体更高、波动更大） | MAE 7.94 → 4.75 |

> `expected.json` 里的数值**不是标准答案**，而是"参考水平"：判据用它核对你的
> `baseline.mae` 是否可信、并识别"可疑地过于好"的结果（例如拿测试集反复调参）。
> 你可以做得比参考实现更好，只要说清是怎么做到的。

## 自测方法

CLI 约定：`train.py <case_dir> <output.json>`（`<case_dir>` 里要有 `data.csv`）。

```sh
# 两个 case 都跑一遍，看是否达标（比值 = metrics.mae / baseline.mae，要求 ≤ 0.80）
for c in cases/*/; do python3 <你的skill>/scripts/train.py "$c" /tmp/out.json; done
```

脚本末尾会打印 `[达标] / [未达标]` 与比值。判据的其余各项（结构、切分占比、`notes`）
请对照 `judge.md` 自己核一遍。

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段。
