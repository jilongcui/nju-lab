# 空气质量估算 Skill（你的方案）

> **本实验是应用任务，不是"按口径写代码"**：给你一个真实需求（提前一小时估算 PM2.5），
> **模型、特征、切分方式都由你自己决定**。没有唯一答案 —— 达标看的是
> "**是否真的比现有做法好 20%** + 能不能说清你的选择"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | 业务背景 + 三条要求 + 数据字典 + 交付格式 |
| `judge.md` | 判据：达标线怎么算、哪些项会被核对 |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案） |
| `cases/case01`、`cases/case02` | 两批不同季节的数据，自测用 |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 解决什么问题、什么算成功（比现有做法好 20%） | 心里有数 |
| ② 看一眼数据 | 行数、列含义、范围/量纲/相关性、有无异常 | 自己跑几行 `pandas` |
| ③ 定基线 | 不做模型能做到多少（沿用上一小时） | 报告的 `baseline` |
| ④ **建模并比较** | **至少两个方案**，记录各自测试集成绩 | 报告的 `notes` |
| ⑤ 评估 | 用业务上说得清的指标（MAE），看误差在哪类样本上 | 报告的 `metrics` |
| ⑥ 写结论 | 最终选哪个、为什么、还有什么不足 | 报告的 `notes` |

材料配合：`task.md`（需求 + 流程）→ 读 `reference/`（一份**走完这六步**的示范，含它比较过的方案与
各自成绩）→ 回 `scripts/train.py` 走自己的六步 → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **特征**：为什么选这几列？数据字典里每一列都可能有用，也可能没用 —— 说说你的判断依据。
2. **模型**：为什么是它？线性模型可解释、树模型能拟合非线性 —— 在什么条件下你会换？
3. **基线**：现有做法（持久性基线）是什么？怎么在**同一个测试集**上算它的成绩？
4. **评估**：为什么用 MAE？它和 R² 分别告诉值班人员什么？（业务上"平均差多少 µg/m³"更好沟通）

## 交付

按 `task.md` 的「交付格式」产出 `output.json`：
`model` / `n_train` / `n_test` / `metrics{mae[,r2]}` / `baseline{name,mae}` / `notes`。

## 自测

两个 case 都要跑，并自己算一下是否达标（比值 = `metrics.mae / baseline.mae`，要求 ≤ 0.80）：

```sh
for c in cases/*/; do
  python3 scripts/train.py "$c" /tmp/out.json
done
```

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段，再回来改自己的实现。
