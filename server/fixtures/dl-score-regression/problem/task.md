# 入门实验：按练习情况估算期末成绩（回归 · 神经网络）

## 业务背景

你是辅导班的教学助理。期末前，老师想知道每个学生大概能考多少分，好提前给需要补课的人排辅导。
手上有两条记录：**每周练习时长**和**出勤率**。

老师的老办法是"**不看人，一律报班里的平均分**"—— 简单，但对练得多的学生估低、
对练得少的学生估高，用处有限。你的任务是做一个**按人估算**的小模型，比这个老办法准得多。

这条关系不是直线：**练得越多分数越高，但收益递减**（练到一定程度，再练也提不了几分）。
所以这是理解"为什么需要会拐弯的模型（神经网络）"的好例子。

**现有做法（基线）**：一律报训练集的平均分。

## 你的任务

用工作目录里的 `data.csv` 训练一个小神经网络，产出 `output.json` 和你的图，达到三条要求：

1. **比现有做法明显更准**：在测试集上，平均绝对误差（MAE）**至少比"一律报平均分"低 45%**。
2. **可复现、可核对**：固定随机种子；写清 `n_train` / `n_test`（测试集占比 **20%~40%**）；
   把**逐轮训练损失**记进 `training.history`（至少 5 轮，且最后一轮的损失要低于第一轮）。
3. **用图讲清楚**：看数据画一张、训练与评估各画一张，并给每张图写一句结论（`figures[].takeaway`）。

> 这是**入门实验**：两个特征、一层隐藏层就够。网络结构、优化器、轮数都由**你自己决定**，
> 选一个你能讲清楚的即可。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 按人估算、比"一律报平均分"准 45%；并且真的训练了 | 心里有数 |
| ② **看一眼数据 + 画图** | 练习时长/出勤率与成绩是什么关系？**是不是一条直线？** 画散点图 | `figures/` 里第 1 张图 |
| ③ **定基线** | 不建模能做到多少（一律报训练集平均分） | 报告的 `baseline` |
| ④ **训练模型** | 搭一个小网络，**逐轮记录训练损失** | 报告的 `training.history` |
| ⑤ **评估 + 画图** | 算 MAE / R²，画训练曲线与预测 vs 实际 | `figures/` 里第 2、3 张图 |
| ⑥ **写结论** | 每张图一句结论（`figures[].takeaway`）+ 整体判断（`notes`：损失怎么变、误差在哪儿大） | 报告的 `figures` / `notes` |

> 图用 `matplotlib` 画（镜像已预装），存到工作目录的 `figures/` 下，
> 例如 `plt.savefig("figures/training_curve.png", dpi=110)`。
>
> ⚠️ 图里的**标题与坐标轴标签用英文**（如 `weekly practice hours`）：运行环境里没有中文字体，
> 中文会渲染成方框。中文解释写在 `takeaway` 和 `notes` 里（那些是给人读的）。

## 数据字典（`data.csv`）

| 列 | 含义 |
|---|---|
| `weekly_hours` | 每周练习时长（小时） |
| `attendance_rate` | 出勤率（0.5~1.0） |
| `final_score` | **目标**：期末成绩（0~100 分） |

> 数据是固定种子合成的教学数据，规律符合常识：**练习时长和出勤率都正向影响成绩**，
> 但练习的**边际收益递减**（0→10 小时涨得最快，20 小时以后再练基本到顶）。
> 成绩接近满分时会"压线"（最高 100 分），这也是模型估高分段时的难点。

## 交付格式

**`output.json`**（写在工作目录下）：

```json
{
  "model": "你最终选择的网络（例如 MLP(2→16→1, ReLU, Adam)）",
  "n_train": 180,
  "n_test": 60,
  "metrics": { "mae": 3.2, "r2": 0.95 },
  "baseline": { "name": "mean_score", "mae": 9.8 },
  "training": {
    "epochs": 200,
    "optimizer": "Adam(lr=0.05)",
    "loss": "MSELoss",
    "history": [
      { "epoch": 1, "train_loss": 0.81 },
      { "epoch": 2, "train_loss": 0.44 },
      { "epoch": 3, "train_loss": 0.31 }
    ]
  },
  "figures": [
    { "path": "figures/data_overview.png", "takeaway": "成绩随练习时长上升但明显是弯的：前 10 小时涨得最快，20 小时以后基本平了。" },
    { "path": "figures/training_curve.png", "takeaway": "训练损失从 0.81 降到 0.10，前 20 轮降得最快，之后基本平了。" },
    { "path": "figures/evaluation.png", "takeaway": "预测点贴着 y=x；残差以 0 为中心，高分段（接近满分）误差略大。" }
  ],
  "notes": "先看散点确认练习时长与成绩是饱和曲线、直线会系统性偏差，所以用一层隐藏层的小网络（2→16→1）：训练 200 轮，损失从 0.81 降到 0.10。测试集 MAE 3.2、R² 0.95，比「一律报平均分」的基线（9.8）低约 67%。不足：只用了两个因素，高分段样本少、误差偏大。"
}
```

- `metrics` 至少要有 `mae`（`r2` 可选，推荐给）。
- `baseline.mae` 必须是**你自己算出来的**：把"训练集的平均分"当作对所有人的预测，
  在**同一个测试集**上算 MAE。
- `training.history` 至少 5 个元素，每个元素含 `epoch` 与 `train_loss`；**最后一轮损失 < 第一轮**
  （判据会核对 —— 这是"真的训练了"的证据）。
- `figures` 至少两张（推荐三张：看数据 / 训练曲线 / 预测-实际），每张都要有 `path` 与一句 `takeaway`。

## 怎么算完成

1. 写一个能跑的训练脚本（推荐做成 Skill 里的一段脚本），能对任意一份同结构 `data.csv`
   产出 `output.json` 与图。
2. 在 `cases/case01` 与 `cases/case02`（另一个班、噪声更大）上都达标 —— 判据对两个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
