# 实验：做一件你自己真正想做的事

前 18 章你跟着做，第 19 章给你场景、你自己搭。这一章**连场景都归你选**。

## 题目

找一件**你自己、或者你身边的人，真的会反复问、反复查**的事，做一个**能对话的东西**来接手它。

要求只有三条：

1. **有人真的会用**（哪怕只有你一个人用）；
2. 它给的东西**能被核对** —— 不是"多喝水、注意休息"这种说了等于没说的话；
3. 你**讲得清**它为什么这么做、哪里做不到。

场景不限，比如：实验记录整理、值班交接问答、文献速查、科室流程提醒、自己的学习资料问答……
数据自己准备（脱敏的、公开的、自己造的都行），**来源要在说明里写清**。

## 你要交什么

**一个能对话的应用**：打开就能问，它来答。

要装到平台上跑，包里必须有入口和它需要的数据：

| 要什么 | 具体 |
|---|---|
| 入口 | **`scripts/api.py`**，实现 `def handle(state, message, attachments, session) -> dict`（返回 `{"reply", "citations"}` 即可） |
| 数据 | 你自己准备的材料，放在包的根目录（`data/` 或直接摊在根都行） |

**这是 Skill，不是 agent。** 循环、会话、附件解析、模型代理这些**平台已经给你了**；
你写的是"拿到一条消息之后，怎么处理它"。

- 上一章你从零搭过一个 agent，知道那层有多麻烦；这一章不用再搭一遍，直接用平台的。
- 想要附件解析：`attachments` 里已经有 `text` / `rows`（PDF / Word / 图片都被解析过）；
- 想调模型：`import platform_core` 然后 `platform_core.call_llm(messages)`（容器里没有 key，走平台代理）；
- 想知道平台把哪些东西塞进了 `state` / `session`：读 `platform_core.py` 的文档字符串。

**至于做什么、数据从哪来、怎么答 —— 全部由你决定。**

## 怎么评

| 项 | 占分 | 看什么 |
|---|---|---|
| 需求 | 20 | 这件事是不是真的有人要问、你做的范围是否说得清 |
| 代码 | 40 | 能不能跑起来、结构说得清不清、做法是否解决了你要解决的问题 |
| 演示 | 40 | 现场跑一遍；讲清为什么这么做、试过什么、还有什么没做到 |

没有自动判分，也不会拿你的东西去和别的同学比。

## 一条底线

涉及**人身安全、诊断结论、用药决定**的判断，不许远程下结论 —— 该拒答就拒答，
并把话题引回你能给的东西（数据、出处、规则条款）。这条在演示时会被问到。
