# 应用实践：用你的 Agent 做一个真实应用（两选一）

## 你已经有什么

- **第 19 章的 agent**：循环、记忆、工具、知识库、安全边界（你在那一章自己写了一遍，知道它内部怎么转）；
- **平台提供**：附件解析（PDF / Word / 图片走视觉）、托管运行、分享链接、教师管理。

所以这一章不再教你"怎么搭 agent"，也不规定数据 —— **你自己选一个真实需求，把它做成能用的应用**。

## 这一章做什么

从下面**两个需求里选一个**（也可以和老师商量换一个相近的），然后：

1. **自己准备数据**（能公开的、脱敏的、或者自己造的都可以，但要在报告里说清来源）；
2. **自己决定产出形态**（报告 / 表格 / 提醒清单 / 图表都行 —— 关键是**能复核**）；
3. 写成 **Skill**（`SKILL.md` + `scripts/api.py` 的 `handle()` + 可选的 `profile.json`）；
4. 上传这个 Skill —— **它本身就是一个应用**（平台把它装到 agent 上，给你分享链接）。

> 我们不提供固定答案：同一个需求，做出来的东西可以很不一样。评分看的是"需求有没有被真正满足"。

---

## 需求 A：实验数据 → 标准格式实验报告

**背景**：实验室每天产出零散数据（仪器导出的表、Excel 补录、拍照记录）。写报告要把它们汇总成固定格式，
慢，而且容易漏掉异常值。

**要做出什么**：上传一批实验数据（表格 + 补充说明 + 图片皆可），输出一份**符合科室模板的实验报告**：
目的 / 方法 / 结果 / 讨论四节 + 指标（或分组）表 + 异常值提示 + 数据出处。

**验收看什么**：
- 报告结构与模板一致，数值能从原始数据复算；
- 异常值（超参考范围 / 离群）被单独列出，并给出"需要复核"的提示；
- 换一批同结构的数据仍然能用（不是对着一份数据硬编码）。

---

## 需求 B：随访 / 用药安全提醒

**背景**：慢病随访要按规则提醒（复查间隔、药物相互作用、禁忌）。护士靠记忆和纸单，容易漏。

**要做出什么**：输入患者情况（用药清单 + 最近检验值，可上传附件或直接对话），
输出一份**随访与用药提醒**：下一步该复查什么、什么时间、哪些药要注意相互作用 / 禁忌，
每条提醒都带**依据**（指南段落或规则编号）。

**验收看什么**：
- 提醒与规则对得上（不是"多喝水、注意休息"这种空话）；
- 每条提醒能指到依据；
- 遇到"该由医生判断"的问题会拒答，而不是硬答。

## 交付

| 交什么 | 说明 |
|---|---|
| **Skill**：`SKILL.md` + `scripts/api.py`（+ 可选 `profile.json`） | 入口是 `handle(state, message, attachments, session)`；`profile.json` 放 agent 定制（名字/语气/签名/禁语） |
| **`report.md`** | 需求理解 / 数据来源与口径 / 产出样例 / 边界（不做什么）/ 局限 |
| **Skill 包**（= 应用） | 上传后平台自动装包、发布，给你分享链接 |

## 为什么"应用 = Skill"，不是"应用 = Agent"

平台有一个**通用 agent**：循环、记忆、工具、知识库、安全兜底、调度 skill —— 它决定"能不能跑"。
你在第 19 章做的，是把这份 agent **定制**成你的（名字、语气、签名、禁语），那是"人格"，不是"业务"。

真正决定"这个应用能干什么"的，是 **Skill**：

| | agent | Skill |
|---|---|---|
| 是什么 | 运行时 + 人格（可定制） | **一个具体业务能力** |
| 举例 | "简洁、先结论后依据的随访助手" | "把实验数据整理成科室模板报告" |
| 能否分享 | 不单独分享 | **一个 Skill = 一个应用**，有独立分享链接 |

所以平台把"应用"的单元放在 Skill 上：同一份 agent，装不同的 Skill 就是不同的应用；
你的 Skill 里带一份 `profile.json`，就能让这个应用带上**你的风格**。

## 验收（老师按这五条评，共 100 分）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 需求覆盖 | 25 | 需求里的每一条都落地了吗？有没有"看起来做了其实没做" |
| 数据与口径 | 25 | 数据来源说清了吗？判断规则写进代码了吗（不是凭模型感觉） |
| 结果可复核 | 20 | 结果能不能被别人一行行核对（表格 / 出处 / 计数） |
| 边界与安全 | 15 | 该拒答的拒答、该提示复核的提示；不越位下结论 |
| 演示与说明 | 15 | 3 分钟讲清：给谁用、输入什么、产出什么、边界在哪 |

## 建议步骤（约 3–4 小时）

1. **选需求**（10 分钟）：A 还是 B？把"要给谁用、他现在的痛点"写进 `report.md`；
2. **准备数据**（30 分钟）：自己找 / 造一批，**脱敏**，说明来源与字段含义；
3. **写 Skill**（1–2 小时）：先做一个"能出结果"的最小版本，再加判断与边界；
4. **本地自测**（30 分钟）：`python3 run_case.py <你的数据目录> output.json`（`run_case.py` 用平台同一套解析）；
5. **提交 + 发布**（10 分钟）：工作台提交 Skill 包 →「我的应用」点一下 → 拿分享链接；
6. **演示**（5 分钟）：用分享链接在浏览器里跑一遍。

## 注意

- **不要用真实患者隐私数据**：脱敏或自己造，报告里写清"虚构/脱敏"；
- **不要硬编码某一份数据**：老师会用另一批数据试一次；
- 结果形态你自己定，但必须**能复核**（表格 / 出处 / 计数至少占一样）。
