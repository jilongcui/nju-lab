评分细则（**写一个 Skill 完成具体业务流程**）

可机器判定的部分（每轮行数、最终报告四节与指标表、升级与拒答的条数）已在 `task.md` 里钉死，
由平台用确定性断言判定；断言未通过不会交给你判。

你只需判断语义（任一项不成立 → 不通过）：

1. **`notes` 是否说清"为什么判断要写进 Skill"**：口径（参考区间、四节、话术）是**业务知识**，
   模型只会说漂亮话，判断必须由代码做；同时要提到"平台的解析（PDF/Word/图片）帮了什么"。
2. **有没有把"超区间"写成"诊断"**：提示复核可以，写"因此是 XX 病" → 不通过。
3. **是否正视局限**：至少一条（约定形态 PDF、图片识别会错、报告需人工复核等）。

判定口径：键序/措辞差异不扣分；数值由断言负责；`score` 0~1，任一项不成立不超过 0.5。
