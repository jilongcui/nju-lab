# 大语言模型机制复现 Skill（你的方案）

> **本实验是应用任务，不是"按公式抄代码"**：给你一组写死的输入与四套口径（切 token / 注意力 / 消融 / 采样），
> **代码怎么组织、图怎么画由你自己决定**。口径是"业务规则"（必须照做），
> 达标看的是"**口径一致 + 消融方向对 + 说得清机制**"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：业务背景、六步流程、四套口径、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案；函数划分与你的骨架一致） |
| `cases/case01`、`cases/case02` | 两种序列长度，自测用（每个 case 有 `expected.json` 可以对照） |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 注意力在分配什么？"缩放"与"掩码"各防什么？ | 心里有数（写进 `notes`） |
| ② **看懂口径** | 切 token / 缩放因子 / 掩码方向 / 校验和格式 / 采样顺序 —— **都不许改** | 心里有数 |
| ③ **算注意力** | Q/K/V → `QKᵀ` → `/√d_head` → 因果掩码 → 逐行 softmax | 报告的 `attention` |
| ④ **消融对照** | full / no_scale / no_mask 三档各算三个统计量 | 报告的 `ablation` |
| ⑤ **采样与画图** | 各锐化系数下的 top-1 概率、熵、实测占比；两张图 | `sampling` / `figures` |
| ⑥ **写结论** | 两个机制各自解决什么、Q/K/V 的分工、局限 | 报告的 `notes` |

材料配合：`task.md`（需求 + 四套口径）→ 读 `reference/`（一份**走完这六步**的示范）→
回 `scripts/attention.py` 填掉你自己的 TODO → 两个 case 都跑 → 补全能力边界（平台不检查）→ 提交；实测记录写进 `report.md`（平台按它评过程分）。

## 能力边界

> 这一节是技能说明书的一部分（什么时候该用、不该用我）；**平台不检查这一节**。
> —— 这一节与 `description` 里的"不适用场景"是同一件事的两种写法。

- 能处理：`sentences.csv` + `embeddings.csv` + `params.json` 这套结构的输入
- （按你的实现补充）：**不处理**哪些情况？（例如：训练模型？多头 / 多层？真实生成？把注意力当因果解释？）
- （按你的实现补充）：你的实现里，哪些地方是**写死**的假设？（写死意味着换个数据/换个 `d_head` 就会坏）

## 要做的决策（本实验的重点）

1. **`√d` 到底在防什么**：如果点积的方差随维度 `d` 增长，softmax 会变成什么样？
   你的消融数据里，`max_row_weight` 与行熵各变了多少？变到极端会怎样（梯度还传得回来吗）？
2. **因果掩码的"方向"能不能写反**：如果掩的是下三角（第 i 个位置只许看 i 之后），
   语言模型还能做"预测下一个 token"吗？为什么？掩码对**解码效率**还有什么好处？
3. **`max_row_weight` 与 `entropy` 为什么要一起看**：只看其中一个够不够？举一个两者"看起来矛盾"的例子。
4. **锐化系数与"概率 vs 实际选择"**：top-1 概率 0.55 时，200 次采样命中多少？
   为什么"概率最高的词"不等于"每次都会被选中的词"？（这与模型输出不稳定、生成结果有随机性是同一件事）

## 自测

两个 case 都要跑，并自己与 `cases/<case>/expected.json` 对照（口径对不对，一眼就能看出来）：

```sh
for c in cases/*/; do
  python3 scripts/attention.py "$c" "/tmp/$(basename "$c").json"
done
```

> 卡住了怎么办：先看 `reference/scripts/attention.py` 里对应的那一段，再回来改自己的实现。

> 实测记录（运行方式、结果、错误分布）写进同级的 `report.md`；这里只保留能力边界与已知失效情形。
