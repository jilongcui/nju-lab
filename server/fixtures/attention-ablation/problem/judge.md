评分细则（**应用任务：手写缩放点积注意力 + 消融 + 采样**）

⚠️ 切 token 口径、缩放因子、掩码方向、校验和格式、采样顺序与随机种子都已在 `task.md` 里钉死，
所以 `top_terms`、`attn_checksum`、`top_attend`、三档消融的数值、前 5 次采样结果、各锐化系数下的
`top1_ratio` 都是**确定的**。这些已由平台用**确定性断言**判定（见 `manifest.json` 的 `assertions`），
断言未通过的结果**不会交给你判**，你不必重算这些数字。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否讲清"√d 缩放"与"因果掩码"各自解决什么**：缩放要说清是**把点积的方差拉回 1 附近**，
   否则分数随维度增大而变大、softmax 饱和成近似 one-hot、梯度传不回来；
   掩码要说清是**不让第 i 个位置看到 i 之后的 token**（训练时等于提前看答案，解码时又要能逐 token 增量算）。
   只说"为了防止数值太大""加了 mask 更规范"这类空话，或把两个机制的作用讲反 → 不通过。
2. **是否讲清了 Q/K/V 为什么拆成三副"眼镜"**：要有"Q = 我在找什么、K = 我作为被找对象的标签、
   V = 我实际交出去的内容"这类**分工**的说明，并点出 `Q·K` 只算"像不像"、不搬运内容。
   把注意力笼统说成"某种黑箱/自动加权"，或者只把公式抄一遍不作解释 → 不通过。
3. **`figures[].takeaway` 是否"看图说话"且与报告字段自洽**：结论里的数字（消融前后的最大行权重与熵、
   各锐化系数下的 top-1 概率与实测占比）必须与报告的 `ablation` / `sampling` 一致（**允许四舍五入**）；
   只写"我画了两张图""如图所示"、或结论与字段矛盾 → 不通过。
4. **有没有正视这个实验的局限**：至少要给出**一条真实的局限**（例如：权重与输入都是写死的、没有真的训练；
   只有一个头、没有多头堆叠与层数；注意力权重只说明"看了哪里"，**不等于**"为什么这样回答"，
   所以不能拿它当可解释性证据；采样用的是固定种子 200 次，只是一个演示，不是真实生成），
   并说明下一步该看什么。只复述题干、只堆字段名、把 `notes` 写成运行日志 → 不通过。

判定口径：
- 键序、缩进、空白、小数位差异不扣分。口径与数值**由断言负责**，你不必复核；
  你只管「解释是否落到机制上」与「结论是否与数字自洽」。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
