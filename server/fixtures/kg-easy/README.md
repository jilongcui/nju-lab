# kg-easy —— 入门实验：两条两跳查询做用药预警（知识图谱）

> 对应课程章节：**知识图谱**（最后的技术实例「两跳查询实现的用药预警」：禁忌证预警 + 相互作用预警 + 可解释路径）。
> 难度 **easy**：18 条三元组、两条两跳查询、`networkx`（镜像已预装），不涉及本体校验/实体消歧。

## 场景与数据

- 应用：合理用药审查 —— 患者正在吃的药 / 医生新开的药，与他的病有没有冲突
- 数据：`problem/cases/case01|case02/triples.csv`（各 18 条：药物知识 + 患者事实），各带 `expected.json`
- 造题：`tools/gen_cases.py`（固定数据，可重跑；**不下发**）

## 判据设计要点

1. 两条查询逐条比对（含顺序与 `path` 措辞），口径写死：
   禁忌证 = `P -患有-> C` + `D -禁忌证-> C` + `P -医嘱使用-> D`（汇合在同一疾病）；
   相互作用 = `P -正在服用-> A` + `A -相互作用-> B` + `P -新开医嘱-> B`（`risk` 取 `B` 的不良反应，字典序第一条）；
2. **每条预警必须带 `path`** —— 本实验要教的就是"可解释性"，路径为空算不通过；
3. 防"只按药名报警"的偷懒解：`P002 -医嘱使用-> 氨氯地平`（禁忌严重低血压、患者却患高血压）不能报。

## 项目字段文案（建项目时用）

- **title**：入门实验：两条两跳查询做用药预警（知识图谱 · 容易）
- **difficulty**：`easy`
- **content**（学生详情页首屏；不写"你的任务"）：
  合理用药要看"关系"：患者患什么病、在吃什么药、新开的药会不会和它冲突。
  把知识写成一条条三元组（头实体, 关系, 尾实体），就能沿着边多走两步把冲突找出来 —— 而且每条预警都能给出推理路径。
- **objectives**：
  1. 会把三元组建成一张有向图，并说出节点与边各是什么；
  2. 会写两跳查询（沿两条边汇合），并解释为什么这叫"两跳"；
  3. 会说明"带路径的预警"为什么是知识图谱在医疗场景的关键。
- **background**（每条 = 概念 + 一句人话解释）：
  - **三元组**：把知识写成「头实体, 关系, 尾实体」，例如「二甲双胍, 禁忌证, 严重肾功能不全」。
  - **有向图**：三元组就是边；节点是实体（患者、药、病），边带方向与关系名。
  - **两跳**：从一个节点沿两条边走到另一个节点 —— 例如「患者→患有→病」和「药→禁忌→病」在同一个病上汇合。
  - **可解释性**：每条预警都能写成一串"因为⋯⋯所以报警"的边，医生能核对。
  - **网络X**：Python 的 `networkx` 是本地图库，`add_edge` 加边、`successors` 沿出边找邻居。
- **description**：
  1. 读实验内容与本节的达标要求，确认两条查询的口径与 `path` 格式；
  2. 读 `triples.csv`，分清哪些是药物知识、哪些是患者事实；
  3. 用 `networkx` 建图（边属性存 `relation`），报出节点数与边数；
  4. 写禁忌证查询：患者-患有->病，且药-禁忌->同一病，且患者-医嘱使用->该药；
  5. 写相互作用查询：患者-正在服用->A，A-相互作用->B，患者-新开医嘱->B；
  6. 给每条预警写 `path`（2~3 段），按口径排序；
  7. 画每个患者的预警条数柱状图（轴标签英文）；两个 case 都与 `expected.json` 核对；
  8. 生成实验报告 `report.md`：数字由平台自动填入，你只补结论与踩坑。
- **references**：`networkx` 文档（`DiGraph` / `successors`）；本章技术实例的 Cypher 写法（对照看"图里 N 跳语法几乎不变"）。
- **faq**：为什么 P002 用了氨氯地平却不报警？（两跳必须汇合在同一个病上：他患高血压，而氨氯地平禁忌的是严重低血压）；为什么每条都要写 path？（可解释性是这个实验的重点，医生要看"为什么报警"）；能不能不用 networkx？（可以，但本章要求用图库，用 dict 也能做但不算练到图遍历）。
