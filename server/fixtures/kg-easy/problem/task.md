# 入门实验：两条两跳查询做用药预警（知识图谱 · 容易）

## 业务背景

关系数据库能精确统计、向量库能语义检索，但「**这个药和患者正在吃的药会不会冲突**」「**患者这个病能不能用这个药**」
这类问题靠表很难问清楚 —— 它们考的是**关系**。知识图谱把知识写成一条条**三元组**：

```
(头实体, 关系, 尾实体)
(二甲双胍, 禁忌证, 严重肾功能不全)
```

一大堆三元组连起来，就成了可以"沿边多走几步"的图。本实验只做**两跳**，正好对应本章技术实例里的两个场景。

## 你的任务

`triples.csv` 里有 18 条三元组（三列：`head, relation, tail`），包含**药物知识**（一线用药 / 禁忌证 / 相互作用 / 不良反应）
与**患者事实**（`P001 -患有-> …`、`P001 -医嘱使用-> …`、`P001 -正在服用-> …`、`P001 -新开医嘱-> …`）。

用 **networkx** 建图，跑两条两跳查询，把预警（**连同推理路径**）写进 `output.json`：

1. **禁忌证预警**：对每个 `P -医嘱使用-> D`，若存在 `D -禁忌证-> C` 且 **`P -患有-> C`** → 预警；
2. **相互作用预警**：对每个 `P -正在服用-> A`，若存在 `A -相互作用-> B` 且 **`P -新开医嘱-> B`** → 预警；
   `risk` 取 `B` 的 `不良反应`（按字典序第一条；没有就填空字符串 `""`）。

**格式口径**（顺序也算分）：

- `path` 是**字符串数组**，写成人能读的链路，例如
  `["P001 -患有-> 严重肾功能不全", "二甲双胍 -禁忌证-> 严重肾功能不全"]`；
- 禁忌证按 `patient`、`drug` 升序；相互作用按 `patient`、`new_drug` 升序；
- `graph.n_nodes` 是去重后的节点数、`graph.n_edges` 等于三元组条数。

## 实验流程（六步）

| 步 | 做什么 | 产出 |
|---|---|---|
| ① 看清需求 | 两条两跳查询的口径与"路径"格式 | 心里有数 |
| ② 看一眼数据 | 18 条三元组里，哪些是药物知识、哪些是患者事实 | 心里有数 |
| ③ 建图 | 用 `networkx` 把三元组加成有向边（边属性 `relation`） | `graph` |
| ④ 两跳查询 | 沿边多走一步，按两个场景筛选 | `evaluation` |
| ⑤ 核对 + 画图 | 与 `expected.json` 对一眼；画每个患者的预警条数 | 图 |
| ⑥ 写结论 | 结论与踩坑 | `report.md` |

## 交付格式

**`output.json`**（写在工作目录下）：

```json
{
  "graph": { "n_nodes": 16, "n_edges": 18 },
  "evaluation": {
    "forbidden": [
      { "patient": "P001", "drug": "二甲双胍", "condition": "严重肾功能不全",
        "path": ["P001 -患有-> 严重肾功能不全", "二甲双胍 -禁忌证-> 严重肾功能不全"] }
    ],
    "interactions": [
      { "patient": "P001", "taken": "华法林", "new_drug": "阿司匹林", "risk": "消化道出血",
        "path": ["P001 -正在服用-> 华法林", "华法林 -相互作用-> 阿司匹林", "阿司匹林 -不良反应-> 消化道出血"] }
    ]
  },
  "figures": [
    { "path": "figures/alerts_by_patient.png", "takeaway": "P001 与 P002 各有一条禁忌或相互作用预警……" }
  ],
  "notes": "……（≥40 字：两条查询分别沿哪条边走的、为什么这叫"两跳"、路径为什么重要）"
}
```

- 图至少 1 张，`path` 与实际落点一致（相对当前工作目录）；轴标签用英文。
- **每条预警都必须带 `path`** —— 这是知识图谱在医疗场景的可解释性：医生要能看到"因为哪条边，所以报警"。

## 怎么算完成

1. 两个 case 都跑通，两条查询的预警与 `expected.json` 一致（含顺序）。
2. 每条预警都有可读的推理路径（2~3 段）。
3. 把结论与踩过的坑记下来 —— 报告会由工具整理进 `report.md`，**不需要改 `SKILL.md`**。

判据全文见 `judge.md`。
