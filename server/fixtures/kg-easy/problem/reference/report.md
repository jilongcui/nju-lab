## 3. 基线对照

- 基线做法：只按"药名出现"报警（不分患者、不看关系）
- 基线指标：两个 case 的 18 条三元组里"药名出现"约 10 次，全是噪音
- 我的结果 / 基线：两跳查询只报 3 条，且每条都带推理路径 —— 这就是"关系推理"与"字符串匹配"的差别

## 4. 踩坑记录（每条行一行，平台按行计数）

1. 边属性必须存 relation：只连边不记关系，两条查询就分不清"患有"和"禁忌证"
2. `P002 -医嘱使用-> 氨氯地平` 不该报警：氨氯地平禁忌"严重低血压"，但 P002 患的是高血压 —— 两跳要**汇合在同一终点**
3. 相互作用查询要检查"新开医嘱"这一跳，只有"正在服用 A"而 B 没开过时不能报
4. 图里写中文会变方框 —— 轴标签一律英文，中文只放在 takeaway 里

## 5. 结论

两条查询都只走两步：禁忌证沿"患者-患有->病"与"药-禁忌证->病"汇合，相互作用沿"正在服用→相互作用→新开医嘱"三段边汇合。关键在"汇合到同一节点"这个条件——少了它会把无关的药也报出来。每条预警都带 path，医生能直接看到"为什么报警"，这正是知识图谱相对 SQL 的优势。
