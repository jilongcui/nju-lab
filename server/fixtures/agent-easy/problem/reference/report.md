## 4. 踩坑记录（每条一行，平台按行计数）

1. 六条规则有先后顺序：`hba1c` 很高但刚复查过（`days < 90`）也必须是 urgent，不能落到 none
2. 记忆边界：`invalid_request` / `unknown_patient` 不写记忆，否则 `memory_after` 多出 P999 / 空键
3. 消息里的"上次联系"要取**处理本条之前**的记忆：case02 里第二条 P001 才变成 2026-10-01
4. 图里不能写中文（复验镜像没有中文字体），轴标签用英文，中文写进 `takeaway`

## 5. 结论

两个 case 的感知 / 决策 / 行动 / 记忆四环结果与参考值完全一致。最容易错的是**优先级顺序**和**记忆边界**：
前者要求把"先看患者号是否有效"放在最前，后者要求只在正常决策后写记忆。值得换成模型的只有感知
（把口语请求变成结构化字段），决策与记忆必须留在代码里 —— 它们的口径必须每次一样。
