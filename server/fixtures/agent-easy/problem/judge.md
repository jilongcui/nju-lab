# 评分细则（语义判据）

> 硬性条件由 `manifest.json` 的 `assertions` 判定（感知 / 决策 / 行动 / 记忆 / 计数逐字段比对，
> 加边界与图、notes）。这里只判**语义**，任一项不成立 → 不通过。

1. **`notes` 是不是自己写的**：要说清六条规则里**哪条最容易写错**（通常是"边界不写记忆"和
   "优先级顺序"），以及为什么记忆要在**同一次运行内**生效。照抄模板或只复述字段名 → 不通过。
2. **记忆边界是否真的理解**：`memory_after` 里**不能**出现无患者号 / 未知患者的键；
   若学生把 `unknown_patient` 也写进了记忆，说明没读懂"记忆只记有效决策"这条口径。
3. **case02 的第二次 P001**：消息里的"上次联系"必须是 `2026-10-01`（第一条请求写下的），
   而不是种子里的 `2026-08-01` —— 说不清这一点，说明没理解"读的是处理本条之前的记忆"。
4. **图是否"看图说话"**：`takeaway` 要说出哪类动作最多、大约几条；与 `counts` 矛盾 → 不通过。
5. **是不是手抄的**：如果 `perceive` 条数与 `requests.txt` 行数对不上（例如直接抄 `expected.json`
   却漏了最后一行），或 `messages` 与模板差一个标点 → 不通过（判据是逐字比对）。
