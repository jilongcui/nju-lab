评分细则（**应用任务：达标判定**）

⚠️ 模型、特征、概率阈值由学生自选，**输出数值不要求等于参考水平**（`expected.json` 里给的是"参考水平"）。

**硬性条件已由平台用确定性断言判定**（见 `manifest.json` 的 `assertions`）：字段完整、
`recall` / `precision` 在 [0,1]、切分覆盖全部样本、测试集占比 20%~40%、基线定义正确（现有做法 recall ≈ 0）、
基线准确率可信（±15%）、**达标线 `recall ≥ 0.65`**、**防退化 `precision ≥ 0.40`**、`notes` ≥20 字。
断言未通过的结果**不会交给你判**，你不必重算这些数值。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否体现了完整流程**：是否能看到 ① 对数据的一点观察（**失约比例有多大**、哪些列看起来有用）
   ② **方案比较（至少两个方案及各自的 recall / precision）** ③ 最终选择与理由（业务上更看重哪一边）
   ④ 对结果的一个判断（哪类错得更多、还有什么不足）。空洞小结（"使用了机器学习模型，效果良好"）、
   与 `model` 字段矛盾、或只是复述题目 → 不通过。
2. **`model` 与 `metrics` 是否自洽**：例如声称"用默认参数训练、未做任何处理"却报出 recall 0.9；
   或给出的 `accuracy` **明显低于**"一律判会来"的准确率（说明模型连多数类都判错了）→ 不通过。
3. **是否可疑地过于好**：`recall` 与 `precision` **同时**远超参考水平
   （recall > `reference.recall + 0.15` 且 precision > `reference.precision + 0.15`）且 `notes` 未给出
   可核对的解释 → 判为可疑（疑似用测试集反复调阈值）→ 不通过。
4. **`baseline` 的语义是否正确**：应表示"不做预测、一律认为患者会来"（`recall` ≈ 0，
   `accuracy` 等于"会来"的人数比例）。若学生拿一个训练过的模型当基线（故意拉低参照）→ 不通过。

判定口径：
- 键序、缩进、空白、小数位差异不扣分；数值比较只按上面写明的容差与阈值。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
