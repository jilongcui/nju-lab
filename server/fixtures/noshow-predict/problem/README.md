# 题目包：预测哪些门诊预约会失约（二分类 · 类别不平衡）

> 这是本实验的**题目包** —— 一个真实需求（提前找出会失约的预约）、判据、两批数据，
> 外加**一份示范实现**（`reference/`）供你对照学习。

## 这个实验要学什么

1. **类别不平衡时，准确率会骗人**：失约的人只占约 1/4，"一律认为会来"就有 7 成准确率，
   但对失约者的**召回率是 0** —— 一个都没抓到。**选对指标**比调模型重要。
2. **召回与精确率的权衡**：想多抓失约者（recall↑）就会误报更多（precision↓）。
   业务上要能说清"我们更怕哪一边"，并据此选阈值。
3. **基线意识**：先量化"现有做法"（不做预测）的成绩，才知道自己有没有真的进步。
4. **可复现**：固定随机种子、写清切分，结论才能被复核。

## 实验流程（六步）

`task.md` 里写了完整流程（① 看清需求 → ② 看一眼数据 → ③ 定基线 → ④ 建模并比较 → ⑤ 评估 →
⑥ 写结论），`reference/scripts/train.py` 是一份**把这六步都走完**的示范 —— 其中第 ④ 步它比较了
两张图（失约比例 + 混淆矩阵），并把结果写进了 `notes`。照着走一遍，再换成你自己的做法。

## 包内有什么、怎么用

| 路径 | 是什么 | 建议怎么用 |

## 两批数据

| case | 规模 | 失约率 | 参考水平（现有做法 → 参考实现） |
|---|---|---|---|
| case01 | 800 行 | 27.5% | recall 0.00 → 0.73；precision — → 0.47 |
| case02 | 600 行 | 33.5% | recall 0.00 → 0.76；precision — → 0.55 |

> `expected.json` 里的数值**不是标准答案**，而是"参考水平"：判据用它核对你的 `baseline` 是否可信、
> 并识别"可疑地过于好"的结果。你可以做得比参考实现更好，只要说清是怎么做到的。

## 自测方法

CLI 约定：`train.py <case_dir> <output.json>`（`<case_dir>` 里要有 `data.csv`）。

```sh
# 两个 case 都跑一遍，看是否达标（recall ≥ 0.65 且 precision ≥ 0.40）
for c in cases/*/; do python3 <你的skill>/scripts/train.py "$c" /tmp/out.json; done
```

脚本末尾会打印三项指标与达标判断。判据的其余各项（结构、切分占比、baseline 定义、`notes`）
请对照 `judge.md` 自己核一遍。

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段 —— 尤其是它**怎么处理不平衡**。
