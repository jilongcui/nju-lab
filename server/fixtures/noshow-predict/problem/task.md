# 应用任务：预测哪些门诊预约会失约

## 业务背景

门诊实行预约制。患者约了号却**没来**（no-show），这个号源就白白浪费了 ——
后面想看的患者又挂不上。运营团队的做法是：**提前给"高风险"的预约打电话提醒**，
再根据风险调整排班。

**现有做法**：不做任何预测，**一律按"患者会来"安排**（号源按预约全排）。

> 注意这个"现有做法"有多迷惑人：因为大多数人确实会来，它的**准确率有 7 成以上**。
> 但它对"会失约的人"的**召回率是 0** —— 一个都没抓出来，也就一个人都没提醒。
> **这就是本实验最重要的一课：类别不平衡时，准确率会骗人。**

## 你的任务

用工作目录里的 `data.csv` 构建一个失约风险预测方案，产出 `output.json` 与你的图，达到四条要求：

1. **尽量别漏掉会失约的人**：在测试集上，对失约者的**召回率 recall ≥ 0.65**。
2. **也不要草木皆兵**：**精确率 precision ≥ 0.40** —— 否则要打电话的名单会长到没人打得完。
3. **可复现**：切分与训练用固定随机种子；产出里写清 `n_train` / `n_test`（测试集占比 20%~40%）。
4. **用图把分析讲清楚**：看数据时画图、评估结果时画图，并**给每张图写一句结论**（`figures` 字段）。

> 模型、特征、阈值都由**你自己决定**（选一个你能讲清楚的即可，不必做多个方案的对比）。
> 达标与否看上面四条是否真的做到（判据见 `judge.md`）。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 别漏掉会失约的人（召回优先）+ 名单别长到打不完 | 心里有数 |
| ② **看一眼数据 + 画图** | 有多少行、**失约比例是多少**、哪些列看起来有用；**画一张总览图**（失约的人占多少？哪些特征和失约有关？） | `figures/` 里第 1 张图 |
| ③ **定基线** | 不做预测能做到多少（一律认为会来） | 报告的 `baseline` |
| ④ **训练模型** | 选一个模型、固定种子分层切分后训练（**注意失约的人只占少数**） | 报告的 `model` / `metrics` |
| ⑤ **评估 + 画图** | 算 recall / precision，并**画混淆矩阵**看"漏了多少、误报多少" | `figures/` 里第 2 张图 |
| ⑥ **写结论** | 每张图一句结论 + 整体判断（业务上更看重哪一边、还有什么不足） | 报告的 `figures` / `notes` |

> ② 和 ⑤ 的图都用 `matplotlib` 画（镜像已预装），存到工作目录的 `figures/` 下。
> ⚠️ 图里的**标题与坐标轴标签建议用英文**（运行环境没有中文字体，中文会显示成方框）；
> 中文解释写在 `takeaway` 与 `notes` 里。

## 数据字典（`data.csv`）

| 列 | 含义 |
|---|---|
| `age` | 患者年龄 |
| `lead_days` | 预约提前天数（今天约的是几天后的号） |
| `prior_noshow` | 该患者既往失约次数 |
| `distance_km` | 住址到医院的直线距离（km） |
| `reminder_called` | 是否已电话提醒（1=已提醒） |
| `noshow` | **目标**：这次是否失约（1=没来） |

> 数据是固定种子合成的**教学数据**（不是真实患者数据）。规律符合常识：越早约、既往失约越多、
> 距离越远，越可能不来；已经电话提醒过的，明显更容易来。

## 交付格式（`output.json`，写在工作目录下）

```json
{
  "model": "你选择的模型名称",
  "n_train": 600,
  "n_test": 200,
  "metrics": { "recall": 0.73, "precision": 0.47, "accuracy": 0.68 },
  "baseline": { "name": "predict_all_show", "recall": 0.0, "accuracy": 0.76 },
  "figures": [
    { "path": "figures/data_overview.png", "takeaway": "失约的人只占约四分之一；预约提前天数越多，失约率越高（最长的档接近四成）。" },
    { "path": "figures/evaluation.png", "takeaway": "混淆矩阵显示漏掉的失约者已经很少，但误报仍有一些 —— 提醒名单大概是实际失约人数的两倍多。" }
  ],
  "notes": "先画图确认了两个事实：失约只占少数（不能看 accuracy）、离预约日越远风险越高。用 class_weight='balanced' 让模型别偏向多数类，测试集 recall 0.73、precision 0.47。不足：误报偏多，可以按单次提醒成本调高阈值换更短的名单。"
}
```

- `metrics` **必须**有 `recall` 与 `precision`（`accuracy` 可选，但推荐一并给出，方便对比"准确率有多骗人"）。
- `baseline` 是你**自己算出来的**现有做法成绩：把所有人都判成"会来"（预测全为 0）时的
  **`recall`（必为 0）与 `accuracy`**。判据会核对它是否可信。
- `figures` 至少两张：一张"看数据"（②）、一张"评估结果"（⑤，建议画混淆矩阵），每张都要有 `path` 与一句 `takeaway`。
- `threshold` 可选：如果你用概率阈值决策，写出来。

## 怎么算完成

1. 方案要普适：对任意一份同结构 `data.csv` 都能产出 `output.json` 与两张图。
2. 两个 case（`cases/case01`、`case02`，两家医院/两个季度）**都要达标** —— 判据对每个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
