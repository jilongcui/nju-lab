# 分子医学学习助手（教师侧解答样例）

> ⚠️ **这份实现不随题目包下发**（它在实验目录根下的 `solution/`，不在 `problem/` 里）。
> 它的作用是两份**机器证明**：① 题目可解（拿它跑平台复验应 2/2 通过）；② 判据不误杀（`expected.json` 由它算出）。
> 学生拿到的是 `skill-template/`（只有 `SKILL.md` + TODO 空壳）—— 这是本章"迁移检验"的设计。

## 能力边界

- 能处理：`questions.csv` + `experiment_data.csv` + `passages.csv` + `tools.json` + `tool_calls.csv` +
  `report_template.json` 这套固定结构的输入（本地文件，无网络）
- 能做：按固定句式抽薄弱点并跨轮应用；按 schema 校验工具调用（非法如实记 rejected）；路由到本地 mock 执行；
  按模板成文；把越界读数引用到行级、解释引用到段级；越界升级 + 拒答
- 不处理：**真正的 MCP 服务**（环境无外网、镜像无 SDK）—— 用本地 mock 代替
- 不处理：**大模型生成**（报告文本是按模板与数据拼出来的，没有调用任何模型）
- 不处理：**mem0 这类记忆服务** —— 用本地条目表代替
- 不处理：语义检索（引用与匹配都只到"字面 / 行级 / 段级"，换一种问法可能不准）
- 不做：诊断（只描述"读数越界"，不下结论）

## 方法（六步 —— 与 `task.md` 的流程一致）

1. **看清需求** —— 五件事对应前面哪几章的本事：记忆（16）/ 工具（17）/ 技能（18）/ 检索与出处（5、9）/ 安全边界（18）
2. **摸清材料** —— 六份文件怎么对上（提问、数据行、段落、名册、待执行调用、模板与阈值）
3. **搭最小闭环** —— `write_memory` / `apply_memory` / `run_tool_calls` / `build_sections` /
   `build_citations` / `run_safety`
4. **逐环跑通** —— 每一环单独看：条目对不对、调用结论对不对、四节齐不齐、引用格式对不对
5. **汇总与画图** —— `plot_overview`：各指标均值 + 越界行数（图上标签用 ASCII，中文写 `takeaway`）
6. **写结论** —— `compose_notes`：每一环为什么这么做、检索结果 ≠ 结论、局限至少两条

产出结构（`output.json`）见 `task.md`；判据见 `judge.md`。

## 为什么这样组装（本章的教学点）

- **记忆只记"薄弱点"**：不是把整段对话存下来，而是抽出一条**后面用得上**的事实，
  并在下次提问里真的用上 —— 这才叫"记忆"，否则只是日志；
- **工具调用必须带校验，而且失败要留痕**：`args_valid=false` 的调用**也要出现在报告里**。
  真实系统里"悄悄跳过非法调用"是最危险的做法：你既不知道模型想干什么，也不知道它错在哪；
- **报告按模板生成**：模板把"交付契约"钉死了（四节、最小篇幅、引用要求），
  于是"报告是否合格"可以机器判，而不是靠感觉；
- **引用要落到行级 / 段级**：`experiment_data.csv:R02` 比"根据数据"有用得多 ——
  出错时能一眼定位到哪一行；
- **安全边界落成字段**：越界读数升级 + 固定话术、要求下诊断的提问拒答 ——
  平台没有 hooks 运行时，所以边界必须体现在**产出字段**里（照第 18 章的做法）。

## 实测档案

- 自测时间：2026-10-10（教师侧复验 2/2 通过）
- 用例通过率：2/2
- 关键数字：
  - case01：6 次调用（**4 executed / 2 rejected**：`missing_required` + `type_mismatch`）；
    2 行越界（`R02` 血小板 18、`R06` 白细胞 12.5）；1 条记忆（老是搞混 白细胞计数/血小板计数）应用 1 次；
    引用 4 条（2 data + 2 passage）
  - case02：6 次调用（4 executed / 2 rejected）；2 行越界（`R02` 舒张压 182、`R04` 收缩压 145）；
    1 条记忆（收缩压/舒张压）
- 踩坑记录（pitfalls）：
  - **非法调用必须留在报告里**：`tool_calls` 的长度要与 `tool_calls.csv` 相同，非法项记 rejected + 理由
  - 校验**顺序**不能换：未知工具 → args 不是对象 → 缺必填 → 类型不符（命中即停），
    否则同一份请求会得到不同的 `rejected_reason`
  - `integer` 类型要用 `isinstance(v, int) and not isinstance(v, bool)`（JSON 里的 `true` 是 `bool`，不是整数）
  - `mean_of_column` 的 `decimals` **缺省 0**；摘要用 `round()` 的默认字符串形式（`9.0` 不是 `9`）
  - `fetch_reference` 要取 `passage_id` **最小**的那条（同一 item 常有多条段落）
  - `citations` 顺序钉死：先 data（按 `row_id` 升序）再 passage（按 item 升序）
  - 固定话术必须**一字不改**地抄模板（升级话术与拒答理由分开）
  - 图上的标签必须 ASCII（指标名是中文，用 `item 1/2/3` 并在 `takeaway` 里给映射）
