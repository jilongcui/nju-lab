评分细则（**综合实践：分子医学学习助手 —— 四环闭环**）

⚠️ 本章是**迁移检验**型任务：学生只拿到需求与交付契约，**没有参考实现**。
可机器判定的部分（工具调用的校验结论与 mock 结果摘要、记忆条目与应用、`citations` 的 kind/ref、
越界行与固定话术、`key_facts`、报告四节的名称与最小篇幅）已在 `task.md` 里钉死，
由平台用**确定性断言**判定（见 `manifest.json` 的 `assertions`）。断言未通过的结果**不会交给你判**，
你不必重算这些值。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否说清每一环"为什么这么做"**：记忆 —— 为什么只把学生的**薄弱点**记下来、为什么要在
   后面的提问里应用；工具调用 —— 为什么要**按 schema 校验**、为什么**失败也要如实记为 rejected**
   （而不是假装成功）；报告 —— 为什么要按模板成文而不是自由发挥；出处 —— 为什么引用要落到
   **行号级 / 段落级**。只写"我都做了""四环齐了"这类空话，或只是复述题干 → 不通过。
2. **有没有把"检索结果"当"结论"**：引用只说明**出处**，不等于诊断。如果报告或 `notes` 里出现
   "因此这个学生（或这个病人）是 XX 病/XX 异常"这类**越界的诊断式断言**，即使字段都填对了 → 不通过。
3. **安全边界是否被真正理解**：要能说清"越界读数为什么要升级而不是照答"（数据可能测错、
   需要人工复核、助手不承担判断责任）与"为什么不能直接下诊断结论"（诊断必须由医师结合完整病史与检查作出）。
   把这两处说成"模板要求/格式要求"、或明显是照抄固定话术而没有理由 → 不通过。
4. **有没有正视局限**：至少给出**两条**真实局限，例如：本地 mock 工具**不是真正的 MCP 服务**；
   报告是**按模板拼的**（没有接大模型生成）；"记忆"是**本地条目表**（不是 mem0 这类记忆服务）；
   检索与引用只做到**字面/行级**，换一种问法就可能引用错段落；环境无外网，所以这些都是本地等价物。
   只复述题干、只堆字段名、把 `notes` 写成运行日志 → 不通过。

判定口径：
- 键序、缩进、空白、措辞差异不扣分。数值与名单**由断言负责**，你不必复核；
  你只管「理由是否说清」与「有没有越界」。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
