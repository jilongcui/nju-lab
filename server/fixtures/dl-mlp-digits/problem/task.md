# 入门实验：分拣手写数字（三分类 · 神经网络）

## 业务背景

你是图书馆数字化小组的实习生。旧借书卡上是一堆**手写数字**，扫描进来全是 8×8 的小图
（每个像素 0~16 的灰度）。现在要做一个"看小图认数字"的小程序，先把最常出现的
**3、8、9** 三个数字分开 —— 这三个数字笔画结构相近，正好用来看看**神经网络到底学到了什么**。

**现有做法（基线）**：不做判断，一律报"样本里最多的那个数字"。
在这个三分类问题上大约只有 **1/3** 的正确率 —— 所以你的任务不是"跑个网络"，
而是**比这个现有做法明显更好**，并且**真的把网络训练起来**（要看得到损失在下降）。

## 你的任务

用工作目录里的 `data.csv` 训练一个小神经网络，产出 `output.json` 和你的图，达到三条要求：

1. **达标**：在测试集上 **accuracy ≥ 0.92**，且 **macro F1 ≥ 0.90**（三个数字都要认得）。
2. **可复现、可核对**：固定随机种子；写清 `n_train` / `n_test`（测试集占比 **20%~40%**）；
   把**逐轮训练损失**记进 `training.history`（至少 5 轮，且最后一轮的损失要低于第一轮）。
3. **用图讲清楚**：看数据画一张、训练/评估各画一张，并给每张图写一句结论（`figures[].takeaway`）。

> 这是**入门实验**：网络很小（一层隐藏层就够）、数据也很小。
> 隐藏层多大、用什么优化器、训多少轮，都由**你自己决定** —— 选一个你能讲清楚的即可。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 三个数字都要认；比"一律猜最多"好得多；并且真的训练了 | 心里有数 |
| ② **看一眼数据 + 画图** | 每行是一张 8×8 小图；三类各多少张？三类笔画差在哪？**画样例图 + 类别计数** | `figures/` 里第 1 张图 |
| ③ **定基线** | 不建模能做到多少（一律猜训练集里最多的数字） | 报告的 `baseline` |
| ④ **训练模型** | 搭一个小网络（如 64 → 32 → 3），**逐轮记录训练损失** | 报告的 `training.history` |
| ⑤ **评估 + 画图** | 算 accuracy / macro F1，画训练损失曲线与混淆矩阵 | `figures/` 里第 2、3 张图 |
| ⑥ **写结论** | 每张图一句结论（`figures[].takeaway`）+ 整体判断（`notes`：损失怎么变、错在哪类） | 报告的 `figures` / `notes` |

> 图用 `matplotlib` 画（镜像已预装），存到工作目录的 `figures/` 下，
> 例如 `plt.savefig("figures/training_curve.png", dpi=110)`。
>
> ⚠️ 图里的**标题与坐标轴标签用英文**（如 `epoch` / `training loss`）：运行环境里没有中文字体，
> 中文会渲染成方框。中文解释写在 `takeaway` 和 `notes` 里（那些是给人读的）。

## 数据字典（`data.csv`）

| 列 | 含义 |
|---|---|
| `p00` … `p77` | 8×8 图像的 64 个像素值（0~16 的灰度；行优先排列，`p03` 是第 0 行第 3 列） |
| `digit` | **目标**：这个数字是 3 / 8 / 9 中的哪一个 |

> 数据来自经典的 8×8 手写数字数据集。**3、8、9 笔画结构相近**（都有圆弧或闭合的圈），
> 所以偶尔会认混 —— 混淆矩阵就是用来看"到底混在哪一对上"的。
> 图像分辨率只有 8×8，写潦草的样本本身就很难辨认。

## 交付格式

**`output.json`**（写在工作目录下）：

```json
{
  "model": "你最终选择的网络（例如 MLP(64→32→3, ReLU, Adam)）",
  "n_train": 402,
  "n_test": 135,
  "metrics": { "accuracy": 0.98, "macro_f1": 0.98 },
  "baseline": { "name": "most_frequent", "label": 3, "accuracy": 0.34 },
  "training": {
    "epochs": 30,
    "optimizer": "Adam(lr=0.05)",
    "loss": "CrossEntropyLoss",
    "history": [
      { "epoch": 1, "train_loss": 1.114 },
      { "epoch": 2, "train_loss": 0.62 },
      { "epoch": 3, "train_loss": 0.34 }
    ]
  },
  "figures": [
    { "path": "figures/data_overview.png", "takeaway": "每行是一张 8×8 小图；三类基本均衡，3/8/9 都有圆弧，区别在开口与闭合的位置。" },
    { "path": "figures/training_curve.png", "takeaway": "训练损失从 1.11 降到 0.01，前几轮降得最快，说明网络确实在学。" },
    { "path": "figures/evaluation.png", "takeaway": "对角线是判对的样本；最容易混的是 3 → 9，因为它们的上半部都是圆弧。" }
  ],
  "notes": "先看样例图确认三类笔画结构相近；用两层 MLP（64→32→3，ReLU + Adam）训练 30 轮，损失从 1.11 降到 0.01。测试集 accuracy 0.98、macro F1 0.98，远高于「一律猜最多数字」的基线（0.34）。不足：只学了三个数字、分辨率低，写潦草时仍会认混。"
}
```

- `metrics` 至少要有 `accuracy` 与 `macro_f1`（0~1）。
- `baseline.accuracy` 必须是**你自己算出来的**：把"训练集里最多的数字"当作对所有人的预测，
  在**同一个测试集**上算 accuracy。
- `training.history` 至少 5 个元素，每个元素含 `epoch` 与 `train_loss`；**最后一轮损失 < 第一轮**
  （判据会核对 —— 这是"真的训练了"的证据，不是走过场）。
- `figures` 至少两张（推荐三张：看数据 / 训练曲线 / 混淆矩阵），每张都要有 `path` 与一句 `takeaway`。

## 怎么算完成

1. 写一个能跑的训练脚本（推荐做成 Skill 里的一段脚本），能对任意一份同结构 `data.csv`
   产出 `output.json` 与图。
2. 在 `cases/case01` 与 `cases/case02`（样本更少、带扫描噪声）上都达标 —— 判据对两个 case 各判一次。
3. 把结论与踩过的坑记下来 —— 报告会由工具整理进 `report.md`，**不需要改 `SKILL.md`**。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
