循环的设计：每一轮把"系统提示 + 已知事实 + 最近几轮问答 + 当前用户话"发出去，模型只回一个 JSON 动作；
执行完工具后，把观察作为一条新的 user 消息回填，模型在这一步的上下文里能看到真实数据，所以它能自己纠偏
（例如先查台账发现编号写错了，下一步改查站点）。步数上限取 limits 的 max_steps_per_turn，用尽就按
"已查到的先给你"收尾，并把 terminated 记成 max_steps —— 掩盖截断会让报告失真。

记忆为什么用条目表而不是回放全文：事实只有几个 key，状态化之后"更正"才真的生效（旧值进 superseded，
不再进提示），上下文也不会随轮次膨胀。代价是抽取规则目前只认"我负责 X 区 / 更正：…"这两种句式，
换个说法就抓不到 —— 这是本项目最大的局限，真实产品应该让模型自己决定写什么进记忆。

另一个局限：检索用字符 2-gram 加长度归一，手册段落一长就会被稀释；本实验 5 篇手册够用，
上百篇时要换成真正的 BM25 或向量检索。边界判断靠关键词（寿命 + 否定词），模型换了说法可能漏判。
