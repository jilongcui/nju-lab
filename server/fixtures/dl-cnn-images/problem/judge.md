评分细则（应用任务：达标判定）

⚠️ 模型/结构/轮数/是否增强由学生自选，**输出数值不要求等于参考水平**（`expected.json` 是"参考水平"，不是标准答案）。

**硬性条件由平台断言判定**（`manifest.json` 的 `assertions`）：字段完整、≥3 张图（每张有 `path` 与 ≥10 字 `takeaway`）、
`macro_f1`/`accuracy` ∈ [0,1]、逐档召回率 10 项齐全、`n_train + n_test` 覆盖全部样本、测试集占比 20%~40%、
`training.history` ≥5 轮且每轮有 `loss` 与 `val_loss`、`epochs_run` 自洽、`early_stopped` 为布尔、
基线 `macro_f1` 与参考值相差 ≤0.12、**`macro_f1` ≥ 0.93（case02 为 0.85）**、
**逐档召回率 ≥0.85（case02 为 0.65）**、`notes` ≥20 字。未过断言者不交给你判，你不必重算。

只判下列语义项（任一不成立 → 不通过）：

1. 三张图里必须有一张讲**逐轮训练过程**（从哪一轮开始变差、怎么处理），一张讲**错在哪两档**（混淆矩阵）。
   结论套话、互相复述、或与 `training` / `metrics` 矛盾 → 不通过。
2. `notes` 必须说清**怎么处理扫描偏移**（卷积 / 增强 / 对齐预处理都算），并给出前后差距。
   只写"用了卷积网络，效果不错" → 不通过。
3. `model` 与 `metrics` / `training` 自洽：例如声明"直接用 64 个像素、未做任何处理"却在 case02 报 0.9 以上 → 不通过。
4. `macro_f1` 高于参考水平 0.08 以上且 `notes` 未给出可核对解释 → 判为可疑（疑用测试集调结构或标签泄漏）→ 不通过。
5. `baseline` 必须是"64 个像素直接进线性分类器"且在同一测试集上算；拿训练过的模型当基线、或用训练集算 → 不通过。

口径：键序 / 缩进 / 空白 / 小数位差异不扣分；`score` = 达成程度（任一项不成立时 ≤0.5）；
rationale 用中文、一句话（≤60 字），不通过时指出具体哪一项。
