# 手写数字分拣 Skill（你的方案）

> **本实验是应用任务，不是"按口径写代码"**：给你一个真实需求（把扫描表单里的手写数字分拣对），
> **网络结构、通道数、优化器、epoch 数、要不要做数据增强都由你自己决定**。没有唯一答案 ——
> 达标看的是"**macro F1 与逐档召回达标** + 你能不能**说清怎么处理扫描偏移**"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | 业务背景 + 三条要求 + 达标线 + 数据字典 + 交付格式 |
| `judge.md` | 判据：哪些项会被核对（含"怎么处理扫描偏移"） |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案） |
| `cases/case01`、`cases/case02` | 两批扫描件（质量好 / 质量差），自测用 |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 每一档都要认出来（串档最贵） | 心里有数 |
| ② **看一眼数据 + 画图** | 逐档样本数、缩略图长什么样、有没有偏移迹象 | `figures/` 里第 1 张图 |
| ③ 定基线 | 上一版系统（像素直接进线性分类器）在同一测试集上的成绩 | 报告的 `baseline` |
| ④ **训练模型 + 画图** | 还原成 8×8 → 训练卷积网络（考虑要不要增强），逐轮记录 loss/val_loss，画训练曲线 | 报告的 `training`、第 2 张图 |
| ⑤ **评估 + 画图** | macro F1 / 逐档召回 + 10×10 混淆矩阵 | 报告的 `metrics`、第 3 张图 |
| ⑥ **写结论** | 怎么处理偏移、和基线比如何、哪一档最弱、还有什么不足 | 报告的 `figures` / `notes` |

材料配合：`task.md`（需求）→ 读 `reference/`（一份**走完这六步**的示范）→ 回 `scripts/train.py` 走自己的六步 → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **怎么把数据喂给模型**：64 个数排成一行，还是还原成 8×8 图像？差别在哪？
2. **用什么结构**：为什么卷积比全连接更适合图像？池化起了什么作用？通道数开多少合适？
3. **要不要数据增强**：case02 的图告诉你什么？增强会不会伤到 case01？怎么折中？
4. **看哪个指标**：为什么本任务不能只看 accuracy？`macro F1` 与逐档召回分别揭示什么？
5. **训练怎么控**：学习率、epoch 上限、早停 patience、取哪一轮的权重。

## 交付

按 `task.md` 的「交付格式」产出 `output.json`：
`model` / `n_train` / `n_test` / `metrics{macro_f1,accuracy,per_class_recall[10]}` /
`baseline{name,macro_f1,accuracy}` / `training{history,epochs_run,best_epoch,early_stopped}` /
`figures[≥3 张]` / `notes`。

## 自测

两个 case 都要跑，并对照 `task.md` 的达标线自己核一遍：

```sh
for c in cases/*/; do
  python3 scripts/train.py "$c" /tmp/out_$(basename "$c").json
done
```

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段，再回来改自己的实现。
