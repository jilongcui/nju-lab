# skill-easy —— 入门实验：把检验判定写成脚本（口径与边界 · 容易）

> 对应课程章节：**技能 Skill 的创建与使用**（动手实践：先跑通判定脚本、再写自己的 SKILL.md）。
> 难度 **easy**：一张区间表 + 一张报告单，只用 Python 标准库 + `matplotlib`。

## 场景与数据

- 应用："这一项高不高、要不要紧"的确定性判定 —— 模型负责解释，脚本负责判。
- 数据：`problem/cases/case01`（10 行报告单）、`case02`（12 行），各带 `report.csv` + `reference_ranges.csv`；
  case01 有 1 个表外项目（`FT4`），case02 有 1 行空值（`HBA1C`）。
- 造题：`tools/gen_cases.py`（固定数据、可重跑；**不下发**）。

## 判据设计要点

1. **边界单独判**：危急值用闭区间 —— case01 的 `K 6.2`、`GLU 2.8` 恰好等于阈值，写成 `>` 就漏报，
   `manifest` 里有一条断言专门数"value === threshold 的危急条目"。
2. **无依据不许猜**：表外项目与空值一律 `unknown`，且 `unknown` 不能同时是 `critical`。
3. **逐项可比**：`items` 与 `report.csv` **行序一致**，只比 `item/value/flag/critical` 四个字段
   （`reason` 留给语义判据，避免逐字比对误杀）。
4. **防退化**：把边界写成 `>` 会漏 2 条危急值；把表外项目判成 `normal` 会让 `unknown` 计数不对 —— 都被抓。
5. **口径钉死**：七条判定顺序、flag 取值、`critical_alerts` 的 `side` 都写进 `task.md`。

## 项目字段文案（建项目时用）

- **title**：入门实验：把检验判定写成脚本（口径与边界 · 容易）
- **difficulty**：`easy`
- **content**（学生详情页首屏；不写"你的任务"）：
  "这一项高不高、要不要紧"是检验报告解读最基础的一步。让模型直接判断，同一份单子会得到三种说法；
  这个实验要求你把判定写成脚本：查参考区间表、比大小、按口径给出唯一的 flag，并逐条说出依据。
- **objectives**：
  1. 能把"偏高 / 偏低 / 危急"这套口径实现成确定性代码；
  2. 知道危急值为什么要用闭区间、参考区间为什么用严格不等；
  3. 知道没有区间依据时必须判 `unknown`，不许猜。
- **background**（每条 = 概念 + 一句人话解释）：
  - **参考区间**：每个检验项目有上下限，落在区间内算正常。
  - **危急值**：必须尽快处理的结果，本表给出上下阈值；命中要立刻提示就医。
  - **闭区间 vs 严格不等**：危急值"等于也算"（宁可多提醒），参考区间"等于算正常"。
  - **unknown**：区间表里没有、或报告单没填数值 —— 没依据就不判，这是医疗场景的底线。
  - **确定性下沉**：判定交给脚本，模型只做解释 —— 同一份单子每次得到同一个 flag。
- **description**：
  1. 读实验内容与 `task.md` 的七条判定顺序、两条边界；
  2. 读两张表，先把"空格 = 该侧不判"处理对；
  3. 实现 `judge()`：先查表、再判危急、再判高低；
  4. 跑两个 case，重点看 `K 6.2`、`GLU 2.8`（等于阈值）与 `FT4`（表外项目）；
  5. 画 flag 计数柱状图（轴标签英文），填 `report.md`（六节，含踩坑 ≥1 条）。

## 实测记录（出题时）

- 参考实现两个 case 全对：`items` / `critical_alerts` / `summary` 与 `expected.json` 一致；
- case01：10 行 → 9 项判定 + 1 unknown（`FT4`）；危急 4 条（其中 2 条恰好等于阈值：`K 6.2`、`GLU 2.8`）；
  六类计数 3 / 1 / 1 / 2 / 2 / 1；
- case02：12 行 → 10 项判定 + 2 unknown（`HBA1C` 空值、`XX` 表外）；危急 5 条（全部恰好等于阈值）；
  六类计数 4 / 1 / 0 / 3 / 2 / 2。
