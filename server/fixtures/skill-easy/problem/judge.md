# 评分细则（语义判据）

> 硬性条件由 `manifest.json` 的 `assertions` 判定（逐项 flag、危急清单、计数、两条边界、图、notes）。
> 这里只判**语义**，任一项不成立 → 不通过。

1. **`notes` 是不是自己写的**：要说清"为什么判定要下沉给脚本"（模型会说'偏高/略高'，脚本只有一个 flag），
   并点出两条边界（危急值闭区间、无依据不许猜）。空话 → 不通过。
2. **边界是否真理解**：case01 的 `K 6.2` 恰好等于危急阈值，必须报警；如果写成 `>` 就会漏掉它。
   报告里要能说出"等于也算"的理由（宁可多提醒，不可漏）。
3. **`reason` 是否带依据**：每项的 `reason` 要写出比较的对象（阈值或区间），不能只写"异常"。
4. **表外项目是否被猜了**：`FT4`（区间表里没有）必须 `unknown`；若被判成 `high`/`normal`，说明在猜。
5. **图是否"看图说话"**：`takeaway` 要说出危急几项、unknown 几项，与 `summary.counts` 矛盾 → 不通过。
6. **是否手抄预期值**：如果 `items` 行序与 `report.csv` 不一致（例如把 unknown 排到后面），→ 不通过。
