## 3. 基线与对照

- 基线做法：让模型直接读报告单口头判断
- 基线会错在哪：同一份单子措辞每次不同；`K 6.2` 恰好等于危急阈值这种边界最容易被说成"略高"
- 我的结果 / 基线：6 类 flag 逐项确定，边界项 2 条与 5 条都抓到了

## 4. 踩坑记录（每条行一行，平台按行计数）

1. 危急值必须用 `>=` / `<=`：`K 6.2`、`GLU 2.8` 恰好等于阈值，写成 `>` 就漏报
2. 参考区间用严格不等：`WBC 9.5` 恰好等于上限，算正常不算偏高
3. 区间表里没有的项目（`FT4`）要判 `unknown`，不能"看起来正常"就写 `normal`
4. 空值行（case02 的 `HBA1C`）也是 `unknown`，`value` 写 `null`
5. 图里不能写中文（复验镜像没有中文字体），轴标签英文、中文进 `takeaway`

## 5. 结论

两个 case 的逐项判定、危急清单与计数都与参考一致。判定必须下沉给脚本：模型能给"偏高/略高/需要关注"三种
都对但都不能用的说法，脚本只能给一个 flag。两条边界是成败关键 —— **危急值闭区间**（宁可多提醒不可漏）、
**无依据不许猜**（表外项目与空值一律 unknown）。把这两条写错，报告看起来一样通顺，临床上却会漏掉危急值。
