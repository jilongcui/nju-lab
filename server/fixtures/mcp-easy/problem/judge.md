# 评分细则（语义判据）

> 硬性条件由 `manifest.json` 的 `assertions` 判定（逐条响应、工具发现、统计、两条边界、图、notes）。
> 这里只判**语义**，任一项不成立 → 不通过。

1. **`notes` 是不是自己写的**：要说清 `isError`（工具**正常回答**但结果是"查不到/失败"）与 `error`
   （请求本身不合法：工具名错、缺参数、方法不认识）是两件事，并说明混用会让客户端怎么误判。空话 → 不通过。
2. **通知是否真被"不回"**：`notifications/initialized` 那条必须 `responded:false`、`response:null`；
   如果学生给它回了一条（常见错：忘了 `id` 为空就回），说明没理解 JSON-RPC 的通知语义。
3. **查不到 ≠ 崩溃**：`get_drug_info(布洛芬)` 必须是 `isError:true` 的 `result`，不是 `error`；
   写成 `error` → 不通过。
4. **错误码有没有混用**：未知工具与缺参数是 `-32602`，未知方法是 `-32601`；把两者都写成 `-32601` → 不通过。
5. **图是否"看图说话"**：`takeaway` 要说出正常回答/协议错误/不响应各几条，与 `stats` 矛盾 → 不通过。
6. **case02 的"加工具"**：`discovered.tools` 里必须出现 `query_labs`（且 `count = 3`）——
   这一条是在验证"工具清单是运行时问出来的，不是硬编码的"。
