## 3. 对照做法（偷懒解）

- 偷懒做法：对所有请求都回同一条 `initialize` 响应
- 它会错在哪：通知被错误地回了（多一条响应）、`tools/list` 问不出清单、5 条错误分类全丢
- 我的结果：逐条响应与参考一致，统计 9/8/1 与错误码 2/1 都能对上

## 4. 踩坑记录（每条一行，平台按行计数）

1. 通知（没有 `id`）一律不回；回了就是多一条响应，客户端会把它当成"没人要的应答"
2. 查不到药是 `isError: true` 的正常返回，不是 `error` —— 前者让模型换说法/换药，后者会让它以为请求写错了
3. 工具名错、缺参数都用 `-32602`；方法不认识才用 `-32601`
4. 相互作用要按两个药名排序后查表（阿司匹林+华法林 与 华法林+阿司匹林 是同一对）
5. 图里不能写中文（复验镜像没有中文字体），轴标签英文、中文进 `takeaway`

## 5. 结论

两个 case 的逐条响应、工具发现与统计都与参考一致。最关键的三个判断：**通知不回**、**isError ≠ error**、
**错误码分清**。`tools/list` 是运行时问出来的，所以 case02 多出一个 `query_labs` 时客户端一行都不用改 ——
这就是"一次构建、处处可用"的具体含义；反过来，如果工具清单是硬编码的，加工具就得改客户端。
