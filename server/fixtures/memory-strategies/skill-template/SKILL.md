# 记忆系统 Skill（你的方案）

> **本实验是应用任务，不是"按口径写代码"**：给你一个真实需求（随访助手要记得住、找得到、改得掉、忘得了），
> **代码怎么组织、图怎么画由你自己决定**。口径（条目格式 / category 顺序 / 阈值 / 检索）是"业务规则"
> （必须照做），达标看的是"**口径一致 + 更新/遗忘真的生效 + 说得清取舍**"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：业务背景、六步流程、抽取/更新/遗忘/策略/检索五套口径、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案；函数划分与你的骨架一致） |
| `cases/case01`、`cases/case02` | 两种规模（12 轮 / 16 轮），自测用（每个 case 有 `expected.json` 可以对照） |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 记得住、找得到、改得掉、忘得了：各自难在哪 | 心里有数（写进 `notes`） |
| ② **看懂口径** | 条目格式 / category 顺序 / 重要性 / 更新与遗忘阈值 / 检索口径 —— **都不许改** | 心里有数 |
| ③ **写入** | 哪些轮产生条目、编号怎么排、字段怎么填 | `memory.entries` / `entries_checksum` |
| ④ **更新与遗忘** | 旧条目失效并挂到新条目；按重要性/时效丢弃 | `updates` |
| ⑤ **三种策略** | 窗口 / 摘要 / 检索各算 `recall@k`，并算 before/after，画图 | `memory` / `metrics` / `updates.before_after` / `figures` |
| ⑥ **写结论** | 三种策略各解决什么、遗忘的代价、错误记忆的风险 | `notes` |

材料配合：`task.md`（需求 + 五套口径）→ 读 `reference/`（一份**走完这六步**的示范）→
回 `scripts/memory_assistant.py` 填掉你自己的 TODO → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **三种策略各自解决什么、代价是什么**：窗口省 token 但只留最近几轮；
   摘要压缩率最高但同类只留一条；检索命中率最高但依赖"提问与条目的用词能对上"。
   你的 `metrics` 里三个 `recall@k` 各是多少？为什么是这个顺序？
2. **更新为什么不能用"再写一条"代替**：如果旧条目还留在 `active` 里，检索会命中哪一条？
   对"患者现在用什么药"这种问题，答错一次会有什么后果？
3. **遗忘的代价有多大**：把你的 `before_after` 里差异最大的那一题找出来，说明差异来自哪一步
   （更新还是遗忘）。被遗忘的条目还能通过别的策略找回来吗？为什么？
4. **提问措辞会怎样影响检索**：把某一题的提问换一种说法（不含条目里的具体词），
   `recall_at_k_retrieval` 会掉吗？这说明这类记忆检索的天花板在哪里？

```sh
for c in cases/*/; do
  python3 scripts/memory_assistant.py "$c" "/tmp/$(basename "$c").json"
done
```

> 卡住了怎么办：先看 `reference/scripts/memory_assistant.py` 里对应的那一段，再回来改自己的实现。
