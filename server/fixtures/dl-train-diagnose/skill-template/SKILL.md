# 辅助筛查 Skill（你的方案）

> **本实验是应用任务，不是"按口径写代码"**：给你一个真实需求（把该查出来的恶性样本查出来），
> **网络结构、优化器、epoch 数、早停策略、判定阈值都由你自己决定**。没有唯一答案 ——
> 达标看的是"**recall / precision 达标** + 你能不能**说清训练过程**"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | 业务背景 + 三条要求 + 达标线 + 数据字典 + 交付格式 |
| `judge.md` | 判据：哪些项会被核对（含"训练曲线要说清过拟合"） |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案） |
| `cases/case01`、`cases/case02` | 两批数据（原始设备 / 另一台仪器），自测用 |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 把恶性样本查出来（recall 优先），同时不能把精确率搞塌 | 心里有数 |
| ② **看一眼数据 + 画图** | 行数、两类占比、**各列量纲差多少**、哪列最区分两类 | `figures/` 里第 1 张图 |
| ③ 定基线 | 现有做法（`mean_radius ≥ 15`）在同一测试集上的成绩 | 报告的 `baseline` |
| ④ **训练模型 + 画图** | 标准化 → 训练/验证划分 → 多轮训练，**记录逐轮 loss/val_loss**，画训练曲线 | 报告的 `training`、第 2 张图 |
| ⑤ **评估 + 画图** | 测试集 recall / precision + 混淆矩阵（漏报、误报各多少） | 报告的 `metrics`、第 3 张图 |
| ⑥ **写结论** | 每张图一句结论 + 整体判断（怎么处理过拟合、和基线比如何、还有什么不足） | 报告的 `figures` / `notes` |

材料配合：`task.md`（需求 + 流程）→ 读 `reference/`（一份**走完这六步**的示范，含它画的三张图与结论）→ 回 `scripts/train.py` 走自己的六步 → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **要不要标准化**：② 会看到各列量纲差几个数量级 —— 不做会怎样？先跑一遍看看（这是本实验最容易踩的坑）。
2. **网络怎么搭**：隐层宽度/层数、激活函数、dropout —— 为什么这么选？
3. **训练怎么控**：学习率、epoch 上限、早停 patience；**取哪一轮的权重**（最后一轮还是最优轮）？
4. **判定阈值**：默认 0.5；如果业务更怕漏报，要不要下调？下调后 precision 会怎么变？
5. **指标怎么读**：为什么本任务用 recall 而不是 accuracy？（② 的类别占比会告诉你答案）
