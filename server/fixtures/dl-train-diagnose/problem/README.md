# 题目包：来料自动分检（二分类 · 训练过程诊断）

> 这是本实验的**题目包** —— 一个真实需求（把该查出来的缺陷件查出来）、达标线、两批数据，
> 外加**一份示范实现**（`reference/`）供你对照学习。

## 这个实验要学什么

1. **训练过程要看得住**：神经网络不是"跑完就算"——要看**训练损失与验证损失怎么走**，
   从哪一轮开始过拟合，据此决定早停、正则化与"取哪一轮的权重"。
2. **预处理不是可选项**：各列量纲差几个数量级时，不标准化网络根本学不动（第二批数据尤其明显）。
   *先看数据，再决定怎么喂给模型*。
3. **基线（baseline）意识**：现有做法是"只看一个测量 + 固定上限"。它不需要模型 ——
   所以你的任务是**比它更可靠**，而不是"跑个神经网络"。
4. **不平衡数据的指标选择**：缺陷只占 22%~37%，accuracy 会骗人；主指标用 recall，
   再用 precision 防止"全报缺陷"这种退化解。
5. **可复现**：固定随机种子、写清切分与训练轮次，别人才能复核你的结论。

## 实验流程（六步）

`task.md` 里写了完整流程（① 看清需求 → ② 看一眼数据 → ③ 定基线 → ④ 训练模型 → ⑤ 评估 →
⑥ 写结论），`reference/scripts/train.py` 是一份**把这六步都走完**的示范（含它画的三张图与图注）
—— 照着走一遍，再换成你自己的做法。

## 两批数据

| case | 规模 | 特点 | 参考水平（现有做法 → 参考实现） |
|---|---|---|---|
| case01 | 569 行（缺陷 37%） | 原始设备、量程常规 | recall 0.72 / precision 0.86 → **0.96 / 0.98** |
| case02 | 320 行（缺陷 22%） | **另一台仪器**：量程差两个数量级、5% 测量噪声、样本更少 | recall 0.00 / precision 0.00 → **0.94 / 0.94** |

> `expected.json` 里的数值**不是标准答案**，而是"参考水平"：判据用它核对你的
> `baseline` 是否可信、并识别"可疑地过于好"的结果（例如拿测试集反复调参）。
> 你可以做得比参考实现更好，只要说清是怎么做到的。

## 自测方法

CLI 约定：`train.py <case_dir> <output.json>`（`<case_dir>` 里要有 `data.csv`）。

```sh
# 两个 case 都跑一遍，对照 task.md 的达标线（case01 recall ≥ 0.90、case02 ≥ 0.85；precision 都 ≥ 0.80）
for c in cases/*/; do python3 <你的skill>/scripts/train.py "$c" /tmp/out_$(basename "$c").json; done
```

脚本末尾会打印本轮成绩、基线与训练轮数。判据的其余各项（`training.history`、图的条数、
`notes` 长度）请对照 `judge.md` 自己核一遍。

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段。
