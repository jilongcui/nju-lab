# 应用任务：给科室文献库做一个"关键词检索"入口

## 业务背景

科室攒了一个**小文献库**（几十篇摘要，`corpus.csv`）。医生想按问题去找段落，现在只能靠肉眼翻。
要做的第一件事非常朴素：**给定一个问题，把最相关的几篇挑出来，并说清这个办法能做到什么、做不到什么**。

对文本做检索的经典方案是**倒排索引 + BM25 打分**（搜索引擎的核心）：先建"词 → 出现在哪些文档"的索引，
再用 BM25 给命中的文档打分排序 —— 词越稀有、出现越集中，得分越高。

这一章的核心论断是"**倒排索引搜得到字面，搜不到意思**"。实验就让你把这句话**量出来**：
同一批查询里，有些查询用的词和文档一样（应当命中），有些是**换了说法的改写**（关键词检索会漏）。
你会同时跑一个**字符 2-gram 基线**做对照 —— 它不建词表，只数字符碎片，正好把"不做长度归一化"的代价也暴露出来。

## 你的任务

用工作目录里的 `corpus.csv`（语料）、`queries.csv`（查询）、`qrels.csv`（哪些文档算相关）做一个
**可复现的检索方案**，产出 `output.json` 与一张图。具体要求：

1. **建倒排索引**：按下面的口径切词、建索引，并算出**词表校验和**（口径钉死，谁算都一样）；
2. **BM25 检索**：按写死的参数与公式打分，取 Top-3；
3. **跑一个字符 2-gram 基线**：口径同样是钉死的（**原始计数、不做归一化**）—— 它是"不建词表、也不做长度归一化"的对照组；
4. **算指标**：`recall@3`（整体 + 按查询类型分组），并**如实报出两类查询上的差距**；
5. **用图说清结论**：把两类方法在两类查询上的 `recall@3` 画成一张分组柱状图；
6. **说清边界**：`notes` 要讲清 BM25 的哪两个机制在起作用、为什么改写查询仍然搜不到、以及这个方案的局限。

> 代码怎么组织、函数怎么切都随你（**纯标准库**就够了：`csv` / `json` / `re` / `math` / `collections`；
> 画图用已预装的 `matplotlib`）。判据看的是：**索引口径一致 + 检索名单一致 + 两个指标对不对 + 说得清边界**。

## 索引口径（**逐字执行**，不许改）

**① 一份文档的检索文本 = `title` + 一个空格 + `text`。**

**② 切词**（对检索文本与查询都做同一套）：

1. 做 Unicode 兼容分解（NFKC）并转小写；
2. 按**非字母数字**字符切分（正则 `[^a-z0-9]+`）；
3. 丢掉长度小于 2 的词项（单个字符不算词）；
4. 丢掉下面的**停用词**：

```
a an the of in on for with and or to is are was were be been by as at from that this these those
it its may can should must than then over after before during into not no but if when which who
what how why does do did
```

**③ 索引**：`postings[词项][doc_id] = 该词在本文档出现的次数`（词频 tf）；
`doc_length[doc_id]` = 该文档切词后的词项**总数**（含重复）；
`n_docs` = 文档数；`vocab_size` = 索引里的**唯一词项数**。

**④ `postings_checksum`**（口径钉死，逐字节可复现）：把索引摊平成若干行

```
词项|doc_id|词频
```

按**词项升序**（ASCII）、同一词项内按 **doc_id 升序**排列；行与行之间用 `\n` 连接、**末尾不加换行**；
UTF-8 编码后取 sha256 十六进制字符串的**前 12 位**。

## 检索口径（**钉死**）

BM25 打分（参数 `k1 = 1.5`、`b = 0.75`）：

```
idf(词项) = ln(1 + (N - df + 0.5) / (df + 0.5))          # N = 文档数，df = 含该词项的文档数
score(文档) = Σ_{词项 ∈ 查询} idf(词项) * tf * (k1 + 1) / (tf + k1 * (1 - b + b * dl / avgdl))
```

其中 `tf` 是该词项在文档里的词频、`dl` 是该文档的词项总数、`avgdl` 是全部文档 `dl` 的平均值。

三条附加口径：

- **查询词项去重**：查询里同一个词出现多次，也只累加**一次**；
- 查询里出现的、索引中**不存在**的词项直接跳过（不参与打分，不是 0 分文档）；
- **Top-3**：按分数**降序**取前 3；分数**并列**时按 `doc_id` **升序**；不足 3 篇就返回全部。

## 基线口径（字符 2-gram，**钉死**）

对同一份检索文本与查询：

1. NFKC + 转小写后，**只保留 `[a-z0-9]` 字符**（其它字符全部删除，得到一串紧凑字符）；
2. 相邻两个字符算一个 2-gram（长度为 n 的串有 n-1 个 2-gram，按位置计数）；
3. **基线得分 = 查询的每个 2-gram 在文档中出现的次数，按查询 2-gram 的出现次数加权后求和**
   （即 `Σ_g count_query(g) * count_doc(g)`，**不做任何长度归一化**）；
4. 同样按分数降序取 Top-3，并列按 `doc_id` 升序。

> 为什么基线故意不做归一化？因为这样才看得出 BM25 的两个机制各自值多少钱：
> **词频饱和**（`k1`）和**长度归一化**（`b`）。基线文档越长、碎片越多，分数就越高 —— 长文档会把真正相关的那篇挤出去。

## 评估口径（**钉死**）

- 相关文档来自 `qrels.csv`（人工标注，"这篇确实回答了这个问题"）；
- `recall@3`（单个查询）= `|Top-3 ∩ 相关文档| / |相关文档|`；
- 报告的 `metrics.recall_at_3_bm25` / `recall_at_3_bigram` = **全部查询的平均值**（保留 6 位小数）；
- `metrics.by_type` 再按 `queries.csv` 的 `type` 列分组（`same_word` / `paraphrase`）各给一组平均值。

## 数据字典

| 文件 | 列 | 含义 |
|---|---|---|
| `corpus.csv` | `doc_id` | 文档号（`D01`…） |
| | `title` | 标题 |
| | `text` | 正文（几段虚构的英文医学摘要） |
| `queries.csv` | `query_id` | 查询号（`Q01`…） |
| | `query` | 查询文本 |
| | `type` | `same_word`（用词与文档相同）/ `paraphrase`（同一个意思换了说法） |
| `qrels.csv` | `query_id` / `doc_id` | 人工标注的"这篇回答了这个问题" |

> 语料是**虚构的教学数据**（英文，没有真实患者，也不是真实文献）。用英文是刻意的：
> 中文要先分词，而环境里没有分词器；英文按上面的口径切词，结果**谁算都一样**。

## 交付格式

**`output.json`**（写在工作目录下；**键名与层级按下面的样例写**）：

```json
{
  "index": { "n_docs": 12, "vocab_size": 154, "postings_checksum": "5cf9366e3cbe" },
  "retrieval": [
    { "query_id": "Q01", "top_k": [ { "doc_id": "D01", "score": 2.5123 }, { "doc_id": "D02", "score": 1.8044 } ] }
  ],
  "baseline": [
    { "query_id": "Q01", "top_ids": ["D08", "D03", "D04"] }
  ],
  "metrics": {
    "recall_at_3_bm25": 0.875,
    "recall_at_3_bigram": 0.0,
    "by_type": {
      "same_word": { "bm25": 1.0, "bigram": 0.0 },
      "paraphrase": { "bm25": 0.75, "bigram": 0.0 }
    }
  },
  "figures": [
    { "path": "figures/recall_by_query_type.png", "takeaway": "……（一句话结论，数字要与 metrics 自洽）" }
  ],
  "notes": "……（≥60 字：口径与做法、BM25 的哪两个机制在起作用、改写查询为什么仍然搜不到、局限）"
}
```

- `retrieval` 按 `query_id` 升序，`top_k` 里每项都要有 `doc_id` 与 `score`（**分数保留 4~6 位小数即可**）；
- `baseline[].top_ids` 是**只有 doc_id** 的数组（基线的分数不必报）；
- 图至少 1 张：`path` + 一句 `takeaway`（结论要"看图说话"，并与 `metrics` 自洽）；
- 报告里的数值**不需要**和任何人一致 —— 只要口径对，它们**本来就该相同**；口径错了就会不一样。
