评分细则（**应用任务：倒排索引 + BM25 检索**）

⚠️ 索引口径（切词、停用词表、校验和方式）、检索口径（BM25 参数与公式、并列规则）、
基线口径（字符 2-gram 原始计数）与评估口径都已在 `task.md` 里钉死，所以**词表大小、校验和、
每个查询的 Top-3 名单、两个 `recall@3` 都是确定的**。这些已由平台用**确定性断言**判定
（见 `manifest.json` 的 `assertions`）：字段完整、索引规模、校验和、两个名单、两个指标、
按类型分组的指标、对照成立、分数降序、图与 `notes` 长度。断言未通过的结果**不会交给你判**，
你不必重算这些数字。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否讲清了 BM25 的两个机制**：要说清**词频饱和**（`k1`：一个词出现 10 次不该比出现 3 次
   强三倍）与**长度归一化**（`b`：长文档不该因为"字数多、碎片多"就占便宜），以及 `idf` 让稀有词
   （例如药名）权重更高。只说"BM25 比关键词好""用了经典算法"这类空话 → 不通过。
2. **是否解释清了"改写查询为什么仍然搜不到"**：要落到机制上 —— 倒排索引里根本没有那些**词项**
   （"blood thinning" 不是 "antiplatelet"、"metal scaffold" 不是 "stent"），所以命中 0 篇；
   而不是笼统地说"语义没理解"或者"数据太少"。把这件事说成"索引没建好 / 参数没调好" → 不通过。
3. **`figures[].takeaway` 是否"看图说话"且与 `metrics` 自洽**：结论里的数字（两类方法在两类查询上
   各是多少）必须与报告的 `metrics` 一致（**允许四舍五入**）；只写"我画了一张柱状图"、
   或结论与数字矛盾 → 不通过。
4. **有没有正视这个方法的局限**：至少要给出**一条真实的局限**（例如没有词干还原/复数处理、
   没有同义词扩展、否定句会被误命中 —— "否认糖尿病史"仍会命中"糖尿病"、停用词表是写死的、
   中文还需要分词器），并说明下一步该怎么补（例如向量检索 / 同义词表）。
   只复述题干、只堆字段名、把 `notes` 写成运行日志 → 不通过。

判定口径：
- 键序、缩进、空白、小数位差异不扣分。口径与数值**由断言负责**，你不必复核；
  你只管「解释是否落到机制上」与「结论是否与数字自洽」。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
