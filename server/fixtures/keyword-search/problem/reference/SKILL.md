# 关键词检索 Skill（参考实现 · 学习示范）

> 📖 这份实现**随题目包一起下发**（`problem/reference/`），是给你的**示范** —— 不是标准答案。
> 判据只看"索引口径一致 + 检索名单一致 + 两个指标对不对 + 说得清边界"，所以函数怎么切、
> 图怎么画都随你；换一种写法只要口径一致就能通过。

## 能力边界

- 能处理：`corpus.csv` + `queries.csv` + `qrels.csv` 这套固定结构的输入（英文语料）
- 能处理：任意文档数（索引与打分都是线性扫描，教学规模下足够快）
- 能处理：同一个查询集上跑多个方法（BM25 与字符 2-gram）并算指标
- 不处理：**中文语料**（环境里没有分词器，也没法联网装）
- 不处理：词干还原 / 复数归一 / 同义词扩展 / 拼写纠错（所以"换了说法"的查询必然漏）
- 不处理：否定（"否认糖尿病史"仍会命中"糖尿病"）、短语顺序、字段权重

## 方法（六步 —— 与 `task.md` 的流程一致）

1. **看清需求** —— 命中定义在 `qrels.csv` 里；要说清方法的天花板
2. **看懂口径** —— 切词、停用词表、BM25 参数、并列规则、基线口径**都不许改**
3. **建索引** —— `build_index` + `postings_checksum`（口径钉死 → 可逐字节复现）
4. **检索** —— `bm25_scores` + `rank`（分数降序、并列按 `doc_id` 升序）
5. **对照与评估** —— `bigram_counts` + `bigram_score` 跑同一个查询集，算 `recall@3`（含按类型分组）
6. **写结论** —— 一张按查询类型分组的图 + `notes`（机制 + 边界 + 局限）

产出结构（`output.json`）见 `task.md`；判据见 `judge.md`。

## 为什么这组对照值得跑（本章的教学点）

- **BM25 强在三个机制**：`idf`（稀有词权重高 —— 药名比 "patients" 值钱）、`k1` **词频饱和**
  （同一个词出现 10 次不该比 3 次强三倍）、`b` **长度归一化**（长文档不该靠"字数多"占便宜）；
- **字符 2-gram 基线弱在两处**：它连词都不是（只是碎片重叠，不会区分同词不同义），
  而且本实验让它**不做归一化** —— 长综述的碎片多、分数就高，把真正相关的那篇短文挤出去；
- **两类查询的差距就是本章那句话的量化**：`same_word` 查询 BM25 能满分命中；
  `paraphrase`（换了说法）查询两套方法都掉下来 —— 倒排索引里根本没有那些词项。
  越过这道坎要靠第 7 章的**向量检索**（按意思找，而不是按字面找）。

## 实测档案

- 自测时间：2026-10-10（参考实现复验 2/2 通过）
- 用例通过率：2/2
- 关键数字：
  - case01：12 篇文档 / 154 个词项（校验和 `5cf9366e3cbe`）；
    `recall@3`：BM25 **0.875**（same_word 1.0 / paraphrase 0.75）vs 字符 2-gram **0.0**
  - case02：24 篇文档 / 214 个词项（校验和 `2b737e9fc1ed`）；
    `recall@3`：BM25 **0.75**（same_word 1.0 / paraphrase 0.5）vs 字符 2-gram **0.0**
- 踩坑记录（pitfalls）：
  - 停用词表是**口径的一部分**：漏掉 `which` / `what` / `how` 这类疑问词，`vocab_size` 与校验和都会变
  - 校验和最容易错在**行序与末尾换行**：词项升序、同词项内 doc_id 升序、行间 `\n`、末尾不加
  - 并列必须按 `doc_id` 升序，否则同一个查询的 Top-3 顺序会抖动（分数相同但顺序不同）
  - 基线**不要"顺手"归一化**：一归一化就不是本实验要对照的那个做法了，名单会全变
  - 相关文档是**短而精准**的那篇，长综述只是干扰 —— 这正是"长度归一化值多少钱"的来源
