## 2. 各 case 的结果

## 3. 对照做法（偷懒解）

- 偷懒做法：更新时直接覆盖旧条目（等于删除）
- 它会错在哪：`final.rows` 少一条、`counts.superseded` 为 0，追溯链条断开
- 我的结果：旧条目保留为 `superseded`，能回答"当时系统以为在用二甲双胍"

## 4. 踩坑记录（每条一行，平台按行计数）

1. 更新一条已经 `superseded` 的条目要**跳过**：case02 的 `M02` 不能被更新成 `M02v2`
2. 遗忘只处理 `active`：`forget M02` 之后它仍是 `superseded`，不是 `forgotten`
3. 检索必须按 `status == "active"` 过滤，否则被遗忘的过敏史还会命中 —— 这是最危险的一条
4. 排序按 `id` 升序：`M03v2` 排在 `M04` 之前（字符串比较，不是"新条目排最后"）

## 5. 结论

两个 case 的逐步快照、检索结果与最终表都与参考一致。最容易错的是**更新与遗忘的边界**：更新是"作废 + 新增"
而不是删除，遗忘只处理 `active`；一旦把这两条写成"直接删/直接改"，就再也回答不出"当时系统以为是什么"。
检索每次都要过滤状态 —— 忘记这一步，被遗忘的过敏史还会被开方逻辑取到，临床上就是事故。
