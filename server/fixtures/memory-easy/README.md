# memory-easy —— 入门实验：给随访助手加一张记忆表（记忆 · 容易）

> 对应课程章节：**记忆系统 Memory**（动手实践：先跑一遍四操作、自己算一次 recall，再进实验）。
> 难度 **easy**：一张 JSON 表 + 6 个操作，只用 Python 标准库 + `matplotlib`。

## 场景与数据

- 应用：随访助手的记忆表 —— 一条记忆 = `{id, patient, fact, kind, status}`，状态只有 active / superseded / forgotten。
- 数据：`problem/cases/case01`（5 条种子 / 6 个操作）、`case02`（4 条种子 / 6 个操作，**种子里就有一条 superseded**），
  每个 case 两个输入文件：`memory_seed.json`、`ops.jsonl`（一行一个操作）。
- 造题：`tools/gen_cases.py`（固定数据、可重跑；**不下发**）。

## 判据设计要点

1. **逐步可判**：每个操作之后都留一版快照（`step`/`op`/`rows`），与 `expected.json` 逐步比对 ——
   "哪一步开始错"一眼能看出来。
2. **两条边界单独判**：更新一条**已作废**条目要跳过（case02 不能出现 `M02v2`）；
   遗忘一条已作废条目不能变成 `forgotten`（仍为 `superseded`）。
3. **行为性判据**：检索必须只取 active —— case01 第 6 步只剩 `M03v2`，若还取到 `M02`（遗忘）或 `M03`（作废）即失败。
4. **防退化**：把"更新"实现成"覆盖/删除"会让 `counts.superseded = 0`、`final.rows` 少行 —— 判据直接抓。
5. **口径钉死**：id 固定 `<旧id>v2`、检索按 `id` 升序（`M03v2` 排在 `M04` **之前**），否则同分顺序不稳定。

## 项目字段文案（建项目时用）

- **title**：入门实验：给随访助手加一张记忆表（记忆 · 容易）
- **difficulty**：`easy`
- **content**（学生详情页首屏；不写"你的任务"）：
  随访助手要学会"记住"：过敏史、在用药物、上次联系时间。记忆不是聊天记录，而是一张带状态的表 ——
  被更正的要留着可追溯，被遗忘的要真的取不到。这个实验让你把写入、检索、更新、遗忘四个操作各写一遍。
- **objectives**：
  1. 说清 active / superseded / forgotten 三种状态的含义与差别；
  2. 实现四个操作，并解释为什么"更新不是删除"；
  3. 知道检索必须过滤状态 —— 否则被遗忘的信息还会被用到。
- **background**（每条 = 概念 + 一句人话解释）：
  - **记忆表**：一条记忆就是一行（谁、什么事、哪一类、什么状态），检索按"患者 + 类别 + 状态"取。
  - **更新不是删除**：旧条目转成 `superseded` 留着，才能回答"当时系统以为是什么"。
  - **遗忘只处理 active**：已经作废的条目不用再"遗忘"一次，口径不写清实现必分叉。
  - **检索要过滤状态**：忘了这一步，被遗忘的过敏史照样会被开方逻辑取到。
  - **排序要写死**：检索结果按 id 升序，`M03v2` 在 `M04` 之前 —— 否则两个 case 顺序对不上。
- **description**：
  1. 读实验内容与 `task.md` 的四个操作口径、三条边界；
  2. 先跑 `case01`：实现 store / retrieve / update / forget，逐操作看快照；
  3. 再跑 `case02`：重点看"更新已作废条目要跳过""遗忘已作废条目不重复处理"；
  4. 画每步三种状态的堆叠柱状图（轴标签英文）；
  5. 填 `report.md`（六节，含踩坑 ≥1 条）。

## 实测记录（出题时）

- 参考实现两个 case 全对：`snapshots` / `retrievals` / `final` 与 `expected.json` 一致；
- case01：6 步后 active 5 / superseded 1 / forgotten 1；第 6 步检索只剩 `M03v2`；
- case02：第 1 步 update 已作废条目 → 跳过（无 `M02v2`）；第 2 步 forget 它 → 仍 `superseded`；最终 4 / 2 / 0。
