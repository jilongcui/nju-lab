# 会员价值分级 Skill（你的方案）

> **本实验是应用任务**：给你一个真实需求（把会员分成低/中/高三档，好分配运营资源）。
> **模型、特征、预处理都由你自己决定** —— 达标看的是"**三档是不是都分准了** +
> 能不能说清你的选择"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | 业务背景 + 四条要求 + 数据字典 + 交付格式 |
| `judge.md` | 判据：达标线（macro F1 / 逐档召回）、防退化项、会被核对的项 |
| `reference/` | 一份**示范实现** —— 先读它（尤其怎么预处理），再写你自己的 |
| `cases/case01`、`case02` | 两家门店 / 两个季度的数据，自测用 |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 三档都要分准（macro 视角）+ 任何一档都不能放弃 | 心里有数 |
| ② **看一眼数据 + 画图** | 行数、**三档各占多少**、量纲差异；并画出总览图 | `figures/` 里第 1 张图 |
| ③ 定基线 | 不做预测能做到多少（一律判多数类） | 报告的 `baseline` |
| ④ **训练模型** | 选一个能讲清楚的模型训练（不必做多方案对比） | 报告的 `model` / `metrics` |
| ⑤ 评估 | 找出"哪两档容易被搞混" | 报告的 `metrics` |
| ⑥ **写结论** | 每张图一句结论 + 整体判断（还有什么不足） | 报告的 `figures` / `notes` |

材料配合：`task.md`（需求 + 流程）→ 读 `reference/`（一份**走完这六步**的示范，含它比较过的方案、
各自成绩与踩到的坑）→ 回 `scripts/train.py` 走自己的六步 → 两个 case 都跑 →
补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **指标**：为什么这里不能只看 accuracy？macro F1 和它有什么不同？
2. **逐档召回**：光看 macro F1 够吗？如果业务上"高档漏判"最贵，你会怎么调整？
3. **预处理**：特征量纲差很多时会发生什么？试试不标准化、直接训练，看有没有警告。
4. **特征**：哪几列真的有用？想想每列的业务含义（数据字典见 `task.md`）。

## 交付

按 `task.md` 的「交付格式」产出 `output.json`：
`model` / `n_train` / `n_test` / `metrics{macro_f1, accuracy, per_class_recall[3]}` /
`baseline{name, accuracy, macro_f1}` / `notes`。

## 自测

两个 case 都要跑，看 macro F1 与逐档召回是否达标（`macro F1 ≥ 0.60` 且每档召回 `≥ 0.50`）：

```sh
for c in cases/*/; do
  python3 scripts/train.py "$c" /tmp/out.json
done
```

脚本末尾会打印 macro F1、逐档召回与是否达标。

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段，再回来改自己的实现。
