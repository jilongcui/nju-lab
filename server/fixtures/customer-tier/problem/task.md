# 应用任务：给会员分价值档位

## 业务背景

一家零售/服务平台想按会员的**价值**分成 **低 / 中 / 高** 三档，好分配不同的运营资源：

| 档位 | 运营策略 |
|---|---|
| 低 | 发优惠券促活 |
| 中 | 做复购提醒、推荐搭配 |
| 高 | 配专属客服、优先体验新品 |

**现有做法**：不做预测，**所有会员一律按"低档"处理**（反正大多数会员确实在低档）。

> 这个"现有做法"看起来准确率有 **40%**，但**中档和高档一个都没分出来** ——
> 后两档的运营策略完全落不了地。**多分类任务里，准确率同样会骗人**：
> 它被"人最多的那一档"主导，看不出你在人少的档位上做得有多差。

## 你的任务

用工作目录里的 `data.csv` 构建一个分档方案，产出 `output.json`，达到四条要求：

1. **三档都要分准**：测试集上 **macro F1 ≥ 0.60**。
   （macro 的意思是"先把每一档各自算一遍，再平均"——**不因为某档人多就多给权重**。）
2. **不要放弃任何一档**：**每一档的召回率都 ≥ 0.50**（每档里至少一半会员要被认出来）。
3. **可复现**：切分与训练用固定随机种子；产出里写清 `n_train` / `n_test`（测试集占比 20%~40%）。
4. **说清你的选择**：用了哪些特征、为什么、怎么判断模型行不行。

> 模型、特征、参数都由**你自己决定**。达标与否看上面四条是否真的做到（判据见 `judge.md`）。

## 数据字典（`data.csv`）

| 列 | 含义 |
|---|---|
| `monthly_spend` | 月均消费（元） |
| `visits_per_month` | 月均到店/下单次数 |
| `months_since_signup` | 注册至今月数 |
| `avg_order_value` | 客单价（元） |
| `support_tickets` | 近半年客服工单数（越多说明体验越差） |
| `tier` | **目标**：价值档位（`0`=低, `1`=中, `2`=高） |

> 数据是固定种子合成的教学数据。规律符合常识：消费/频次/客单价越高、注册越久、工单越少，价值越高。
> 三个档位的人数并不平均（大致 40% / 35% / 25%），这正是"要看 macro F1 而不是只看准确率"的原因。

## 交付格式（`output.json`，写在工作目录下）

```json
{
  "model": "你选择的模型名称",
  "n_train": 675,
  "n_test": 225,
  "metrics": { "macro_f1": 0.77, "accuracy": 0.77, "per_class_recall": [0.84, 0.71, 0.75] },
  "baseline": { "name": "majority_class", "accuracy": 0.40, "macro_f1": 0.19 },
  "notes": "先对特征做了标准化（各列量纲差很多，月均消费到几千、到店次数只有十几），再用多分类逻辑回归；主要信息来自月均消费与到访频次。"
}
```

- `metrics.per_class_recall` **必须**按 `0/1/2` 的顺序给出**每一档**的召回率（只给平均值不算）。
- `baseline` 是你**自己算出来的**现有做法成绩：把所有人都判成 `0`（低档）时的 `accuracy` 与 `macro_f1`。
  判据会核对它是否可信。
- 不需要和任何"标准答案"数值一致 —— 达标看的是"三档是不是都分准了"。

## 怎么算完成

1. 方案要普适：对任意一份同结构 `data.csv` 都能产出 `output.json`。
2. 两个 case（`cases/case01`、`case02`，两家门店/两个季度）**都要达标** —— 判据对每个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
