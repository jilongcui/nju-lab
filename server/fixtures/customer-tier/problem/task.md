# 应用任务：给会员分价值档位

## 业务背景

一家零售/服务平台想按会员的**价值**分成 **低 / 中 / 高** 三档，好分配不同的运营资源：

| 档位 | 运营策略 |
|---|---|
| 低 | 发优惠券促活 |
| 中 | 做复购提醒、推荐搭配 |
| 高 | 配专属客服、优先体验新品 |

**现有做法**：不做预测，**所有会员一律按"低档"处理**（反正大多数会员确实在低档）。

> 这个"现有做法"看起来准确率有 **40%**，但**中档和高档一个都没分出来** ——
> 后两档的运营策略完全落不了地。**多分类任务里，准确率同样会骗人**：
> 它被"人最多的那一档"主导，看不出你在人少的档位上做得有多差。

## 你的任务

用工作目录里的 `data.csv` 构建一个分档方案，产出 `output.json` 与你的图，达到四条要求：

1. **三档都要分准**：测试集上 **macro F1 ≥ 0.60**（macro = 先对每一档各自算一遍再平均，**不因某档人多就多给权重**）。
2. **不要放弃任何一档**：**每一档的召回率都 ≥ 0.50**。
3. **可复现**：切分与训练用固定随机种子；产出里写清 `n_train` / `n_test`（测试集占比 20%~40%）。
4. **用图把分析讲清楚**：看数据时画图、评估结果时画图，并**给每张图写一句结论**（`figures` 字段）。

> 模型、特征、预处理都由**你自己决定**（选一个你能讲清楚的即可，不必做多个方案的对比）。
> 达标与否看上面四条是否真的做到（判据见 `judge.md`）。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 三档都要分准（macro 视角）+ 任何一档都不能放弃 | 心里有数 |
| ② **看一眼数据 + 画图** | 有多少行、**三档各占多少**、各列量纲差多少；**画一张总览图**（三档分布？哪个特征最能区分档位？） | `figures/` 里第 1 张图 |
| ③ **定基线** | 不做预测能做到多少（一律判多数类） | 报告的 `baseline` |
| ④ **训练模型** | 选一个模型、固定种子分层切分后训练（**注意各列量纲差别很大**） | 报告的 `model` / `metrics` |
| ⑤ **评估 + 画图** | 算 macro F1 与逐档召回，并**画混淆矩阵**看"哪两档容易被搞混" | `figures/` 里第 2 张图 |
| ⑥ **写结论** | 每张图一句结论 + 整体判断（哪档最弱、还有什么不足） | 报告的 `figures` / `notes` |

> ② 和 ⑤ 的图都用 `matplotlib` 画（镜像已预装），存到工作目录的 `figures/` 下。
> ⚠️ 图里的**标题与坐标轴标签建议用英文**（运行环境没有中文字体，中文会显示成方框）；
> 中文解释写在 `takeaway` 与 `notes` 里。

## 数据字典（`data.csv`）

| 列 | 含义 |
|---|---|
| `monthly_spend` | 月均消费（元） |
| `visits_per_month` | 月均到店/下单次数 |
| `months_since_signup` | 注册至今月数 |
| `avg_order_value` | 客单价（元） |
| `support_tickets` | 近半年客服工单数（越多说明体验越差） |
| `tier` | **目标**：价值档位（`0`=低, `1`=中, `2`=高） |

> 数据是固定种子合成的教学数据。规律符合常识：消费/频次/客单价越高、注册越久、工单越少，价值越高。
> 三个档位的人数并不平均（大致 40% / 35% / 25%）。

## 交付格式（`output.json`，写在工作目录下）

```json
{
  "model": "你最终选择的模型名称",
  "n_train": 675,
  "n_test": 225,
  "metrics": { "macro_f1": 0.77, "accuracy": 0.77, "per_class_recall": [0.84, 0.71, 0.75] },
  "baseline": { "name": "majority_class", "accuracy": 0.40, "macro_f1": 0.19 },
  "figures": [
    { "path": "figures/data_overview.png", "takeaway": "三档人数不平均（约 40/35/25%）；月均消费在三档之间区分得比较开，而到访次数在高档里也有高有低。" },
    { "path": "figures/evaluation.png", "takeaway": "混淆矩阵里中档与高档之间有明显交叉（真实高档有一成多被判成中档），低档几乎不会被认错。" }
  ],
  "notes": "先画图确认三档不平均、各列量纲差别很大（月均消费到几千、到访次数只有十几），所以先做标准化再训练。用多分类逻辑回归，macro F1 0.77、三档召回都在 0.7 以上。不足：中档最弱，且与高档之间有混淆。"
}
```

- `metrics.per_class_recall` **必须**按 `0/1/2` 的顺序给出**每一档**的召回率（只给平均值不算）。
- `baseline` 是你**自己算出来的**现有做法成绩：把所有人都判成 `0`（低档）时的 `accuracy` 与 `macro_f1`。
- `figures` 至少两张：一张"看数据"（②）、一张"评估结果"（⑤，建议画 3×3 混淆矩阵），每张都要有 `path` 与一句 `takeaway`。
- 不需要和任何"标准答案"数值一致 —— 达标看的是"三档是不是都分准了"。

## 怎么算完成

1. 方案要普适：对任意一份同结构 `data.csv` 都能产出 `output.json` 与两张图。
2. 两个 case（`cases/case01`、`case02`，两家门店/两个季度）**都要达标** —— 判据对每个 case 各判一次。
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
