# 题目包：给会员分价值档位（多分类）

> 这是本实验的**题目包** —— 一个真实需求（把会员分成低/中/高三档好分配运营资源）、判据、两批数据，
> 外加**一份示范实现**（`reference/`）供你对照学习。

## 这个实验要学什么

1. **多分类问题长什么样**：标签有三档，混淆矩阵就是 **3×3** —— 你能一眼看出"哪两档容易被搞混"。
2. **为什么这里要看 macro F1，而不是只看准确率**：三档人数不平均（约 40% / 35% / 25%），
   准确率会被人数最多的"低档"主导；**"全判低档"这个不做预测的基线就有 40% 准确率**，
   但中档和高档一个都没分出来（它们召回率都是 0）。
3. **macro 视角**：先对每一档各自算一遍指标，再平均 —— 人少的档位不被淹没。
   （作业/业务上如果"高档漏判"代价最高，还可以进一步给高档更高的权重。）
4. **预处理会影响成败**：几列的量纲差很多（月均消费到几千、到访次数只有十几），
   某些模型不标准化就难以收敛 —— 这是很常见的一个坑。

## 实验流程（六步）

`task.md` 里写了完整流程（① 看清需求 → ② 看一眼数据 → ③ 定基线 → ④ 建模并比较 → ⑤ 评估 →
⑥ 写结论），`reference/scripts/train.py` 是一份**把这六步都走完**的示范 —— 其中第 ④ 步它比较了
三个方案（含"不标准化就上逻辑回归"这个常见坑），并把结果写进了 `notes`。照着走一遍，再换成你自己的做法。

## 包内有什么、怎么用

| 路径 | 是什么 | 建议怎么用 |
|---|---|---|
| `task.md` | 需求 + 四条要求 + 数据字典 + 交付格式 | **动手前先读** |
| `judge.md` | 判据：达标线（macro F1 / 逐档召回）、防退化项、语义核对项 | 交之前读一遍 |
| `reference/` | **示范实现**（标准化 + 多分类逻辑回归 + 基线对比） | 先读 `scripts/train.py`，再写自己的 |
| `cases/case01`、`case02` | 两家门店 / 两个季度的数据 + 参考水平 `expected.json` | 自测用 |

## 两批数据

| case | 规模 | 三档比例 | 参考水平（基线 → 参考实现） |
|---|---|---|---|
| case01 | 900 行 | 40% / 35% / 25% | macro F1 0.19 → 0.77（逐档召回 0.84 / 0.71 / 0.75） |
| case02 | 600 行 | 40% / 35% / 25% | macro F1 0.19 → 0.68（逐档召回 0.83 / 0.62 / 0.57） |

> `expected.json` 里的数值**不是标准答案**，而是"参考水平"：判据用它核对你的 `baseline` 是否可信、
> 并识别"可疑地过于好"的结果。你可以做得比参考实现更好，只要说清是怎么做到的。

## 自测方法

CLI 约定：`train.py <case_dir> <output.json>`（`<case_dir>` 里要有 `data.csv`）。

```sh
# 两个 case 都跑一遍，看是否达标（macro F1 ≥ 0.60 且每一档召回 ≥ 0.50）
for c in cases/*/; do python3 <你的skill>/scripts/train.py "$c" /tmp/out.json; done
```

脚本末尾会打印三项：macro F1、逐档召回、是否达标。判据里的其余各项（结构、切分占比、
baseline 定义、`notes`）请对照 `judge.md` 自己核一遍。

> 卡住了怎么办：先看 `reference/scripts/train.py` 里对应的那一段 —— 尤其是它**怎么预处理**。
