评分细则（**应用任务：达标判定**）

⚠️ 模型、特征、参数由学生自选，**输出数值不要求等于参考水平**（`expected.json` 里给的是"参考水平"）。

**硬性条件已由平台用确定性断言判定**（见 `manifest.json` 的 `assertions`）：字段完整、
`macro_f1` / `accuracy` 在 [0,1]、**逐档召回率齐全（3 档）**、切分覆盖全部样本、测试集占比 20%~40%、
基线定义正确（现有做法准确率 ≈ 多数类占比、`macro_f1` < 0.4）、**达标线 `macro_f1 ≥ 0.60`**、
**防退化：每一档召回率 ≥ 0.50**、`notes` ≥20 字。断言未通过的结果**不会交给你判**。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否体现了完整流程**：是否能看到 ① 对数据的一点观察（**三档各占多少**、量纲差异）
   ② **方案比较（至少两个方案及各自的 macro F1 / 逐档召回）** ③ 最终选择与理由 ④ 对结果的一个判断
   （哪两档容易混、还有什么不足）。空洞小结（"使用了机器学习模型，效果良好"）、
   与 `model` 字段矛盾、或只是复述题目 → 不通过。
2. **`model` 与 `metrics` 是否自洽**：例如声称"未做任何预处理、直接用默认参数"却报出只有标准化后才可能达到的
   指标；或 `per_class_recall` 与 `macro_f1` 明显矛盾（例如某一档召回 0.1 却报 `macro_f1` 0.9）→ 不通过。
3. **是否可疑地过于好**：`macro_f1` 高于参考水平 0.15 以上且 `notes` 未给出可核对的解释
   → 判为可疑（疑似用测试集反复调参）→ 不通过。
4. **`baseline` 的语义是否正确**：应表示"不做预测、一律判为多数类"（`accuracy` ≈ 多数类占比、
   `macro_f1` 很低）。若学生拿一个训练过的模型当基线（故意拉低参照）→ 不通过。

判定口径：
- 键序、缩进、空白、小数位差异不扣分；数值比较只按上面写明的容差与阈值。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
