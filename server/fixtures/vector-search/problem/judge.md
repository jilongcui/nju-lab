评分细则（**应用任务：向量化 + Top-K 检索 + 增删改查**）

⚠️ 向量化口径、检索口径、对照口径都已在 `task.md` 里钉死，所以 Top-3 名单与 recall 是**确定的**。
这些数值（维度/条数、两种检索的 Top-3、recall、增删改条数、更新后与过滤后的检索结果）已由平台用
**确定性断言**判定（见 `manifest.json` 的 `assertions`）。断言未通过的结果**不会交给你判**，
你不必重算这些数字。

你只需要判断以下**语义**问题（任一项不成立 → 不通过）：

1. **`notes` 是否讲清了机制**：要说出"同义词落进同一维 → 矢量相近 → 余弦大"这条因果链，
   以及**为什么关键词检索在改写查询上会漏**（它不做同义扩展，字面不重叠就打不着）。
   以下情况**不通过**：只复述题目、只说"向量检索更好"却不解释为什么、
   或把机制说错（例如声称"向量检索做了词形还原/分词"）。
2. **`notes` 是否讲清了增删改查里"改写要重算向量"**：改文本不重算向量 → 检索还按旧文本给分，
   这是向量库最容易踩的坑。没提到这一点、或声称"改文本不用动向量" → 不通过。
3. **是否说清方案的局限**：词表是人写的（没收录的说法搜不到、同义词表覆盖不到就失效）、
   真实场景要用训练好的 embedding 模型。只说优点、看不出有任何局限 → 不通过。
4. **`figures[].takeaway` 是否"看图说话"且与 `metrics` 自洽**：图里的两个数字必须与
   `metrics.recall_at_3_vector` / `recall_at_3_keyword` 一致；只写"我画了对比图"、数字对不上 → 不通过。

判定口径：
- 键序、缩进、空白、`kind` 字段的有无不扣分。
- 结论里引用 recall 等数字时**允许四舍五入**：`metrics` 是 `0.4345` 时，`takeaway`/`notes` 写
  `0.43`、`43%`、`0.4345` 都算一致 —— **不要把两位小数当成"数字对不上"**（断言已负责精确数值）。
- `score` = 上述语义项的达成程度（0~1）；任一项不成立时 score 不超过 0.5。
- rationale 用中文、**一句话（≤60 字）**说清结论；不通过时指出具体是哪一项。
