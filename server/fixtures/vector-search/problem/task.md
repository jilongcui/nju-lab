# 应用任务：给病例库做一个"按意思找"的检索

## 业务背景

上一章的文本检索能"找到文档"，但它只认字面：搜「心梗」找不到写着「心肌梗死」的病历，
口语化的主诉（"老人跌倒后站不起来"）更是一条都搜不到 —— **同一个意思，换个说法就检索不到**。

向量数据库就是治这个的：把每段文本变成一串数字（**向量**），语义相近的文本在向量空间里距离就近；
检索时算一下相似度，取最像的几条。这次你自己动手把这条链条走一遍：

> **文本 → 向量 → 存进库 → 算余弦相似度取 Top-K → 和"关键词检索"对照**

工作目录里有一批**虚拟病例/指南条目**（`corpus.csv`）、一组**查询**（`queries.csv`）、
一份**概念词表**（`concepts.json`，就是你的"embedding 模型"）、一份**更新单**（`updates.json`）。

## 你的任务

写一个可复现的检索方案，产出报告 `output.json` 与一张图，达到四条要求：

1. **按 `concepts.json` 的口径做向量化**（下面写死了），把每条语料变成一个向量存起来；
2. **检索**：对 `queries.csv` 里每条查询算相似度，取 **Top-3**；
3. **做一次对照**：同一批查询也用**关键词检索**（字符 2-gram，口径见下）跑一遍，
   算两者各自的 **recall@3**（相关文档在 `queries.csv` 里标好了），并说清"为什么差这么多"；
4. **增删改查**：按 `updates.json` 新增一条语料、改写一条（**向量必须重算**）、删除一条，
   再做一次**带科室过滤**的检索。

> ⚠️ 真实场景的向量来自训练好的 embedding 模型。这里为了让实验**离线、可复现、看得见原理**，
> 用一份**人写的概念词表**当"模型"：每个概念占向量的一维，它的同义词都算这一维。
> 于是「心梗」和「心肌梗死」自然落进同一维 —— 这正是 embedding 在做的事，只不过真实模型是学出来的。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 要解决的是"字面不同、意思相近"的检索；关键词检索为什么不够 | 心里有数 |
| ② **回头看概念** | 向量化是怎么回事：为什么同义词要落进同一维、L2 归一化是干什么的 | 报告的 `index` |
| ③ **建立向量库** | 把每条语料变成向量存起来（list / numpy / 存文件都行） | 报告的 `index` |
| ④ **检索 + 对照** | 余弦 Top-3；再用关键词检索跑一遍同一批查询 | 报告的 `retrieval` / `keyword_baseline` |
| ⑤ **增删改查** | 新增 / 改写（重算向量）/ 删除 / 带科室过滤的检索 | 报告的 `crud` |
| ⑥ **评估 + 写结论** | 算 recall@3 对比、画一张对比图、说清机制与局限 | `metrics` / `figures` / `notes` |

> 图用 `matplotlib`（已预装）画，存到工作目录的 `figures/` 下，例如
> `plt.savefig("figures/recall_comparison.png", dpi=110)`。
> ⚠️ **图上的标题与坐标轴标签必须用英文**：运行环境里没有中文字体，中文会渲染成方框。
> 中文解释写在 `figures[].takeaway` 与 `notes` 里。

## 向量化口径（**逐字照做**，`concepts.json` 里也写了一遍）

1. 文本转**小写**；
2. 对词表里的第 i 个概念，累加它**全部同义词**在该文本中出现的次数（**子串计数**，出现几次算几次）；
3. 得到一个 `dim` 维向量；用 **L2 归一化**（除以自身模长）；模长为 0 时取零向量；
4. **相似度 = 两个已归一化向量的点积**（这就是余弦相似度）；零向量与任何向量的相似度记为 0。

## 检索口径（两种都照做）

| | 口径 |
|---|---|
| **向量检索** | 对每条查询算出向量 → 与库里每条向量算相似度 → 取 **Top-3**；**只返回相似度 > 0 的结果**（没命中就少返回，不硬凑 K 条）；相似度相同按 `doc_id` 升序 |
| **关键词对照** | 把查询文本转小写，取**相邻两个字符**组成的全部 2-gram（**去重**）；文档得分 = 这些 2-gram 在文档文本（小写）中出现的**总次数**；同样 Top-3、只返回得分 > 0 的、同分按 `doc_id` 升序 |
| **recall@3** | 对每条查询：`命中 = Top-3 与该查询标注的相关文档的交集大小 / 相关文档总数`；只对**标了相关文档**的查询求平均（`unrelated` 查询没有标注，跳过），保留 4 位小数 |

> `queries.csv` 的 `kind` 有三类：`same_words`（用文档里出现过的说法）、
> `paraphrase`（**换成同义词**，字面完全不同）、`unrelated`（与语料无关）。
> 改写类查询就是这次对照的关键 —— 关键词检索在它们身上会漏得很难看。

## 增删改查口径（`updates.json`，**在检索跑完之后执行**）

| 字段 | 语义 | 你要做的 |
|---|---|---|
| `add_docs` | 新增语料 | 入库 + 算向量 |
| `update_docs` | 改写某条语料的文本 | 改文本 **并重算它的向量**（不重算，检索还按旧文本给分） |
| `delete_docs` | 删除某条语料 | 从库/索引里移除（之后的检索不能再出现它） |
| `filter_query` | 带元数据过滤的检索 | 用 `query_id` 的查询文本，在该 `dept` 的语料里取 Top-3 |

更新单执行完之后，再对**前两条查询**重跑一次向量检索（结果写进 `crud.post_retrieval`）——
这条是给你自己看的：新增/改写/删除是不是真的反映到检索结果里了。

## 数据字典

| 文件 | 列 | 含义 |
|---|---|---|
| `corpus.csv` | `doc_id` | 语料编号（`D001`…） |
| | `text` | 语料正文（虚拟病例/指南条目） |
| | `dept` | 所属科室（元数据，用于"带过滤的检索"） |
| `queries.csv` | `query_id` | 查询编号（`q1`…） |
| | `text` | 查询文本 |
| | `kind` | `same_words` / `paraphrase` / `unrelated` |
| | `relevant_doc_ids` | 人工标注的相关文档（`\|` 分隔；`unrelated` 为空） |
| `concepts.json` | `dim` | 向量维度（= 概念个数） |
| | `concepts[].name` / `concepts[].terms` | 概念名与它的同义词列表 |
| `updates.json` | — | 增删改单（见上表） |

> 数据是固定种子生成的**虚构**教学语料（没有真实患者），但构造方式符合真实情况：
> 一条语料常同时提到几个概念，同一个概念在不同语料里用不同说法。

## 交付格式

**`output.json`**（写在工作目录下；**键名与层级按下面的样例写**）：

```json
{
  "index": { "dim": 12, "n_docs": 40, "n_docs_after_crud": 40 },
  "retrieval": [
    { "query_id": "q1", "kind": "same_words", "top_k": [{ "doc_id": "D033", "score": 0.7071 }] }
  ],
  "keyword_baseline": [
    { "query_id": "q1", "top_k": [{ "doc_id": "D033", "score": 3 }] }
  ],
  "metrics": { "recall_at_3_vector": 0.6464, "recall_at_3_keyword": 0.1278, "n_queries_evaluated": 6 },
  "crud": {
    "added": 1, "updated": 1, "deleted": 1, "n_docs_final": 40,
    "post_retrieval": [{ "query_id": "q1", "top_k": [{ "doc_id": "D033", "score": 0.7071 }] }],
    "filtered": { "query_id": "q2", "dept": "心内科", "top_k": [{ "doc_id": "D018", "score": 1.0 }] }
  },
  "figures": [
    { "path": "figures/recall_comparison.png", "takeaway": "向量检索 recall@3 为 0.65，关键词只有 0.13；改写过的查询字面几乎不重叠，关键词基本搜不到。" }
  ],
  "notes": "向量化用词表打分的玩具版 embedding：12 个概念各占一维，同义词表让「心梗」和「心肌梗死」落进同一维……"
}
```

- `retrieval` / `keyword_baseline` 的顺序与 `queries.csv` 一致；每条查询的 `top_k` 按相似度降序。
- `crud` 的 `added` / `updated` / `deleted` 是**实际生效**的条数。
- 图至少 1 张：`path` + 一句 `takeaway`（要"看图说话"，并与 `metrics` 自洽）。

## 怎么算完成

1. 写一个能跑的方案（推荐做成 Skill 里的一段脚本），能对任意一份同结构的语料 + 查询 + 词表 + 更新单
   产出 `output.json` 与一张图。
2. 在 `cases/case01` 与 `cases/case02`（两批不同规模、不同维度的数据）上都能跑通 —— 判据对两个 case 各判一次。
3. 把结论与"为什么关键词会漏"写进 `SKILL.md` 的「实测档案」。
