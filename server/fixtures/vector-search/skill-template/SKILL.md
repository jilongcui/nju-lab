# 相似病例检索 Skill（你的方案）

> **本实验是应用任务**：给你一个真实需求（换个说法也找得到相似病例），
> **向量怎么存、索引怎么组织、代码怎么写由你自己决定**；向量化与检索口径是口径（必须照做），
> 达标看的是"口径一致 + 更新后索引真的变 + 能说清机制与局限"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：业务背景、六步流程、向量化/检索/对照/增删改查口径、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（函数划分与你的骨架一致） |
| `cases/case01`、`cases/case02` | 两批数据（不同规模/维度），自测用（各带 `expected.json` 可对照） |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 要解决"字面不同、意思相近"；关键词检索为什么不够 | 心里有数 |
| ② **回头看概念** | 为什么「心梗」和「心肌梗死」要落进同一维（词表就是最简的 embedding） | 报告的 `index` |
| ③ **建立向量库** | 每条语料 → 向量 → 存起来 | 报告的 `index` |
| ④ **检索 + 对照** | 余弦 Top-3 + 关键词检索跑同一批查询 | `retrieval` / `keyword_baseline` |
| ⑤ **增删改查** | 新增 / 改写（**重算向量**）/ 删除 / 带科室过滤检索 | 报告的 `crud` |
| ⑥ **评估 + 写结论** | recall@3 对比图 + 机制与局限 | `metrics` / `figures` / `notes` |

材料配合：`task.md`（需求 + 口径）→ 读 `reference/`（一份**走完这六步**的示范）→
回 `scripts/search.py` 填掉自己的 TODO → 两个 case 都跑 → 补全下面的能力边界与实测档案 → 提交。

## 要做的决策（本实验的重点）

1. **向量怎么来**：真实场景用训练好的 embedding 模型；这里用词表 + 计数 ——
   说说这两种方式"在机制上"哪里一样、哪里不一样（泛化能力差在哪）。
2. **为什么关键词会漏**：`paraphrase` 类查询字面不重叠，关键词检索的得分结构决定了它拿不到分 ——
   请用你自己跑出来的数字说明。
3. **改写要重算向量**：为什么"改文本不改向量"会让检索结果错？错在哪一步？
4. **只返回分数 > 0**：为什么检索要这样规定？（提示：不规定的话，零分文档会按 id 排进 Top-3）

## 自测

```sh
for c in cases/*/; do
  python3 scripts/search.py "$c" "/tmp/$(basename "$c").json"
done
```

> 卡住了怎么办：先看 `reference/scripts/search.py` 里对应的那一段，再回来改自己的实现。
