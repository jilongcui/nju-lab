# 分子医学知识问答原型（你的方案）

> **本实验是综合实践，不是"按口径写代码"**：给你一份小语料与五个问题，**四条路怎么搭、
> 代码怎么组织、图怎么画由你自己决定**。路由口径与各形态的实现口径是业务规则（必须照做），
> 但"怎么实现"是你的自由 —— 达标看的是"走对了路 + 关键事实对 + 出处带出来 + 说得清"。

## 实验材料（都在题目包 `problem/` 里，领取后工作区就有）

| 材料 | 作用 |
|---|---|
| `task.md` | **题干**：业务背景、六步流程、**路由口径**、各形态实现口径、交付格式 |
| `judge.md` | 判据：哪些是硬性口径、哪些是语义判断 |
| `reference/` | 一份**示范实现** —— 先读它，再写你自己的（它不是标准答案；函数划分与你的骨架一致） |
| `cases/case01`、`cases/case02` | 两种语料规模，自测用（每个 case 有 `expected.json` 可以对照） |

**实验流程（六步，与 `task.md` 一致 —— 每一步都要走完）**：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| ① 看清需求 | 五个问题分别在问什么？各需要哪种形态 | 心里有数（写进 `notes`） |
| ② **摸清材料** | 七份文件的主键、段落号、边的方向 —— 先看清楚再动手 | 心里有数 |
| ③ **搭四个入口** | SQL / 关键词 / 相似度 / 图多跳 —— 每条路先单独跑通 | 代码里的四个函数 |
| ④ **逐题路由** | 选主路取答案；两跳题把第二条路也记进 `sources` | 报告的 `answers` |
| ⑤ **汇总与画图** | 统计每种形态回答了几题，画一张图 | `route_counts` / `figures` |
| ⑥ **写结论** | 路由理由、出处可溯源、局限（含「检索结果 ≠ 结论」） | 报告的 `notes` |

材料配合：`task.md`（需求 + 口径）→ 读 `reference/`（一份**走完这六步**的示范）→
回 `scripts/qa_ask.py` 填掉你自己的 TODO → 两个 case 都跑 → 补全能力边界（平台不检查）→ 提交；实测记录写进 `report.md`（平台按它评过程分）。

## 能力边界

> 这一节是技能说明书的一部分（什么时候该用、不该用我）；**平台不检查这一节**。
> —— 这一节与 `description` 里的"不适用场景"是同一件事的两种写法。

- 能处理：本实验这套固定结构的七份数据文件
- （按你的实现补充）：**不处理**哪些情况？（例如：语料换了结构？需要真正的语义检索？图谱里没有的关系？
  要生成自然语言长答案？要给出诊疗建议？）
- （按你的实现补充）：你的实现里，哪些地方是**写死**的假设？（写死意味着换个数据就会坏）

## 要做的决策（本实验的重点）

1. **"该走哪条路"怎么判断**：五个问题里，哪两个长得像但实际应该走不同的路？你的判断依据是什么？
2. **为什么"精确数字"不能让相似度检索去答**：如果用向量/相似度去找 `T-102` 的客观缓解率，会出什么问题？
3. **出处为什么必须是"可核查的对象"**：`trials:T-102` 和"某篇文献说"有什么区别？
   如果换个数据、出处写错了，谁会先发现？
4. **两跳组合题的顺序能不能反**：Q05 先查 SQL 再查图谱行不行？为什么？（提示：图谱给的是"候选集合"，
   关系库给的是"这个药的试验数据"——谁决定了检索范围？）
5. **缺兜底会怎样**：如果图谱里没有这条关系，你的原型会返回什么？这种情况下该怎么如实告诉用户？

## 交付

按 `task.md` 的「交付格式」产出 `output.json`：
`answers`（每题含 `route` / `answer` / `key_facts` / `sources` / `confidence`）/ `route_counts` / `figures` / `notes`。

## 自测

两个 case 都要跑，并自己与 `cases/<case>/expected.json` 对照（路由对不对，一眼就能看出来）：

```sh
for c in cases/*/; do
  python3 scripts/qa_ask.py "$c" "/tmp/$(basename "$c").json"
done
```

> 卡住了怎么办：先看 `reference/scripts/qa_ask.py` 里对应的那一段，再回来改自己的实现。

> 实测记录（运行方式、结果、错误分布）写进同级的 `report.md`；这里只保留能力边界与已知失效情形。
