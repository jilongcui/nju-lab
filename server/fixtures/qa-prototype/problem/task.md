# 综合实践：搭一个最小的分子医学知识问答原型（四种形态各用一次）

## 业务背景

前四章你分别学了知识库的四种形态：**文本内容**（第 5 章）、**关系数据库**（第 6 章）、
**向量数据库**（第 7 章）、**知识图谱**（第 8 章）。这一章把这四样**组装起来**回答真实提问。

临床科研里常见这样的问题：

> "BRCA1 突变的卵巢癌患者有什么靶向药？依据是什么？"

拆开看，它其实要四类答案的汇合：**精确数字**（试验分期、客观缓解率）在结构化表里；
**原文出处**在指南/综述段落里；**"换了说法"也能找到**需要相似度检索；
**"为什么这个突变对应这类药"**需要沿关系链推理。没有任何单一形态能同时满足这四点 ——
这正是真实知识库的样子：**多源融合、混合检索、图谱增强**。

本实验给你一份**小规模虚构语料**（基因 / 变异 / 药物 / 试验 / 段落 / 关系边）与 **5 个问题**，
你要把四种形态**各用上一次**（第 5 个问题是两跳组合），并且**每个答案都要带出处**。

## 你的任务

用工作目录里的七份文件，做一个**可复现的问答原型**，产出 `output.json` 与一张图。具体要求：

1. **看清每个问题要什么**：是精确数字、原文段落、"意思相近"的段落，还是关系链推理？
   选错路也能凑出答案，但要付出"说不清依据"的代价 —— 所以**先判断再动手**；
2. **四条路都要真的搭起来**（都要用上，缺一条就会有几个问题答不出/答不实）：
   - **关系库**：结构化表用 SQL 查（精确数字、按条件筛）；推荐用标准库 `sqlite3`；
   - **关键词（字面）**：在段落里找**同时出现指定术语**的那一段；
   - **向量相似（字符 2-gram 余弦）**：找"换了说法"但仍指同一件事的段落
     （环境里没有语义向量模型，所以用与第 5 章一致的字符 2-gram 等价实现，口径见下）；
   - **知识图谱**：用 `edges.csv` 的有向边做**多跳**查询，并把**完整路径**报出来；
3. **每个答案带出处**：`sources` 里逐条写清"这条结论来自哪里" —— 表名 + 主键（`trials:T-102`）、
   段落号（`passages:P-01`）、或边的路径（`edges:BRCA1->olaparib`，多跳时附 `path`）；
4. **说清路由理由**：`notes` 里要讲清"为什么这一题该走这条路"，以及这套原型的局限；
5. **用图说话**：把"每个问题分别由哪种形态回答"画成一张图。

> 代码怎么组织、函数怎么切都随你（**纯标准库**就够：`csv` / `json` / `sqlite3` / `math` /
> `collections`；画图用已预装的 `matplotlib`）。判据看的是：**走对了路 + 关键事实对 + 出处带出来 + 说得清**。

## 实验流程（六步，每一步都要走完）

| 步 | 做什么 | 产出/落点 |
|---|---|---|
| ① **看清需求** | 五个问题分别在问什么？各自需要哪一种形态 | 心里有数（写进 `notes`） |
| ② **摸清材料** | 七份文件各是什么、彼此怎么对上（表的主键、段落号、边的方向） | 心里有数 |
| ③ **搭四个入口** | 关系库（SQL）/ 关键词 / 相似度 / 图多跳 —— 每条路都能单独跑通 | 代码里的四个函数 |
| ④ **逐题路由** | 每题选一条主路取答案，需要两跳时把第二条路也记进 `sources` | 报告的 `answers` |
| ⑤ **汇总与画图** | 统计每种形态回答了几题，画一张图 | 报告的 `route_counts` / `figures` |
| ⑥ **写结论** | 讲清路由理由、出处可溯源性、局限（含"检索结果 ≠ 结论"这条坑） | 报告的 `notes` |

> 图用 `matplotlib`（已预装）画，存到工作目录的 `figures/` 下，例如
> `plt.savefig("figures/route_counts.png", dpi=110)`。
> ⚠️ **图上的标题与坐标轴标签必须用英文**：运行环境里没有中文字体，中文会渲染成方框。
> 中文解释写在 `figures[].takeaway` 与 `notes` 里。

## 路由口径（怎么判断该走哪条路）

| 问题要的是 | 走哪条路 | 判断依据 |
|---|---|---|
| **精确数字 / 统计 / 按条件筛** | `sql` | 答案在 `trials.csv` 这类结构化表里，口径是"筛选条件 + 字段" |
| **原文里直接出现了指定术语的段落** | `keyword` | 问题问的是"哪一段**直接给出**了某个推荐/说法" —— 靠字面术语共现就能定位 |
| **意思相近、但措辞不同的段落** | `vector` | 问题问"哪一段**解释了**某个机制/原因"，而问法里没有那一堆原词 |
| **关系链 / 推理链 / "为什么"** | `graph` | 答案是一串关系（可解释的证据链），要按边的方向多跳 |
| **两件事的组合**（先查关系、再查数据） | 主路 `graph` + `sources` 里补一条 `sql` | 「先拿到适应证，再取试验数据」这种 |

`sources[].kind` 只能取 `sql` / `keyword` / `vector` / `graph` 四个值之一。

## 各形态的实现口径（**钉死**，结果才能唯一确定）

- **SQL**：结构化事实（基因 / 变异 / 药物 / 试验）用 SQL 查。推荐内存 SQLite（`sqlite3`），
  也可以自己写筛选逻辑 —— 判据只看答案对不对；
- **关键词（字面）**：术语在段落文本里做**大小写不敏感的子串**匹配；
  Q02 要的是"三个概念（PARP 抑制剂 / BRCA 突变 / 卵巢癌）**同时**出现"的那一段；
- **相似度（字符 2-gram 余弦）**：把文本做 NFKC + 转小写后**只保留字母与数字**
  （`str.isalnum()`，标点与空格全部删除），相邻两字符算一个 2-gram；用余弦相似度排序，
  **并列时取段落号升序**；取相似度最高的那一段。
  （这与第 5 章实验里的字符 2-gram 口径一致 —— 中文不需要分词器。）
- **图谱**：`edges.csv` 是**有向**边（`head,relation,tail`）；多跳用 BFS **最短路径**，
  同长度多条时取**边序列 ASCII 升序最小**的那条；路径写成 `head|relation|tail` 的三元组链（按顺序）。

## 数据字典

| 文件 | 列 | 含义 |
|---|---|---|
| `genes.csv` | `gene_symbol` / `full_name` / `chromosome` | 基因（主键 `gene_symbol`） |
| `variants.csv` | `variant_id` / `gene_symbol` / `variant_type` / `clinical_significance` | 变异（主键 `variant_id`） |
| `drugs.csv` | `drug_name` / `drug_class` / `target` / `approval_status` | 药物（主键 `drug_name`） |
| `trials.csv` | `trial_id` / `drug_name` / `indication` / `phase` / `orr_pct` | 临床试验（主键 `trial_id`，`orr_pct` = 客观缓解率 %） |
| `passages.csv` | `passage_id` / `source` / `section` / `text` | 文献/指南段落（主键 `passage_id`） |
| `edges.csv` | `head` / `relation` / `tail` | 知识图谱的有向三元组 |
| `questions.csv` | `question_id` / `question` | 五个问题 |

> 数据是**虚构的教学数据**（没有真实患者，也不是真实临床试验），但结构符合真实知识库的组织方式。

## 交付格式

**`output.json`**（写在工作目录下；**键名与层级按下面的样例写**）：

```json
{
  "answers": [
    {
      "question_id": "Q01",
      "route": "sql",
      "answer": "……（≥10 字，中文；说清结论，不带诊断式断言）",
      "key_facts": { "trial_id": "T-102", "phase": "III", "orr_pct": 62.4 },
      "sources": [ { "kind": "sql", "ref": "trials:T-102" } ],
      "confidence": 0.95
    },
    {
      "question_id": "Q04",
      "route": "graph",
      "answer": "……",
      "key_facts": { "drugs": ["niraparib", "olaparib", "talazoparib"], "hops": 3 },
      "sources": [
        { "kind": "graph", "ref": "edges:BRCA1->olaparib",
          "path": ["BRCA1|loss_of_function|同源重组修复缺陷", "同源重组修复缺陷|synthetic_lethal_with|PARP抑制剂", "PARP抑制剂|includes|olaparib"] }
      ],
      "confidence": 0.85
    }
  ],
  "route_counts": { "keyword": 1, "vector": 1, "sql": 1, "graph": 2 },
  "figures": [ { "path": "figures/route_counts.png", "takeaway": "……（一句话结论）" } ],
  "notes": "……（≥60 字：路由理由、出处可溯源、局限与『检索结果不是结论』这条坑）"
}
```

**每题 `key_facts` 的键名必须按下面写**（口径钉死，判据逐题比对）：

| 题 | `key_facts` 的键 | 说明 |
|---|---|---|
| `Q01` | `trial_id` / `phase` / `orr_pct` | 奥拉帕利卵巢癌 **III 期**试验的编号、分期、客观缓解率 |
| `Q02` | `passage_ids` | 同时字面出现「PARP」「BRCA」「卵巢癌」的段落号（升序数组） |
| `Q03` | `passage_ids` | 与「为什么修复缺陷的肿瘤对铂类和 PARP 抑制剂都敏感」相似度最高的段落号 |
| `Q04` | `drugs`（ASCII 升序）/ `hops` | PARP 抑制剂这一类包含的药物 + 最短路径的跳数 |
| `Q05` | `indication` / `trial_id` / `orr_pct` | 尼拉帕利获批的适应证 + 它的试验编号与客观缓解率 |

- `answers` **按 `question_id` 升序**；
- `sources` 每项：`kind`（四个取值之一）+ `ref`（非空字符串）+ 多跳时附 `path`（三元组链）；
- `route` 是**主路**（两跳题的 `sources` 里会有两条不同 `kind`，`route` 记先走的那条）；
- `confidence` 是 0~1 的小数（你自己的把握）；
- 图至少 1 张：`path` + 一句 `takeaway`；
- 报告里的数值**不需要**和任何人一致 —— 只要口径对，它们**本来就该相同**；口径错了就会不一样。

## 怎么算完成

1. 写一个能跑的方案（推荐做成 Skill 里的一段脚本），能对任意一份同结构的语料 + 问题产出
   `output.json` 与一张图；
2. 在 `cases/case01` 与 `cases/case02`（两种语料规模）上都能跑通 —— 判据对两个 case 各判一次；
3. 把结论与踩过的坑写进 `SKILL.md` 的「实测档案」。

判据全文见 `judge.md`；怎么自测、包内还有什么，见 `README.md`。
