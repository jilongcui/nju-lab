# vector-easy —— 入门实验：按主诉找相似病例（向量检索 · 余弦 + Top-3）

> 对应课程章节：**向量数据库**（动手实践：亲手算一次余弦相似度 → 语义检索演示 → 三种查询对照）。
> 难度 **easy**：10 篇病例、8 维词表、只用 Python 标准库 + matplotlib。

## 场景与数据

- 应用：门诊按主诉找相似病例
- 数据：`problem/cases/case01|case02` 各含 `docs.csv`（10 篇主诉）、`queries.csv`（3 条：同词/同义/不相关）、
  `concepts.json`（8 个概念 + 同义词表）
- 造题：`tools/gen_cases.py`（固定数据，可重跑；**不下发**）

## 判据设计要点

1. 向量化口径写死（同义词按长度降序归一 + 概念计数），否则分数对不上；
2. 排序口径写死（分数降序 + `doc_id` 升序；只保留 > 0）；
3. **不相关查询必须返回空** —— 这是"向量检索回答像不像、不回答对不对"的现象本身；
4. 不涉及真实 embedding / ANN / 过滤 —— 留给中等档 `vector-search`。

## 项目字段文案（建项目时用）

- **title**：入门实验：按主诉找相似病例（向量检索 · 容易）
- **difficulty**：`easy`
- **content**（学生详情页首屏；不写"你的任务"）：
  门诊想做个「输入一段主诉，找出以往最相似病例」的小工具。病例库只有 10 条主诉，
  没有真正的 embedding 模型可用，所以用 8 个概念词表做玩具版向量：同义词归一、按概念计数，
  用余弦相似度找最像的几篇。
- **objectives**：
  1. 会用手算的余弦相似度比较两段文本；
  2. 会把文本变成向量（词表 + 计数），并解释为什么"同义改写"也能命中；
  3. 会说明向量检索返回的是"最相似"而不是"正确答案"。
- **background**（每条 = 概念 + 一句人话解释）：
  - **向量化**：把文本压成一组数字。这里的玩具版是"数概念"：8 个概念各占一维，出现几次就是几。
  - **同义词归一**：先把「胸闷」「心梗」都换成「胸痛」，再计数——这是"意思相近"能被算出来的前提。
  - **余弦相似度**：两个向量的夹角余弦，只看方向不看长度；公式 `(x·y)/(|x|×|y|)`，范围 0~1。
  - **Top-K**：按分数排序取前几条。它回答"最像的几条是哪几条"，不保证"里面有正确答案"。
  - **为什么 0 分要丢掉**：完全不相关的查询如果硬凑三条 0 分结果，会把"没找到"伪装成"找到了"。
- **description**：
  1. 读实验内容与本节的达标要求，确认向量化与排序口径；
  2. 读 `concepts.json`，把同义词按长度降序替换成概念；
  3. 对 10 篇病例与 3 条查询分别向量化（8 维计数）；
  4. 用余弦算相似度，取 Top-3（分数降序 + `doc_id` 升序，只保留 > 0）；
  5. 画三条查询的 top-1 分数柱状图（轴标签英文）；
  6. 两个 case 都跑一遍，与 `expected.json` 核对；
  7. 想清楚"不相关查询返回空"说明什么；
  8. 生成实验报告 `report.md`：数字由平台自动填入，你只补结论与踩坑。
- **references**：余弦相似度定义；`problem/reference/scripts/solve.py`（示范实现）。
- **faq**：为什么我的同义查询没命中？（同义词必须先按长度降序替换，否则「胸闷」会被拆开）；为什么分数和别人不一样？（分数四舍五入到 4 位，向量化口径要一致）；为什么不相关查询要返回空？（见 background 最后一条）。
