# 入门实验：按主诉找相似病例（向量检索 · 余弦 + Top-3）

## 业务背景

门诊想做个「输入一段主诉，找出以往最相似的病例」的小工具。病例库只有 10 条，每条一段主诉；
没有真正的 embedding 模型可用（教室环境不联网），所以用**词表**做一个玩具版向量：

- \`concepts.json\` 给出 **8 个概念**（胸痛 / 气短 / 心悸 / 发热 / 咳嗽 / 头痛 / 腹痛 / 乏力）和一张**同义词表**；
- 文本向量化 = 先把同义词归一成概念（长词优先，例如「胸闷」→「胸痛」、「喘不上气」→「气短」），
  再按**每个概念出现的次数**填 8 维向量；
- 相似度用**余弦**：\`cos = (x·y) / (|x| × |y|)\`；查询向量全 0 时分数记 0。

## 你的任务

读 \`docs.csv\`（10 篇病例）、\`queries.csv\`（3 条查询：同词 / 同义改写 / 完全不相关），
对每条查询算相似度并取 **Top-3**，写进 \`output.json\`，并画一张「三条查询的 top-1 分数」柱状图。

**排序与取舍口径**（顺序也算分）：

1. 按分数**降序**；分数相同时按 \`doc_id\` **升序**；
2. **只保留分数 > 0 的结果**（不足 3 条就少返回；完全不相关的查询返回空数组）；
3. 分数四舍五入到 **4 位小数**。

## 实验流程（六步）

| 步 | 做什么 | 产出 |
|---|---|---|
| ① 看清需求 | 向量化口径、排序与 0 分的处理 | 心里有数 |
| ② 看一眼数据 | 10 篇主诉、3 条查询、词表与同义词 | 心里有数 |
| ③ 向量化 | 同义词归一 + 概念计数 → 8 维 | `index` |
| ④ 算相似度 | 余弦 + Top-3 | `retrieval` |
| ⑤ 对照 | 同词 / 同义 / 不相关三种查询的差别 | 图 + 结论 |
| ⑥ 写结论 | 结论与踩坑 | `report.md` |

## 交付格式

**`output.json`**（写在工作目录下）：

```json
{
  "index": { "dim": 8, "n_docs": 10 },
  "retrieval": [
    { "query_id": "q1", "kind": "same_words", "top_k": [{ "doc_id": "D01", "score": 1.0 }] },
    { "query_id": "q2", "kind": "paraphrase", "top_k": [{ "doc_id": "D02", "score": 1.0 }] },
    { "query_id": "q3", "kind": "irrelevant", "top_k": [] }
  ],
  "figures": [
    { "path": "figures/top1_scores.png", "takeaway": "同词与同义改写都能拿到高分，不相关查询一条都不命中。" }
  ],
  "notes": "……（≥40 字：向量怎么来的、为什么同义改写也能命中、0 分结果为什么要丢掉）"
}
```

- \`retrieval\` 的顺序与 \`queries.csv\` 一致；\`top_k\` 按分数降序。
- 图至少 1 张，\`path\` 与实际落点一致（相对当前工作目录）。

## 怎么算完成

1. 两个 case 都跑通，三条查询的 Top-K 与 \`expected.json\` 一致（同分按 `doc_id` 升序）。
2. 不相关那条查询**必须返回空** —— 这正好说明向量检索回答的是「像不像」，不是「对不对」。
3. 把结论与踩过的坑记下来 —— 报告会由工具整理进 \`report.md\`，**不需要改 \`SKILL.md\`**。

判据全文见 `judge.md`。
